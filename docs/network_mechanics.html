Guia UE 5.7 - Passo a passo para recriar mecânicas

Todos os passos refletem o código disponível. Onde faltar lógica ou assets, está indicado explicitamente.

Conexão e Aceitação de Servidor

  1. No Unreal Editor 5.7, crie uma classe C++ derivada de AActor chamada AProtocolSender para representar o papel de CProtocolSend. Ative Replicates apenas se precisar sincronizar estado de conexão entre clientes.
  2. Adicione um objeto membro que envolva sockets: use FSocket (TCP/UDP) via ISocketSubsystem ou um wrapper similar a CustomClient. Inicialize no construtor.
  3. Implemente bool ConnectServer(const FString& IP, int32 Port) criando o socket, resolvendo o endereço e conectando. Exponha essa função ao Blueprint (UFUNCTION(BlueprintCallable)) para ser chamada pelo PlayerController.
  4. Crie um FTimerHandle em BeginPlay() que chama um método de recebimento a cada ~0.01s (equivalente ao loop em RecvMessage()), lendo dados do socket para um buffer.
  5. Ao receber dados, interprete um enum EProtocolHead equivalente a ProtocolHead. Para SERVER_CONNECT, deserialize para uma struct FMsgConnectClientRecv (campos result, index[2], ClientVersion[5]) e chame uma função RecvJoinServerNew().
  6. Em RecvJoinServerNew(), atualize uma variável HeroKey e acione eventos de UI (via UMG) que simulam CUIMng exibindo LoginWin. Marque como Client RPC se quiser notificar somente o cliente local.
  7. Implemente void DisconnectServer() fechando o socket e limpando timers. Opcionalmente, dispare um NetMulticast RPC para notificar HUDs se o actor for replicado.

Ping / Keep-Alive

  1. Adicione a AProtocolSender uma função SendPingTest() que preenche um buffer com tick (DWORD) e dois WORDs (1 e 2) exatamente como CustomClient::PingServer(). Use FPlatformTime::Cycles64() ou FDateTime::UtcNow() para o valor de tempo.
  2. Crie um FTimerHandle chamado por SendCheckOnline() para disparar SendPingTest() a cada N segundos enquanto bIsConnected for verdadeiro.
  3. No recebimento, trate ProtocolHead::SERVER_DISCONNECT e registre no log ou em UI (mostrando o clientID do pacote), espelhando a impressão do código.
  4. Em Blueprints, exponha um evento OnPingResponse para atualizar indicadores de latência. Essa lógica visual não está no código — configure manualmente (NÃO DÁ PARA INFERIR COM SEGURANÇA COM BASE NO CÓDIGO).

Login de Conta

  1. Defina uma struct FMsgConnectAccountSend com campos Account[10], Password[20], TickCount, ClientVersion[5], ClientSerial[16] (packed) para replicar PMSG_CONNECT_ACCOUNT_SEND. Use uint8 arrays para bytes.
  2. No Project Settings → Input, crie um Action Mapping "ConfirmLogin". No PlayerController blueprint, chame SendRequestLogInNew(Account, Password) da AProtocolSender.
  3. Implemente SendRequestLogInNew: copie strings para buffers fixos, aplique uma função de ofuscação equivalente a BuxConvert (implemente em C++), preencha versões/seriais e envie com cabeçalho BOTH_CONNECT_LOGIN.
  4. Na rotina de recebimento, associe BOTH_CONNECT_LOGIN a RecvLoginNew(). Mapear códigos 0x00..0x0D, 0x11, 0x40, 0xC0..0xD2 para mensagens de erro em UI (Widget Blueprint) conforme o switch de RecvLoginNew().
  5. Quando result for sucesso (0x01 ou 0x20), atualize um estado LogIn = 2 equivalente e acione carregamento de mapa ou mudança de nível. A lógica exata de CheckHack() não existe aqui — deixe como função vazia ou placeholder.

Solicitação de Lista de Personagens

  1. Crie uma struct FMsgSimpleResultSend com uint8 Result para espelhar PMSG_SIMPLE_RESULT_SEND.
  2. Adicione uma função SendRequestCharactersListNew() que seta result = 1 e envia com cabeçalho BOTH_CONNECT_CHARACTER.
  3. No handler de recebimento, quando chegar BOTH_CONNECT_CHARACTER, despache para uma função BlueprintImplementableEvent ReceiveCharacterList(const TArray& RawData) para permitir parsing no Blueprint ou em C++. O formato não está no código — você deve definir manualmente (NÃO DÁ PARA INFERIR COM SEGURANÇA COM BASE NO CÓDIGO).
  4. Atualize Widgets de seleção de personagem após o parsing. Marque a função como Client RPC se o actor for replicado e só o dono precisar ver a lista.

Atualização de Posição (XY)

  1. Implemente SendPositionNew(uint8 PosX, uint8 PosY) preenchendo FMsgPositionSend (equivalente a PMSG_POSITION_SEND) e enviando com cabeçalho BOTH_POSITION.
  2. No Character class (derivado de ACharacter), capture movimento local e chame SendPositionNew() quando a posição mudar (por exemplo, no Tick com threshold de distância) para mimetizar o envio manual do cliente.
  3. No recebimento, encaminhe BOTH_POSITION para um método ReceiveMovePosition em C++/Blueprint que aplique a posição recebida aos pawns remotos. O payload exato não está detalhado — defina no projeto (NÃO DÁ PARA INFERIR COM SEGURANÇA COM BASE NO CÓDIGO).
  4. Para compatibilidade com o sistema de replicação do UE, considere manter bUseControllerRotationYaw sincronizado via RPC se necessário.

Movimento com Caminho Compactado

  1. Adapte SendCharacterMoveNew() para UE criando uma função SendCharacterMoveNew(int32 Key, float Angle, uint8 PathNum, const TArray& PathX, const TArray& PathY, uint8 TargetX, uint8 TargetY). Replique a montagem do array Path[8] usando uma tabela de direções DirTable igual à do código.
  2. Antes de enviar, limite PathNum a MAX_PATH_FIND - 1 e garanta que PathX/PathY tenham pelo menos PathNum entradas. Preencha path com nibble alto para a direção inicial e nibble baixo para contagem (PathNum-1), igual ao código original.
  3. Envie o pacote com cabeçalho BOTH_MOVE. No recebimento, chame ReceiveMoveCharacter para reconstruir o caminho. Como o corpo de ReceiveMoveCharacter não está disponível, defina a reconstrução manualmente (NÃO DÁ PARA INFERIR COM SEGURANÇA COM BASE NO CÓDIGO).
  4. Se optar por usar replicação nativa do UE, converta o caminho para um FVector array e replique via NetMulticast. Ainda assim, mantenha a compatibilidade com o cabeçalho customizado se o servidor externo exigir.

Encaminhamento Genérico de Pacotes Clássicos

  1. Implemente DataSendRaw(const TArray& Payload) que envia com cabeçalho ProtocolHead::BOTH_MESSAGE, similar a CustomClient::DataSend(uint8_t*,...). Valide o tamanho (até 8024 bytes) antes de enviar.
  2. No handler de recebimento, reconstrua o cabeçalho clássico (0xC1/0xC3 = 1 byte size; 0xC2/0xC4 = 2 bytes size) exatamente como o switch do código e extraia head/size.
  3. Crie uma função BlueprintImplementableEvent TranslateProtocol(uint8 Head, const TArray& Buffer, int32 Size) para que a lógica específica (não disponível no código) possa ser implementada manualmente (NÃO DÁ PARA INFERIR COM SEGURANÇA COM BASE NO CÓDIGO).
  4. Adicione logs no Output Log replicando g_ConsoleDebug para auxiliar depuração.

Lista de Servidores e Redirecionamento

  1. No C++, declare structs FReceiveServerList e FReceiveServerAddress espelhando PHEADER_DEFAULT_SUBCODE_WORD e PRECEIVE_SERVER_LIST. Marque-as com BlueprintType para debugar no Editor.
  2. Implemente um método HandleServerList(const TArray& Buffer) que faça parsing da quantidade (Value/Value2) e popular um array de grupos em um UDataTable usado pelo Widget de seleção de servidor.
  3. Crie um Widget Blueprint de seleção com um ListView e um botão “Conectar”. Ao clicar, chame DisconnectServer() e depois ConnectServer(IP, Port) usando os valores recebidos, replicando o fluxo de ReceiveServerConnect().
  4. Marque o Actor que gerencia a UI como Only Owner See se estiver replicado, já que a escolha é local. Não há lógica de fallback no código; considere implementar toast de erro quando a nova conexão falhar (NÃO DÁ PARA INFERIR COM SEGURANÇA COM BASE NO CÓDIGO).

Chat público / GM

  1. Crie um Widget Blueprint W_Chat com ScrollBox e entrada de texto. Exponha um evento OnChatMessage(const FString& Sender, const FString& Text, bool bIsGM) que colore linhas diferentes.
  2. No C++ do gerenciador de rede, implemente HandleChatPacket reconstruindo ID e texto conforme ReceiveChat. Marque como Client RPC se o Actor for replicado; caso contrário, chame localmente após ler do socket.
  3. Para distinguir GMs, replique a checagem de CtlCode/eBuff_GMEffect com flags booleanas vindas do pacote. Se o pacote não contiver, insira manualmente (NÃO DÁ PARA INFERIR COM SEGURANÇA COM BASE NO CÓDIGO).
  4. Conecte o evento de entrada de chat (Project Settings → Input "SendChat") a um método SendChatMessage() que monte o pacote clássico e use DataSendRaw para enviá-lo.

Whisper / Mensagem Privada

  1. Adicione ao W_Chat um painel separado para whispers com som opcional. Use USoundCue associado a SOUND_WHISPER e reproduza somente se o usuário não tiver bloqueado whispers.
  2. No C++ do cliente, implemente HandleWhisperPacket lendo ID e texto tal como ReceiveChatWhisper e despache para o Widget. Dispare um Client RPC se precisar forçar execução apenas no dono.
  3. Implemente validação de resultado chamando HandleWhisperResult quando ReceiveChatWhisperResult chegar; traduza códigos de erro em mensagens UMG.
  4. Crie um comando de input "SendWhisper" que abre um modal solicitando ID de destino e conteúdo, então envia o pacote via DataSendRaw (estrutura precisa ser definida manualmente — NÃO DÁ PARA INFERIR COM SEGURANÇA COM BASE NO CÓDIGO).

Avisos e Slides de Servidor

  1. Construa um Widget W_ServerNotice com dois elementos: um texto persistente (para resultados 0,1,2) e um Overlay para slides animados.
  2. No handler de pacotes, parseie Result, Notice, Count, Delay, Speed e Color espelhando ReceiveNotice. Invoque animações temporizadas (Timeline ou FTimerHandle) para mostrar slides entre 10 e 15 segundos.
  3. Quando o aviso for de guild (Result 2), encaminhe para um Widget de guild; se não existir no projeto, crie um placeholder (NÃO DÁ PARA INFERIR COM SEGURANÇA COM BASE NO CÓDIGO).
  4. Adicione um painel de debug que registre MCD_RECEIVE-like logs no Output Log para cada aviso, auxiliando QA.

Teleport / Troca de Mapa

  1. No Character (Blueprint ou C++), exponha uma função ApplyTeleport(int32 MapID, uint8 PosX, uint8 PosY, uint8 Angle, uint8 Flag). Ela deve parar movimento (MovementComponent->StopMovementImmediately()) e reposicionar o pawn.
  2. Implemente um gerente de mapas que carregue níveis por UGameplayStatics::OpenLevel ou ULevelStreamingDynamic, tomando MapID como entrada. Replique a lógica condicional de sons/efeitos conforme o código (por exemplo, limpar interfaces de eventos ao trocar de mapa).
  3. Depois de carregar o mapa, atualize widgets como nome do mapa e resets de seleção (SelectedItem/NPC/Character). Mantenha um hook para SendRequestFinishLoading() se o servidor exigir confirmação.
  4. Se usar replication nativa, envie um ServerTeleportRequest RPC em vez de setar posição localmente para respeitar autoridade do servidor do UE.

Atualização Visual de Equipamentos

  1. Crie structs FReceiveEquipment e FChangeCharacter com campos equivalentes aos pacotes ReceiveEquipment/ReceiveChangePlayer (Key, Item array, nível, opções).
  2. No Character Blueprint, adicione funções ApplyEquipmentSet e ApplyEquipmentChange que trocam Skeletal Meshes ou USkeletalMeshComponent attachments com base no tipo/nível retornado por ConvertItemType equivalente.
  3. Chame essas funções ao receber pacotes do servidor. Se o Actor for replicado, considere usar OnRep_CurrentEquipment para atualizar clientes que entrarem depois.
  4. Integre com o sistema de aparência atual (por exemplo, Gameplay Tags para armas). Caso o formato exato de mesh/opções não esteja definido, crie um mapa de configuração manual (NÃO DÁ PARA INFERIR COM SEGURANÇA COM BASE NO CÓDIGO).

Roadmap de Evolução

Curto Prazo

  • [Alta] Unificar loop de recebimento em task assíncrona (AsyncTask/FRunnable) para substituir a thread comentada em RecvMessage(); afeta Conexão e Ping; reduz risco de stutter no cliente.
  • [Alta] Implementar validação e rate limit em SendPositionNew e SendCharacterMoveNew; mecânicas: Atualização de Posição e Movimento; mitiga spam e cheating.
  • [Média] Mapear e implementar parsing real de ReceiveCharacterList; mecânica: Lista de Personagens; dependência: definição do formato no servidor.
  • [Média] Adicionar telas de erro para todos os códigos em RecvLoginNew; mecânica: Login; impacto: melhor feedback e segurança.
  • [Média] Criar sistema de anti-spam para chat público e whisper (cooldown por remetente); mecânicas: Chat público / GM, Whisper; reduz carga e abuso.
  • [Média] Validar dados de ReceiveNotice antes de criar slides (tamanho de texto, contagem); mecânica: Avisos/Slides; evita estouro visual.

Médio Prazo

  • [Alta] Criar camada de segurança para credenciais (TLS ou criptografia simétrica) além de BuxConvert; mecânica: Login; risco atual de interceptação.
  • [Média] Converter mensagens BOTH_MESSAGE em objetos estruturados e validar tamanhos antes de chamar TranslateProtocol; mecânica: Encaminhamento Genérico; reduz crash por pacotes inválidos.
  • [Média] Implementar reconexão automática em DisconnectServer com backoff; mecânica: Conexão; dependência: tratamento de estado no servidor.
  • [Média] Centralizar carregamento de mapas com verificação de assets antes de aplicar ReceiveTeleport; mecânica: Teleport; reduz falhas de carregamento.
  • [Média] Cachear malhas e materiais utilizados em ReceiveEquipment/ReceiveChangePlayer para evitar hitch de streaming; mecânica: Atualização de Equipamentos; impacto em desempenho.
  • [Baixa] Criar painel de latência/estado de conexão no HUD atualizado via respostas de Ping; mecânica: Ping; impacto em UX.

Longo Prazo

  • [Alta] Migrar protocolos customizados para o sistema de replicação nativo do UE (RPCs e propriedades replicadas) mantendo compatibilidade com o servidor existente; mecânicas: todas que enviam ProtocolHead; dependência: planejamento de API.
  • [Média] Automatizar testes de integração (simulação de cliente/servidor) para validar SendRequestLogInNew, SendPositionNew e SendCharacterMoveNew contra um servidor mock.
  • [Média] Adicionar testes de UX para o fluxo de seleção de servidor e reconexão; mecânica: Lista de Servidores; impacto em retenção.
  • [Baixa] Documentar formalmente o formato de TranslateProtocol e dos pacotes clássicos (0xC1..0xC4) para permitir futura substituição por Protobuf/JSON binário.
