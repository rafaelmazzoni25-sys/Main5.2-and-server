Guia de Recriação das Mecânicas na Unreal Engine 5.7

Passos refletem apenas o comportamento visto no código C/C++; conteúdos não definidos usam a frase obrigatória.

Estabelecimento de conexão com servidor

Equivalente a CProtocolSend::ConnectServer / DisconnectServer.

  1. No Unreal Editor 5.7, adicione uma classe C++ derivada de AActor chamada AProtocolSend para encapsular o socket. Ative PrimaryActorTick.bCanEverTick para controlar reconexões se necessário.
  2. No construtor, crie membros FSocket* e bool bIsConnected. Em BeginPlay(), inicialize o socket via ISocketSubsystem::CreateSocket (TCP) e tente conexão usando Connect() com IP/porta fornecidos, replicando ConnectServer().
  3. Exponha UFUNCTION(BlueprintCallable) bool ConnectServer(const FString& IP, int32 Port) que resolve endereço, chama Socket->Connect() e retorna sucesso/falha. Se falhar, registre log como em g_ConsoleDebug->Write.
  4. Implemente UFUNCTION(BlueprintCallable) void DisconnectServer() que fecha o socket, zera bIsConnected e cancela timers, seguindo a lógica do código.
  5. Crie um FTimerHandle que a cada poucos milissegundos chama um método PollIncoming(); ele verifica bIsConnected e lê dados do socket para uma fila (TQueue) similar a Incoming().
  6. Se precisar replicar o estado de conexão para outros clientes, marque a classe com bReplicates = true e replique apenas flags (não o socket) via UPROPERTY(Replicated). Caso contrário, mantenha somente no cliente local.

Loop de recebimento e roteamento de pacotes

Equivalente a CProtocolSend::RecvMessage.

  1. No método PollIncoming(), ao ler um pacote, deserialize um cabeçalho que contenha ProtocolHead (enum espelhando o switch do código).
  2. Implemente um switch em C++ para os casos observados: SERVER_CONNECT, SERVER_DISCONNECT, BOTH_CONNECT_LOGIN, BOTH_CONNECT_CHARACTER, BOTH_POSITION, BOTH_MOVE e BOTH_MESSAGE.
  3. Para SERVER_CONNECT, deserialize em struct FConnectClientRecv (campos result, index[2], ClientVersion[5]) e chame RecvJoinServerNew() em C++/Blueprint.
  4. Para SERVER_DISCONNECT, leia um uint32 ClientID e apenas registre log (como o std::cout do código).
  5. Para BOTH_CONNECT_LOGIN, entregue o payload a RecvLoginNew(); para BOTH_CONNECT_CHARACTER invoque ReceiveCharacterList; para BOTH_POSITION invoque ReceiveMovePosition; para BOTH_MOVE invoque ReceiveMoveCharacter.
  6. Para BOTH_MESSAGE, reconstituir o cabeçalho 0xC1/0xC3/0xC2/0xC4 conforme o código e encaminhar bytes a uma função TranslateProtocol(uint8 Head, const TArray& Data). O comportamento desta função NÃO DÁ PARA INFERIR COM SEGURANÇA COM BASE NO CÓDIGO-FONTE C/C++.
  7. Os handlers ReceiveCharacterList, ReceiveMovePosition e ReceiveMoveCharacter devem ser implementados manualmente (BlueprintImplementableEvent ou C++) pois o código fonte não fornece corpo completo.

Roadmap de Evolução (Baseado no Código C/C++ e Adaptação à UE 5.7)

Curto Prazo

  • [Alta] Mecânicas: Loop de recebimento; Login. Garantir que o polling de socket tenha controle de tempo e validação de tamanho antes de acessar buffers, espelhando os pontos de entrada em RecvMessage(). Impacto: estabilidade do cliente; reduz risco de travamentos. Dependência: implementação de fila de mensagens.
  • [Média] Mecânica: Ping / keep-alive. Adicionar rate limit configurável no timer de ping para evitar envio excessivo; Impacto: uso de banda e carga do servidor. Dependência: temporizador existente.
  • [Média] Mecânica: Carregamento de lista de servidores. Validar existência e integridade do arquivo ServerList.bmd antes de usar; Impacto: evitar encerramento abrupto por MessageBox/PostMessage. Dependência: rotina de leitura de arquivo.
  • [Média] Mecânica: Seleção de servidor. Garantir que os campos gravados por SetSelectServerInfo() sejam validados (índices e flags) antes de alimentar a UI; Impacto: previne inconsistências locais. Dependência: dados carregados por LoadServerListScript(). Baseado diretamente no código C++ (ServerListManager.cpp, SetSelectServerInfo).

Médio Prazo

  • [Alta] Mecânicas: Atualização de posição; Movimento com caminho. Implementar validações no cliente para limites de mapa antes de enviar BOTH_POSITION/BOTH_MOVE; Impacto: evita envio de dados inválidos ao servidor. Dependência: acesso a limites do mapa.
  • [Média] Mecânica: Login. Registrar métricas de códigos de erro do switch de RecvLoginNew() para depuração em UE 5.7; Impacto: diagnóstico de conexões. Dependência: sistema de log.
  • [Média] Mecânica: Loop de recebimento. Criar testes automatizados para cada ProtocolHead observado, garantindo que os handlers existam mesmo quando o payload estiver incompleto (pois o código não valida); Impacto: robustez. Dependência: framework de testes.
  • [Média] Mecânica: Envio genérico de pacotes. Inserir validações de tamanho/cabeçalho em DataSend() e SendPacketClassic() para evitar envio de buffers vazios ou truncados; Impacto: integridade de protocolo. Dependência: camada de rede. Baseado diretamente no código C++ (ProtocolSend.h, CustomClient::DataSend).

Longo Prazo

  • [Alta] Mecânicas: Todas as de rede. Migrar do protocolo manual (0xC1/0xC3/0xC2/0xC4) para RPCs nativas da Unreal (Server/Client/NetMulticast) mantendo os fluxos de login/movimento descritos; Impacto: simplificação de código e segurança. Dependência: conclusão das etapas de curto e médio prazo.
  • [Média] Mecânica: Carregamento de lista de servidores. Substituir arquivo binário por fonte de dados replicada (por exemplo, DataTable replicado ou serviço REST interno). Impacto: facilidade de atualização; risco de latência adicional. Dependência: autenticação estabilizada.
  • [Baixa] Mecânica: Ping / keep-alive. Adicionar medição de round-trip time e exibição em HUD; Impacto: visibilidade para usuário. Dependência: implementação de UI; esta é uma SUGESTÃO GENÉRICA, NÃO DIRETAMENTE INFERIDA DO CÓDIGO-FONTE C/C++.
  • [Média] Mecânicas: Seleção e iteração de servidor. Unificar construção de nomes/percentuais em um serviço central replicado (por exemplo, em AGameState) para reduzir duplicação local e facilitar sincronização em multiplayer; Impacto: consistência entre clientes. Dependência: conclusão da migração de dados do ServerList.bmd. SUGESTÃO GENÉRICA, NÃO DIRETAMENTE INFERIDA DO CÓDIGO-FONTE C/C++.
