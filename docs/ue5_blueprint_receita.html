Ângulos & Direção

A função CreateAngle define o zero de rotação apontando para o Sul, 90° para Oeste, 180° para Norte e 270° para Leste. Isso evidencia eixos invertidos em relação ao padrão da UE5.

float CreateAngle(float x1,float y1,float x2,float y2) { float nx = x2 - x1, ny = y2 - y1; if (fabs(nx) < 0.0001f) return (ny < 0.f) ? 0.f : 180.f; // S / N if (fabs(ny) < 0.0001f) return (nx < 0.f) ? 270.f : 90.f; // E / W ... }

ADAPTAÇÃO OBRIGATÓRIA PARA UE5: Conversão de Coordenadas

O legado usa grid 2D (X cresce para Oeste, Y cresce para Norte) com zero de ângulo apontando para o Sul. Na UE5 o sistema é X para frente, Y para a direita e Z para cima. Aplique a rotação de -90° em torno de Z e inverta o eixo X para alinhar as orientações.

  1. Tile → Mundo (Legado)
    Antes de converter para UE, calcule as coordenadas legadas em centímetros: LegacyX = (TileX + 0.5) * 100, LegacyY = (TileY + 0.5) * 100, LegacyZ = Altura(Terrain).【F:Source Main 5.2/source/_define.h†L245-L257】【F:Source Main 5.2/source/WSclient.cpp†L1718-L1730】
  2. World → UE5
    Use um Blueprint Function Library para transformar:
    UE_X = LegacyY UE_Y = -LegacyX UE_Z = LegacyZ UE_Yaw = LegacyAngle - 180.0f
    Essa matriz equivale a uma rotação de -90° em Z seguida de inversão de X, preservando o "Norte" legado como X+ (Yaw 0°) na UE5 e mantendo o up em Z. O yaw subtrai 180° para seguir a mesma rotação aplicada às coordenadas, garantindo que Oeste (90°) vire UE Y- (Yaw -90°) e Sul (0°) vire UE X- (Yaw 180°).
  3. Aplicação em Teleporte
    No GameMode (servidor), ao receber coordenadas tile (x,y,dir): (a) converta para LegacyX/Y usando a escala; (b) aplique a função acima para setar ActorLocation e ActorRotation. Armazene o valor original em variáveis replicadas para reuso em RPCs.
  4. Trajetórias e Pathfinding
    Quando ler arrays de caminho (PathX/PathY) reutilize o mesmo conversor antes de alimentar AI Move To. Mantenha a grade em inteiros (tile) para o servidor e exponha somente vetores UE para componentes de movimento.
Validação: compare o yaw calculado para alvos cardinais usando a tabela CreateAngle para garantir que Sul=0° legado se converta em Yaw=90° UE (virado para a direita), evitando inversão de animações.

ADAPTAÇÃO OBRIGATÓRIA PARA UE5: Controle de Grid

A UI de inventário do legado usa coordenadas inteiras (x,y) dentro da grade. Em UE5, armazene X e Y no PlayerState para cada item e derive SlotIndex = Y * 8 + X em Blueprints antes de preencher o Grid Panel. Isso preserva a distribuição original e evita reordenamentos por widgets dinâmicos.

Procedimentos 1:1 em Blueprint

  1. Adicionar Item (Server)
    Entrada: FItemData e dimensões do item. Passos: (1) Percorra slots na ordem linha->coluna até MaxSlots-1; (2) Para cada slot, teste se cabe usando Width/Height do ItemAttribute; (3) Respeite TwoHand ocupando 2 colunas se necessário; (4) Ao encontrar espaço, grave X/Y no struct, insira no array e marque como replicado.   2. Remover Item
    No servidor, limpe o slot definindo Type = 0x1FFF ou removendo a entrada do array replicado e preenchendo com um FItemData vazio. Em clientes, a OnRep do array deve redesenhar o Grid Panel apagando o ícone correspondente.
  3. Empilhamento (Stacking)
    O legado permite sobreposição para tipos específicos, verificados por IsOverlayItem (poções, flechas, pets, etc.). Replique com uma função Blueprint pura que compara Type e Durability exatamente como as cláusulas originais (ex.: poções normais empilham até durabilidade 3, frascos especiais até 50, Spirit, flechas, etc.).【F:Source Main 5.2/source/NewUIInventoryCtrl.cpp†L1532-L1644】
  4. Movimentação/Swap
    Ao arrastar, mantenha uma cópia de segurança (BackupPickedItem no legado). Em UE5, crie um FItemData PickedItem transitório no PlayerController e só confirme o swap via RPC para o servidor, que então atualiza o array replicado. Use as mesmas validações de ocupação de grid antes de mover.
  5. Sincronizar com UI
    Construa um UserWidget com UniformGridPanel de 8×8. No OnRep_Inventory, itere o array replicado e para cada item crie um UserWidget de ícone ancorado no slot (X,Y). Campos exibidos: ícone baseado em Type, texto de nível, barra de durabilidade usando Durability.

Blueprint passo a passo (Attach/Swap)

  1. Preparar Sockets
    Abra o Skeletal Mesh do personagem e crie sockets: Weapon_R, Weapon_L, Wing (na coluna vertebral), HelperPelvis, Necklace, Ring_R, Ring_L. Marque-os como Inherit Transform para animar junto ao esqueleto.
  2. Estrutura de Dados
    No PlayerState, crie um struct replicado contendo um TMap<int32, FItemVisual> (Slot → asset). Preencha os índices conforme a tabela de slots e vincule os Model IDs lidos dos DataAssets que reproduzem MODEL_ITEM+Type.
  3. Receber Item
    Quando o inventário coloca um item em um slot, execute no servidor:
    1. Atualize o TMap com o asset (Static/Skeletal mesh) correspondente.
    2. Chame um NetMulticast UpdateEquipmentVisual passando Slot e Asset.
    3. No multicast, use Switch on Int (0-11) para selecionar o socket e chame Attach Component to Component (ou Set Skeletal Mesh para partes corporais).
  4. Swap
    No NetMulticast, antes de anexar, valide se já existe componente no socket: use Get Attach Children, destrua o antigo e anexe o novo. Isso espelha o comportamento do cliente que substitui BodyPart inteiro quando Type != 0x1FFF.【F:Source Main 5.2/source/WSclient.cpp†L1919-L1978】
  5. Replicação
    Adicione OnRep_EquipmentVisual no Character para reaplicar attachments em clientes tardios. Chame a mesma função de attach usada no multicast usando o mapa replicado.
