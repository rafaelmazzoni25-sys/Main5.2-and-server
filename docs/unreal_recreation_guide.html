Configuração Inicial

  1. Projeto Multiplayer UE5
    Abra a Unreal > New Project > Games > Blank > habilite C++, Multiplayer e Starter Content. Nas Project Settings: defina Enable Net Dormancy e Use Dedicated Server para builds de servidor.
  2. Submódulos e Estrutura
    Crie pastas Source/Server, Source/Client e Content/UI. No DefaultEngine.ini ajuste NetDriverDefinitions para OnlineSubsystemNull (mock) e defina WorldSettings -> GlobalDefaultGameMode para AGM_ServerAuthoritative.
  3. Classes base
    Adicione classes C++: UGI_MMORPG (GameInstance), AGM_ServerAuthoritative (GameMode), APlayerStateRPG, APlayerControllerLobby, ACharacterRPG. Compile antes de criar Blueprints derivados.

Cookbook rápido: Clique direito no Content Browser → Blueprint Class → selecione sua classe C++ para gerar versões Blueprint (ex.: BP_CharacterRPG).

Sistemas Core: Login & Autenticação

  1. UI de Login
    Content Browser → User Interface → Widget Blueprint → WBP_Login. Abra e: Canvas Panel → adicione Image de fundo (1920x1080), um Vertical Box centralizado com campos Text Box (usuário) e Password Box (senha), botão Login. Binding: no botão, chame PC->Server_RequestLogin(User, Pass) (RPC Server).
  2. RPCs de Handshake
    Em APlayerControllerLobby:
    UFUNCTION(Server, Reliable)
void Server_RequestLogin(const FString& User, const FString& Pass);

UFUNCTION(Client, Reliable)
void Client_LoginResult(bool bOk, const FString& Message);
    Na implementação, valide com dados mock (array local) e chame Client_LoginResult. Em caso de sucesso, abra o mapa de Lobby via ClientTravel.
  3. Spawn do Pawn
    GameMode: sobrescreva ChoosePlayerStart para retornar um PlayerStart por slot. Em PostLogin, chame SpawnDefaultPawnFor e possua o ACharacterRPG. Configure bReplicates e UseControllerRotationYaw no Character.
  4. Persistência temporária
    Em UGI_MMORPG, mantenha structs simples (UserId, CharList). Use SaveGame somente para cache local; toda autoridade fica no servidor dedicado.

Seleção & Lobby

  1. Mapa de Login: Crie um mapa Login_P com um Level Script que instancia WBP_Login no BeginPlay do PlayerController.
  2. Seleção de Sala: Widget WBP_ServerSelect com ListView. Cada linha chama Server_SetDesiredServer(Id) (RPC Server) e o servidor aplica ServerTravel para o mapa de Lobby correspondente.
  3. Seleção de Personagem: Widget WBP_CharacterSelect com Uniform Grid (4 colunas, 320x420 cards). Cada card: preview 3D (Level Sequence ou SceneCapture2D), botões Selecionar/Deletar. No botão Selecionar, chame Server_SelectCharacter(CharId) que seta as replicated vars do APlayerStateRPG e chama ClientTravel para o mapa do mundo.

Gameplay: Mundo & Movimentação

  1. Geração/Streaming de Mapas: Use World Partition. Crie subníveis para cidades e campos. No GameMode, carregue via UGameplayStatics::OpenLevel no servidor e clientes replicam automaticamente.
  2. Navegação: Adicione NavMeshBoundsVolume cobrindo o cenário. Character: habilite Use Controller Desired Rotation e Orient Rotation to Movement. Para click-to-move, no PlayerController em OnLeftClick faça Server_MoveToLocation(Hit.Location) usando AIController::MoveTo.
  3. Gates/Warps: Coloque BoxTrigger com componente UGateDestination (struct MapName, SpawnTag). Ao overlap do servidor, chame ServerTravel ou Teleport para destinos intra-mapa.

Gameplay: Dados & RPG

Use structs replicadas em APlayerStateRPG com ReplicatedUsing para atualizar HUD.

Level Up (fórmula do legado)
  • Incrementa nível se Experience + AddExperience >= NextExperience, adicionando LevelUpPoint por classe e bônus pós nível 220.(Ver código)
  • Atualiza vida/mana/escudo para valores máximos recalculados.
// Em APlayerStateRPG
UPROPERTY(ReplicatedUsing=OnRep_Exp) int64 Experience;
UPROPERTY(Replicated) int32 LevelUpPoints;

UFUNCTION(Server, Reliable)
void Server_AddExperience(int64 Delta) {
    Experience += Delta;
    while (Experience >= NextExp) {
        Level++;
        LevelUpPoints += BasePointsPerClass[ClassId];
        if (Level > 220 && bQuest220Concluida) LevelUpPoints += PlusStatPoint;
        Experience -= NextExp;
        RecalcNextExp();
    }
    OnRep_Exp();
}

Blueprint: use nós WhileLoop, GreaterEqual (int64), incrementando Level e pontos. Fórmula e checkpoints seguem o legado.(Ver código)

UI/UX: Inventário e Drag & Drop

  1. Widget: Content Browser → User Interface → WBP_Inventory. Canvas 1024x768, adicione Border 900x640 central, dentro um Uniform Grid Panel 8x5 (slots de 64px). Habilite DPI Scaling (Project Settings > User Interface).
  2. Slot Blueprint: WBP_ItemSlot com Image (64x64) e overlay para highlight. Implemente interfaces OnDragDetected, OnDrop. No drop, chame Server_MoveItem(SrcIndex, DstIndex) (RPC Server) para ajustar array replicado.
  3. Estrutura: Em C++ crie FItemInstance (Id, Quantity, Durability, Sockets). Array TArray<FItemInstance> InventorySlots replicado com OnRep_Inventory atualizando UI.
  4. Arrastar: No OnDrop do slot, valide tamanho do item (1x1, 1x2) antes de enviar RPC. Se falhar, mostre tooltip "Espaço insuficiente".

UI/UX: HUD, Status, CashShop

  • HUD Base: WBP_HUD 1920x1080, Canvas. Adicione barras: HP (400x24), Mana (320x18), EXP (600x12) ancoradas inferior. Mini-mapa 220x220 (topo direito). Hotbar 10 slots de 64px com espaçamento 4px.
  • Status: Widget WBP_Status 640x720. Use Grid 2 colunas para STR/AGI/VIT/ENE/LDR com botões +. Conecte ao RPC Server_AddStat(StatType, Amount).
  • Warehouse: 10x6 slots (64px) em modal WBP_Warehouse. Só abre quando o servidor confirma interação com NPC Baú.
  • CashShop: Widget 1280x720 com abas (Tabs) para categorias. Cards 256x320 com imagem, descrição e botão Comprar. Chamadas via Server_BuyCashItem(ItemId) validando moeda premium.
  • Tooltips: Widget 420x240, fundo semitransparente, textos ancorados à posição do cursor. Preencha usando DataAsset do item.

Gameplay: Combate & Skills (Server Authoritative)

Fórmula de Dano Físico (legado)

Base: calcula min/max combinando armas (mão direita/esquerda), bônus de skill, efeitos, críticos e excelência, depois subtrai defesa do alvo.(Ver código)

// Simplificação fiel ao legado
int32 ServerCalcPhysicalDamage(const FAttackCtx& Ctx) {
    int32 DamageMin = Ctx.PhyMin + Ctx.SkillMin;
    int32 DamageMax = Ctx.PhyMax + Ctx.SkillMax;
    DamageMin += Ctx.AddPhys;
    DamageMax += Ctx.AddPhys;
    DamageMin = DamageMin * (100 + Ctx.MulPhys) / 100;
    DamageMax = DamageMax * (100 + Ctx.MulPhys) / 100;
    int32 Roll = FMath::RandRange(DamageMin, DamageMax);
    if (Rand(100) < CritRate) Roll = DamageMax + CritBonus;
    if (Rand(100) < ExcRate)  Roll = (DamageMax * 120 / 100) + ExcBonus;
    Roll = FMath::Max(0, Roll - TargetDefense);
    return Roll;
}

Blueprint: nós Random Integer in Range, Float * Int, Subtract, Max. Para crítico: Random Integer < chance.

Projéteis e Line Trace
  1. Line Trace: Em BP_CharacterRPG use LineTraceByChannel a partir da câmera. No hit, chame Server_ApplySkill(Target, SkillId).
  2. Projéteis: Crie BP_SkillProjectile (Actor, MovementComponent). No spawn (RPC Server) configure velocidade. Em OnHit, servidor calcula dano e faz NetMulticast_PlayHitFX.
  3. Fenrir/Plasma: Para skills montaria use fórmula baseada nos atributos por classe (STR/DEX/VIT/ENE/LDR) antes de aplicar crítico/excelente.(Ver código)

Gameplay: NPCs & Lojas

  1. Interação: Coloque BoxCollision nos NPCs. No overlap (servidor), chame Client_OpenShop(ShopId). Use Actor Tag para identificar tipo (Loja, Warehouse, Quest).
  2. UI de Loja: Widget WBP_Shop 960x640. Lista de itens (Grid 6x4). Botões Comprar/Vender chamam Server_BuyItem(ItemId) / Server_SellItem(Slot) validando moedas (Zen ou Cash).
  3. Validação: No servidor, cheque saldo antes de alterar inventário replicado. Use DataAssets para preço e moeda. Retorne sucesso/erro via Client_ShowShopResult.

Database/Itens: Modelagem Completa

  1. DataAssets: Crie PrimaryDataAsset DA_ItemBase com campos: Id, Nome, Tipo (enum), Grade, DamageMin/Max, Defense, Slots (Largura, Altura), Preço, Efeitos (arrays de modifiers).
  2. Carregamento: Crie UItemDatabase singleton que carrega todos os DataAssets em UGI_MMORPG::Init(). Exponha FindItemById.
  3. Instâncias: Struct FItemInstance referencia ItemId, quantidade, durabilidade, level de upgrade e sockets. Replicar na PlayerState.
  4. Drop: No servidor, tabela de drop por MobId. Ao morrer, sorteie itens e adicione ao mundo como BP_WorldItem (Actor com StaticMesh e SphereCollision). No overlap, servidor chama GiveItemToPlayer e destrói o actor.

Mapeamento de Arquivos Legados

Enums do Legado

Resumo (usar como Enum Blueprint):

  • UI: Janela Inventory, Warehouse, CashShop.
  • Itens: Tipo (Weapon, Armor, Wing, Jewel), Raridade, SlotSize.
  • Gameplay: Classe (DW, DK, FE, MG, DL, SU, RF), Resistências, Tipos de Skill.
  • Economia: Moeda (Zen, Cash), Tipo de Loja (NPC, CashShop).

Checklist & Testes

  • Login: RPC Server/Client funcionando e troca de mapa após seleção.
  • Inventário: mover item entre slots replica para outro cliente observador.
  • Dano: comparar resultado do cálculo com fórmulas do legado para mesmos atributos.
  • Loja: compra bloqueada quando saldo insuficiente.
