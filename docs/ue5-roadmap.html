Princípios

  • Usar somente assets originais (modelos, texturas, áudio) do cliente legado.
  • Priorizar Blueprints para UI, fluxo de jogo e scripting; usar C++ apenas para performance/integrações.
  • Documentar cada conversão de asset e cada chamada de rede portada.
Roadmap

Do diagnóstico ao lançamento

1) Diagnóstico inicial

  • Mapear os subsistemas do cliente: render, UI, áudio, input, rede.
  • Listar chamadas do servidor e mensagens binárias para login, movimento e combate.
  • Inventariar assets proprietários (modelos BMD, texturas, animações, efeitos).

2) Fatias verticais

  • Converter um conjunto mínimo de personagens + mapa para testar no UE 5.7.
  • Recriar fluxo de login e movimentação básica via Blueprints.
  • Validar áudio e UI (menus) usando UMG.

3) Expansão controlada

  • Portar mapas e dungeons gradualmente, reusando materiais e colisões.
  • Implementar combate, buffs e efeitos visuais com Niagara.
  • Replicar inventário, quests e eventos sazonais.

4) Rede e escalabilidade

  • Portar protocolo do cliente legado para C++ (sockets) e expor funções Blueprint.
  • Garantir compatibilidade com o servidor, validando pacotes e latência.
  • Automatizar testes de carga e sincronismo de estado.

5) Ferramentas & QA

  • Scripts de conversão de assets (BMD → FBX/GLTF) e auditoria de materiais.
  • Automação de builds e smoke tests in-engine.
  • Checklists de regressão para UI, rede e animações.

6) Lançamento

  • Staging com jogadores internos, telemetria de crashes e performance.
  • Planos de rollback e patch rápido para hotfixes.
  • Entrega final com documentação e treinamentos.
Guia UE 5.7

Passo a passo detalhado

A. Preparação (Cliente + Servidor)

  1. Inventariar assets: exporte modelos, texturas e animações do cliente original. Documente dependências de shaders/efeitos e nomes usados em scripts.
  2. Mapear rede: gere um diagrama das mensagens do cliente (login, seleção de personagem, movimento, combate) e confirme comportamentos esperados no servidor.
  3. Definir branch base: crie um projeto vazio no UE 5.7 com Starter Content desabilitado para garantir uso exclusivo dos assets originais.

A2. Configuração base do projeto (paridade 1:1)

  1. Plugins: habilite Enhanced Input, Niagara, World Partition, Editor Scripting Utilities, Python e Online Subsystem (para sockets). Se houver veículos/montarias, habilite Chaos Vehicles.
  2. Project Settings > Maps & Modes: GameInstance (C++), GameMode base (C++ + BP derivado); Editor Startup Map = Login.umap, Game Default Map = Login.umap, Transition Map = Transition.umap.
  3. Input Mapping Context (IMC_Legacy): ações Move (Axis X/Y), Look (Axis, Scale 0.5), Jump, Attack, Interact, Inventory, Skill1..Skill0. Ajuste escalas conforme resposta do cliente original.
  4. Network: Max Client Rate = 30000; Net Client Fixed Frame Rate = 0; Net Relevancy Check Distance igual ao alcance de renderização legado. Use Network Simulator desligado por padrão.
  5. Rendering: desative Generate Mesh Distance Fields se não usar; habilite Support Sky Atmosphere Affect Height Fog; configure Scalability.ini com LOD Bias e Anisotropy 8x replicando qualidade do cliente.
  6. Framerate: bloqueie em 60 FPS para testes iniciais e consistência de rede; habilite Use Fixed Frame Rate durante depuração de protocolo.

B. Importação e organização de assets

  1. Converter BMD → FBX/GLTF mantendo hierarquia de ossos; valide pesos de vértice e animações.
  2. Texturas e materiais: exporte diffuse/normal/specular; crie Material Instances no UE5 para reutilizar parâmetros.
  3. Mapas: replique colisões e blocagens. Use World Partition se o mapa for grande.
  4. Áudio: importe trilhas e efeitos sonoros; configure Sound Cues equivalentes aos gatilhos do cliente.

B2. Parâmetros de importação (modelos, texturas, áudio)

  1. FBX/GLTF: Import Mesh = true, Skeletal Mesh = true, Import Animations = true, Import Normals & Tangents = true, Preserve Smoothing Groups = true, Max Influences = 4; Skeleton compartilhado (ex.: SK_Player).
  2. Materiais: crie Material Function base (MF_CharacterSurface) com BaseColor/Normal/ORM; Material Instances por personagem copiando Specular/Intensity do cliente. Ative Use Emissive for Static Lighting se precisar de brilho legado.
  3. Texturas: Mip Gen Settings = Sharpen5 (UI) ou Sharpen2 (personagens); Compression Settings = Masks para ORM; desative sRGB em Normal/ORM; mantenha resolução original.
  4. Áudio: Sound Waves em 48 kHz, Compression Quality 60 para SFX curtos; Sound Cues com Random/Loop nodes replicando gatilhos (passos, impactos, UI).
  5. Niagara: limite Max Particles para coincidir com orçamento antigo; crie perfis de qualidade em Scalability > Niagara.
  6. Mapas: habilite World Partition em cenas grandes; converta colisões para Blocking Volume + NavMeshBoundsVolume; Directional Light (6–8 lux), SkyLight e Height Fog com Fog Density ~0.02 (ajuste conforme visibilidade original).

C. Configuração de projeto UE 5.7

  1. GameMode & PlayerController: crie classes C++ base e exponha eventos (login, spawn, morte) a Blueprints.
  2. Pawns/Characters: configure Character Movement; adicione Animation Blueprints e estados (Idle/Run/Attack/Damage).
  3. UI em UMG: recrie telas de login, seleção de personagem e HUD. Use Widget Blueprints com bindings para dados de rede.
  4. Input: mapeie teclas/ações do cliente original usando o Enhanced Input.

D. Rede e replicação

  1. Adaptar protocolo: implemente um módulo C++ para sockets (TCP/UDP) que traduza os pacotes binários legados.
  2. Blueprint Function Library: exponha funções de envio/recebimento para que Blueprints tratem login, movimento e ações.
  3. Validação servidor: compare payloads com o servidor original e implemente checagens de segurança (anti-cheat, rate limit).
  4. Testes de carga: simule sessões múltiplas e inspecione latência/redundância; ajuste replicação de atores e relevância.

E. Gameplay e sistemas

  1. Combate: use Blueprints para estados de ataque, dano e efeitos com Niagara; mantenha cálculos pesados em C++.
  2. Inventário e quests: crie estruturas replicadas e UIs correspondentes; sincronia com servidor para loot e progresso.
  3. Bosses e eventos: scripts de fase em Blueprints; registre ganchos de rede para spawn e mecânicas especiais.
  4. Persistência: confirme salvamento/recuperação de personagens, atributos e itens conforme o servidor legado.

F. QA, otimização e lançamento

  1. Performance: perfilar draw calls, colisões e Blueprints quentes; migrar gargalos para C++ quando necessário.
  2. Testes funcionais: checklists para UI, rede, animações e física; automatize smoke tests.
  3. Builds e deploy: configure Cook, Pak e distribuição; prepare rollback e monitoramento de crashes.
  4. Documentação: registre decisões de assets, scripts de conversão e APIs de rede para a equipe.

G. Sistemas críticos (roteiro prático)

Login
  1. Widget UMG com usuário/senha; valide campos localmente.
  2. Função C++ exposta em Blueprint para montar/enviar pacote de login.
  3. Ao receber sucesso, guarde token/sessão e carregue mapa de seleção.
Criação de personagem
  1. Tela de slots em UMG usando Data Tables para classes/atributos.
  2. Valide nome/classe em Blueprint e chame RPC de criação.
  3. Atualize lista ao receber confirmação; transicione para seleção/spawn.
HUD
  1. Widget principal com HP/MP, XP, mini-mapa e hotbar modulares.
  2. Use Event Dispatchers para ligar atributos replicados.
  3. Inclua toasts/log para feedback de servidor e eventos locais.
Movimentação
  1. Character Blueprint com estados walk/run/dash; ajuste curvas de aceleração.
  2. Mapeie entradas no Enhanced Input e câmera conforme estilo do jogo.
  3. RPCs de movimentação em C++; VFX e passos em Blueprint.
Itens, inventário e drops
  1. Defina itens em Data Table; inventário replicado em PlayerState/Controller.
  2. Widgets de inventário/tooltip em Blueprint, atualizados por eventos.
  3. Actors de drop com colisão; RPC de pickup valida servidor e confirma em UI.
  4. Equipar/usar em Blueprint com checagens sensíveis em C++.
XP e progressão
  1. Calcule XP/nível em C++ e exponha evento OnXpGained a Blueprint.
  2. Ao upar, atualize HUD, atributos e dispare VFX/SFX.
  3. Sincronize mudanças com servidor e regenere barras/ícones em UMG.
Criação de cenário
  1. Organize mapas em World Partition/subníveis; use Level Streaming para login, seleção e mundo.
  2. Gere colisões/NavMesh compatíveis com movimentação original.
  3. Prepare perfis de iluminação/clima (dia/noite/fog) para alternância em Blueprint.
Chat, loja e eventos
  1. Chat com canais e anti-spam em C++; UI em Blueprint.
  2. Loja/serviços consumindo APIs de rede; confirme saldo/estoque antes de concluir.
  3. Buffs/Debuffs e eventos sazonais controlados por timers replicados; efeitos em Blueprint.

H. Guia detalhado 1:1 (Blueprint + C++)

  1. Crie WB_Login com campos de usuário/senha e botão Entrar. Botão chama BP_SendLogin (BPL_Network) que aciona SendLogin em C++.
  2. Valide vazio/regex local; desabilite campos até resposta. Mostre spinner usando Timeline.
  3. Evento OnLoginResult (C++) retorna Success/Fail/Reason; em sucesso salve token no GameInstance e abra Select.umap via OpenLevel.
  4. Servidor envia opcode 0xF1 com token; recuse respostas que excedam o tamanho esperado.

  2. Valide nome (<=12 chars) em Blueprint e chame SendCreateCharacter. Receba OnCharacterCreated para atualizar lista.
  3. Botão Play chama SendSelectCharacter e armazena ID no GameInstance; GameMode instancia BP_PlayerCharacter com atributos de DataTable.
  4. Spawns usam pontos nomeados do mapa original; confirme colisão antes de liberar controle.

  1. WB_HUD agrega WB_Bars (HP/MP/STA), WB_XP, WB_Minimap, WB_Hotbar, WB_Log e WB_QuestTracker.
  2. PlayerState expõe atributos replicados; PlayerController retransmite via Event Dispatchers para widgets.
  3. Minimapa: SceneCapture2D + RenderTarget 512x512; DataTable mapeia ícone por tipo (NPC, portal, objetivo).
  4. Hotbar lê DataTable de skills/itens; botão chama SendAttack/UseItem. Cooldown renderizado com Material Instance dinâmico.

  2. SpringArm com Target Arm Length 600–800 (isométrico) ou 300–400 (over-the-shoulder); Use Pawn Control Rotation conforme estilo original.
  3. Rede: CharacterMovement replicado; habilidades extras usam RPC Server confiável. Habilite Client Prediction e Network Smoothing Mode = Linear.

  3. VFX com Niagara; notifies para passos/impacto/voz acionam Sound Cues. Ajuste Max Particles para budget legado.

  4. Equipar/usar: Server_Equip checa requisitos e replica aparência (Attach ou Mesh Merge).

  3. Perfis Dia/Noite em Data Assets (Directional Intensity, SkyLight Intensity, Fog Density, Temperature). Blueprint alterna conforme servidor.
