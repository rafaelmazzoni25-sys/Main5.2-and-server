Referências do código

  • Loop/Render: Winmain.cpp inicializa OpenGL, UI (UIWindows.h, UIManager.h), cena (ZzzScene.h) e áudio (wzAudio.lib via PlayMp3/StopMp3).
  • Assets: Estruturas BMD em ZzzBMD.h (MAX_BONES=200, MAX_MESH=50, MAX_VERTICES=15000) e scripts de textura em TextureScript.h.

  • Rede: ProtocolSend.h/.cpp define ProtocolHead (login, personagem, posição, movimento) e pacotes PMSG_*_SEND/RECV.
  • UI: Fluxos de login/seleção/criação em LoginWin.cpp, CharSelMainWin.cpp, CharMakeWin.cpp; HUD/inventário em NewUIMainFrameWindow.cpp, NewUIMyInventory.cpp, mini-mapa em NewUIMiniMap.cpp.

Guia detalhado (Blueprint + C++)

  • BMD → FBX/GLTF respeitando MAX_BONES=200, MAX_MESH=50, MAX_VERTICES=15000 (ZzzBMD.h). Preserve hierarquia Bone_t.Parent e bounding boxes.
  • Mapeie flags RENDER_* para materiais: Chrome/Oil → Fresnel+Emissive; Shadow/NoDepth → material sem depth.
  • Material Instance recebe booleans de TextureScript (Bright, HiddenMesh, StreamMesh, NoneBlendMesh, ShadowMesh).
  • Animation Sequences: PlayRate = Action_t.PlaySpeed, Loop conforme Action_t.Loop.
  • Áudio: converter MP3 chamados em PlayMp3/StopMp3 para WAV/OGG; Sound Cues com looping para BGMs.

  1. Implemente cliente socket em C++ (UE Module) com opcodes de ProtocolHead: BOTH_CONNECT_LOGIN, BOTH_CONNECT_CHARACTER, BOTH_POSITION, BOTH_MOVE, BOTH_MESSAGE.
  2. Pacotes:
    • PMSG_CONNECT_ACCOUNT_SEND: account[10], password[20], TickCount, ClientVersion[5], ClientSerial[16] (preencher como SendRequestLogInNew).
    • PMSG_POSITION_SEND: x, y (BYTE).
    • PMSG_MOVE_SEND: x, y, path[8] (primeiro byte = direção + (PathNum-1) como em SendCharacterMoveNew).
  3. Thread de recepção: leia fila e dispare delegates Blueprint equivalentes a RecvMessage() (casos SERVER_CONNECT, BOTH_CONNECT_LOGIN/CHARACTER/POSITION/MOVE/MESSAGE).
  4. Trate resultados de login conforme RecvLoginNew (0x01/0x20 sucesso; 0x00 senha errada; 0x02 ID inválido; 0x06 versão incompatível etc.).
  5. Servidor UE deve iniciar sockets/timers espelhando GameServer.cpp (TCP/UDP, timers 100ms para AI/eventos, 1s/10s para manutenção) e respeitar limites de User.h para replicação.

  • Login: Widget WB_Login valida campos (<=10/20 chars). Botão chama função Blueprint → C++ envia BOTH_CONNECT_LOGIN. Delegate de resultado mapeia códigos de RecvLoginNew e exibe mensagens equivalentes às PopUpMsgWin.
  • Seleção/Criação: WB_CharacterSelect popula slots via retorno de BOTH_CONNECT_CHARACTER. WB_CharacterCreate envia criação com estrutura do servidor; validação de nome antes do envio. Jogar envia select e abre World.umap.
  • HUD: reproduzir NewUIMainFrameWindow com barras HP/MP/Estamina, XP, mini-mapa (SceneCapture2D 512x512), hotbar e log.
  • Mini-mapa: ícones via DataTable (NPC/Party/Enemy) usando máscaras dos mapas de w_MapHeaders.h.

  • Character Blueprint: valores base MaxWalkSpeed=600, BrakingDeceleration=2048, RotationRate=(0,720,0). Animation State Machine cobre ACTION_MOVE/ATTACK/DAMAGE/DIE de User.h.
  • Input: clique simples/hold/double replicam CInput. Rede envia PMSG_POSITION_SEND a cada tile e PMSG_MOVE_SEND ao calcular path (usar DirTable de SendCharacterMoveNew).
  • Câmera: SpringArm 600–800 (isométrico) ou 300–400 (third-person), com pivô ajustado para comportamento do cliente.

  • Estruturar DataAssets como arrays, espelhando Inventory[MAX_INVENTORY] de ZzzInventory.h com colunas _COLUMN_TYPE_* (Level, AttMin/Max, ReqStr/Dex/Eng, etc.).
  • UI de inventário/tooltip deve exibir informações de equipar, requisitos e opções ITEMSETOPTION (Store/Trade/Drop/Repair).
  • Drops: actor com colisão; pickup via RPC validando regras de servidor (ItemDrop.cpp/ItemMove.cpp).
  • Moeda: teto 2.000.000.000 conforme MAX_MONEY em User.h.

  • Nível máximo 400 e tipos de XP (EXPERIENCE_COMMON, EXPERIENCE_PARTY, etc.) conforme User.h.
  • No servidor, reproduzir cálculos de ExperienceTable.cpp; no cliente, evento OnXpChanged atualiza HUD e dispara VFX.
  • Buffs/efeitos usam enums e estruturas de Effect.h/EffectManager.cpp; representar como DataAssets para Blueprints.

  • Converter mapas de w_MapHeaders.h/w_MapProcess.cpp para Levels UE; use World Partition para áreas grandes.
  • Gerar NavMeshBoundsVolume e volumes de colisão correspondentes às malhas originais.
  • Clima/visibilidade: replicar lógica de weather = rand()%3 de Winmain.cpp via perfis de ExponentialHeightFog e SkyLight.

  • Mapear BGMs/efeitos acionados por PlayMp3/StopMp3 em Winmain.cpp; criar Sound Mixes para mutar conforme m_MusicOnOff.
  • Eventos de UI/combate replicam efeitos de DSPlaySound.h/wzAudio.h via Sound Cues.
