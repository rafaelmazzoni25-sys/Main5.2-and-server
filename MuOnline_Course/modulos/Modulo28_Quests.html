CQuest::Load – Carregamento da tabela de quests
📘 O Que é?

Carrega a lista de quests a partir de um script, preenchendo QUEST_INFO com requisitos de nível, classe e dependências.

void CQuest::Load(char* path) {
  CMemScript* lpMemScript = new CMemScript;
  if(lpMemScript->SetBuffer(path) == 0) { ... return; }
  this->m_count = 0;
  while(true) {
    if(lpMemScript->GetToken() == TOKEN_END) break;
    if(strcmp("end",lpMemScript->GetString()) == 0) break;
    QUEST_INFO info; memset(&info,0,sizeof(info));
    info.Index = lpMemScript->GetNumber();
    info.StartType = lpMemScript->GetAsNumber();
    info.MonsterClass = lpMemScript->GetAsNumber();
    info.CurrentState = lpMemScript->GetAsNumber();
    info.RequireIndex = lpMemScript->GetAsNumber();
    info.RequireState = lpMemScript->GetAsNumber();
    info.RequireMinLevel = lpMemScript->GetAsNumber();
    info.RequireMaxLevel = lpMemScript->GetAsNumber();
    for(int n=0;n < MAX_CLASS;n++){info.RequireClass[n] = lpMemScript->GetAsNumber();}
    this->SetInfo(info);
  }
}

🎯 Para Que Serve?

Popular a matriz interna de quests com regras de elegibilidade, base para validar diálogos, recompensas e teleporte.

💻 Como Funciona?

  1. Lê sequencialmente tokens do script até TOKEN_END.
  2. Preenche campos de requisito (nível, classe, dependência de outra quest).
  3. Armazena no array m_QuestInfo através de SetInfo.

CQuest::CGQuestStateRecv – Atualização de estado pelo cliente
📘 O Que é?

Handler de pacote que confirma progresso/estado de quest e aplica recompensas.

void CQuest::CGQuestStateRecv(PMSG_QUEST_STATE_RECV* lpMsg,int aIndex) {
  LPOBJ lpObj = &gObj[aIndex];
  if(gObjIsConnectedGP(aIndex) == 0) return;
  QUEST_INFO* lpInfo = this->GetInfoByIndex(lpObj,lpMsg->QuestIndex);
  if(lpInfo == 0) return;
  if(gQuestObjective.CheckQuestObjective(lpObj,lpInfo->Index) == 0) {
    this->GCQuestResultSend(aIndex,lpInfo->Index,0xFF,this->GetQuestList(lpObj,lpInfo->Index));
    return;
  }
  if(lpInfo->CurrentState == QUEST_NORMAL) {
    gQuestObjective.RemoveQuestObjective(lpObj,lpInfo->Index);
    gQuestReward.InsertQuestReward(lpObj,lpInfo->Index);
    this->AddQuestList(lpObj,lpInfo->Index,QUEST_ACCEPT);
    gQuestObjective.InitQuestObjectiveKillCount(lpObj,lpInfo->Index);
    this->GCQuestResultSend(aIndex,lpInfo->Index,0x00,this->GetQuestList(lpObj,lpInfo->Index));
    return;
  }
  if(lpInfo->CurrentState == QUEST_ACCEPT) {
    gQuestObjective.RemoveQuestObjective(lpObj,lpInfo->Index);
    gQuestReward.InsertQuestReward(lpObj,lpInfo->Index);
    this->AddQuestList(lpObj,lpInfo->Index,QUEST_FINISH);
    gQuestObjective.InitQuestObjectiveKillCount(lpObj,lpInfo->Index);
    this->GCQuestResultSend(aIndex,lpInfo->Index,0x00,this->GetQuestList(lpObj,lpInfo->Index));
    return;
  }
}

🎯 Para Que Serve?

Processa pacotes do cliente para aceitar, completar ou finalizar quests, removendo objetivos pendentes e aplicando recompensas.

💻 Como Funciona?

  1. Valida conexão e obtém QUEST_INFO elegível.
  2. Confere objetivos via gQuestObjective.CheckQuestObjective.
  3. Remove objetivos, insere recompensa (gQuestReward.InsertQuestReward) e altera flag em QuestList.
  4. Reinicia contagem de kills e envia GCQuestResultSend ao cliente.

Implementação em Unreal Engine 5

O fluxo é mapeado para um sistema de missões usando DataAssets, componentes e replicação.

  1. Crie um UDataAsset UQuestTable com uma lista de FQuestRow (Index, Requisitos, Classe, Nível, Objetivos).
  2. Implemente um UQuestComponent em APlayerState ou AActor que mantém arrays replicados de estados (TMap<int32, EQuestState>).
  3. Ao iniciar o servidor, carregue o DataAsset e inicialize o componente (equivalente ao Load).
  4. Crie funções ServerAcceptQuest e ServerCompleteQuest marcadas com UFUNCTION(Server, Reliable), validando requisitos de classe/nível.
  5. Implemente um subsistema de objetivos: ao matar inimigos, incremente contadores no componente (usando delegates de morte ou OnAnyDamage).
  6. Persistência: no servidor UE5, exponha endpoints Node.js/SQL (/quests/save, /quests/load) e, no cliente, use VaRest para salvar/recuperar o mapa de estados durante login/logout.
  7. UI: crie widgets UMG listando quests com bindings para os arrays replicados e botões que chamam ServerAcceptQuest / ServerCompleteQuest.
  8. Teleporte/entrega: em interações com NPCs (Blueprints ou AActor com OnInteract), chame as RPCs e mostre feedback via notificações.

Checklist Final

  • Tabela de quests carregada e validada no servidor UE5.
  • Estados replicados por jogador (aceita, ativa, concluída) sincronizados com clientes.
  • Contadores de kills atualizam objetivos automaticamente.
  • Salvar/carregar progresso via Node.js/SQL e VaRest funcionando.
