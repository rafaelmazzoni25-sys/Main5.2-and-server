Módulo 2 – Rede e Autenticação

Estudamos as classes de rede do cliente (ProtocolSend) e o fluxo de entrada do GameServer para pacotes de login e personagem.

Pré-requisitos

  • Módulo 1 concluído.
  • Conhecimento de sockets TCP e filas de mensagens.

Conceitos do Código Original

Cliente – CProtocolSend (conexão e recebimento)
📘 O Que é?

Classe responsável por abrir a conexão TCP, manter estado e processar mensagens recebidas do servidor.

bool CProtocolSend::ConnectServer(char* IP,uint16_t Port) {
    this->SocketConnect = new CustomClient;
    if (this->SocketConnect->Connect(IP,Port)) {
        return true;
    }
    return false;
}

🎯 Para Que Serve?

Viabiliza a comunicação com GameServer/JoinServer, mantendo a fila de mensagens e repassando para handlers específicos.

💻 Como Funciona?

RecvMessage percorre a fila Incoming() da conexão, desempacota e despacha de acordo com msg.header.id.

while(true) {
    if (!gProtocolSend.SocketConnect->Incoming().empty()) {
        auto msg = gProtocolSend.SocketConnect->Incoming().pop_front().msg;
        switch(msg.header.id) {
            case ProtocolHead::SERVER_CONNECT:
                PMSG_CONNECT_CLIENT_RECV pMsg; msg >> pMsg;
                gProtocolSend.RecvJoinServerNew(&pMsg);
                break;
            case ProtocolHead::BOTH_CONNECT_LOGIN:
                gProtocolSend.RecvLoginNew((PMSG_SIMPLE_RESULT_RECV*)msg.body.data());
                break;
            case ProtocolHead::BOTH_CONNECT_CHARACTER:
                ReceiveCharacterList((BYTE*)msg.body.data());
                break;
        }
    } else { break; }
}

Cliente – Serialização e envio baixo nível (SendPacket)
📘 O Que é?

Funções inline que enviam buffers já montados para o socket, abstraindo o CustomClient.

🎯 Para Que Serve?

Centraliza a chamada de envio para que todos os pacotes (login, movimento, posição) passem pelo mesmo ponto e possam ser monitorados.

💻 Como Funciona?

class CProtocolSend {
public:
    void SendPacket(ProtocolHead head,uint8_t* message, uint16_t size) {
        if(SocketConnect) SocketConnect->DataSend(head,message,size);
    }
    void SendPacketClassic(uint8_t* message,uint16_t size) {
        if(SocketConnect) SocketConnect->DataSend(message,size);
    }
};
Ambas verificam se SocketConnect foi criado e então delegam para DataSend, garantindo consistência de cabeçalhos.

Cliente – Envio de Login e Lista de Personagens
📘 O Que é?

Funções que enviam as requisições de login e recuperação da lista de personagens.

🎯 Para Que Serve?

Controla o estado do protocolo (CurrentProtocolState) e valida versão antes de liberar a seleção de personagem.

💻 Como Funciona?

void CProtocolSend::SendRequestLogInNew(char* account, char* password) {
    PMSG_CONNECT_ACCOUNT_SEND pMsg = { 0 };
    LogIn = 1;
    CurrentProtocolState = REQUEST_LOG_IN;
    strncpy(pMsg.account, account, MAX_ID_SIZE);
    strncpy(pMsg.password, password, MAX_PASSWORD_SIZE);
    pMsg.TickCount = GetTickCount();
    for (int i = 0; i < SIZE_PROTOCOLVERSION; i++)
        pMsg.ClientVersion[i] = (BYTE)(Version[i] - (i + 1));
    SendPacket(ProtocolHead::BOTH_CONNECT_LOGIN,(uint8_t*)&pMsg,sizeof(pMsg));
}
void CProtocolSend::SendRequestCharactersListNew() {
    PMSG_SIMPLE_RESULT_SEND pMsg = { 0 };
    pMsg.result = 1;
    SendPacket(ProtocolHead::BOTH_CONNECT_CHARACTER,(uint8_t*)&pMsg,sizeof(pMsg));
}

Cliente – Tratamento da resposta de login
📘 O Que é?

Handler que interpreta os códigos de retorno e atualiza o estado de protocolo e mensagens de erro.

🎯 Para Que Serve?

Define as transições de CurrentProtocolState e aciona janelas de popup específicas para cada motivo de falha.

💻 Como Funciona?

void CProtocolSend::RecvLoginNew(PMSG_SIMPLE_RESULT_RECV* pMsg) {
    switch (pMsg->result) {
        case 0x20:
        case 0x01:
            CurrentProtocolState = RECEIVE_LOG_IN_SUCCESS;
            LogIn = 2;
            CheckHack();
            break;
        case 0x00: CUIMng::Instance().PopUpMsgWin(RECEIVE_LOG_IN_FAIL_PASSWORD); break;
        case 0x06: CUIMng::Instance().PopUpMsgWin(RECEIVE_LOG_IN_FAIL_VERSION); break;
        case 0x09: CUIMng::Instance().PopUpMsgWin(RECEIVE_LOG_IN_FAIL_NO_PAYMENT_INFO); break;
        default:  CUIMng::Instance().PopUpMsgWin(RECEIVE_LOG_IN_FAIL_CONNECT); break;
    }
}

Implementação em Unreal Engine 5

Use um UActorComponent de rede no PlayerController do cliente para encapsular socket e fila. No servidor, use o sistema de networking próprio de UE5 ou sockets nativos em um AGameSession customizado.

Para cenários web/mobile, você pode combinar sockets com uma camada HTTP usando VaRest + Node.js que valide login diretamente em um banco SQL antes de abrir a sessão de jogo, espelhando o comportamento de SendRequestLogInNew e RecvLoginNew.

Passo a Passo em Unreal Engine 5

  1. Adicionar um componente UNetworkClientComponent ao APlayerController para gerenciar socket e estados de protocolo.
  2. Criar uma classe helper FPayloadBuilder que empacota headers e payloads seguindo o mesmo tamanho dos structs originais.
  3. Implementar conexão TCP/UDP usando FSocket do UE5, configurando Blocking = false para mimetizar o loop com WSAAsyncSelect.
  4. Espelhar as structs de pacotes (PMSG_CONNECT_ACCOUNT_SEND, PMSG_CHARACTER_LIST_RECV) em USTRUCT() com UPROPERTY() para facilitar debug.
  5. Despachar mensagens recebidas no TickComponent, refletindo o switch(msg.header.id) original, e registrar handlers em um mapa de delegates.
  6. Integrar VaRest para uma etapa opcional de autenticação HTTP (Node.js + SQL) que retorna token e endereço/porta do servidor de jogo antes de abrir socket nativo.
  7. No servidor Node.js, criar rota /login que valida conta no banco SQL e retorna JSON com status; salvar scripts SQL no repositório.
  8. Após sucesso HTTP, abrir a conexão TCP para o GameServer e enviar PMSG_CONNECT_ACCOUNT_SEND serializado; caso falhe, exibir erro e reter UI.
  9. Implementar state machine no UGameInstance com enums (ELoginState) garantindo que transições de mapa só ocorram após RECEIVE_LOG_IN_SUCCESS.
  10. Atualizar UI em Blueprints após o handler equivalente a RecvLoginNew sinalizar sucesso, carregando o Widget de seleção de personagem.
  11. Adicionar mensagens de erro localizadas em Widgets, mapeando cada código de falha (senha incorreta, conta banida, servidor cheio) a textos amigáveis.
  12. Implementar timeouts e reconexão automática; ao estourar o tempo, exibir um popup equivalente aos códigos de erro do cliente Win32 e reabrir conexão.
  13. Criar testes automatizados com AutomationTest que simulam respostas do servidor (via socket local ou mock Node.js) e verificam troca de telas.
  14. Registrar um dispatcher/logging central para cada chamada de envio, semelhante ao papel de SendPacket, permitindo captura de tráfego para debug e gravação em arquivo.
  15. Documentar na HUD (por exemplo, um painel debug) o estado atual (REQUEST_LOG_IN, RECEIVE_LOG_IN_SUCCESS), o endereço do servidor e o token HTTP usado.
  16. Publicar um checklist de rede (latência, perda, reconexão) e validar manualmente com pacotes reais capturados via Wireshark para garantir fidelidade ao protocolo.

Guia Blueprint ultra detalhado (iniciante)

  1. Preparar UI de Login
    • Crie um Widget Blueprint chamado WB_Login. Canvas central 1280x720; insira um Border 520x360 centrado (Pos X=380, Pos Y=180).
    • Adicione dois TextBox (Account, Password) dentro do Border: Account em (40,60) com dica “Account”, Password em (40,140) com “Password” e marcar Is Password.
    • Adicione botão “Conectar” em (40,240) tamanho 180x48. Vincule evento OnClicked para o passo seguinte.
    • Adicione um TextBlock vermelho em (40,300) chamado Txt_Erro para exibir mensagens do servidor.
  2. Configurar VaRest + SQL
    • Na pasta /Game/Blueprints/Network, crie BP_HTTPAuth (Actor). Em BeginPlay, defina variável APIBase = "https://auth.local".
    • No evento LoginHTTP(Account,Password), adicione nó VaRest Request (JSON) método POST, URL APIBase + "/login". No Body, Add Field string account/password.
    • No OnRequestComplete, use Get Response Object → Get String Field "token" e Get String Field "gameserver"; salve em variáveis AuthToken e GameServerAddress. Se falhar, atualize Txt_Erro.
    • SQL: crie tabela Accounts(id PK, password_hash, last_token, last_ip); o endpoint deve validar hash, gerar token, salvar em last_token e devolver gameserver_host/port.
  3. Conectar ao socket do GameServer (Blueprint)
    • No PlayerController, adicione componente BP_SocketClient (ActorComponent). Exponha função Connect(Host,Port) (use plugin de socket ou FSocket via C++ wrapper).
    • Após BP_HTTPAuth retornar sucesso, chame BP_SocketClient.Connect(GameServerAddress, Port=55901) e guarde estado IsConnected.
    • Crie evento custom SendLoginPacket(Account,Password): use nó Make Struct com campos alinhados ao struct (account[10], password[20], TickCount, ClientVersion[5]). Serialize para Byte Array e chame Send Bytes.
    • No Tick do componente, leia fila de bytes → decodifique header (2 bytes id + size) → Switch on Int para IDs 0x01 (conectado), 0x20 (login OK), 0x00/0x06/0x09 (erros). Atualize Txt_Erro e navegue para seleção de personagem quando id 0x20.
  4. Fluxo de Seleção de Personagem
    • Crie WB_CharacterList: lista vertical 320x400 em (40,40) + botão “Entrar” em (380,380).
    • Ao receber pacote BOTH_CONNECT_CHARACTER, use ForEach Loop nos personagens e crie widgets WB_CharEntry (texto + ícone). Salvar SelectedIndex.
    • No botão “Entrar”, monte pacote PMSG_SIMPLE_RESULT_SEND (result=1) e envie via Send Bytes; avance para mapa ao receber confirmação.
  5. Checklist visual para iniciantes
    • UI login mostra “Conectando…” em laranja enquanto aguarda resposta.
    • Quando falhar, borda do Border fica vermelha (Set Brush Color).
    • Quando sucesso, botão “Conectar” desabilita e texto muda para “Selecionar personagem…”.
    • LED debug no canto superior direito: um Image 24x24 que troca cor Azul (HTTP), Amarelo (Socket conectando), Verde (Logado), Vermelho (Erro).

Checklist Final

  • Cliente UE5 conecta, envia login e recebe resposta de sucesso ou erro.
  • Fila de recebimento trata pacotes de login e lista de personagens.
  • Estados de protocolo reproduzem CurrentProtocolState do projeto original.
