Módulo 2 – Rede e Autenticação

Estudamos as classes de rede do cliente (ProtocolSend) e o fluxo de entrada do GameServer para pacotes de login e personagem.

Pré-requisitos

  • Módulo 1 concluído.
  • Conhecimento de sockets TCP e filas de mensagens.

Conceitos do Código Original

Cliente – CProtocolSend (conexão e recebimento)
📘 O Que é?

Classe responsável por abrir a conexão TCP, manter estado e processar mensagens recebidas do servidor.

bool CProtocolSend::ConnectServer(char* IP,uint16_t Port) {
    this->SocketConnect = new CustomClient;
    if (this->SocketConnect->Connect(IP,Port)) {
        return true;
    }
    return false;
}

🎯 Para Que Serve?

Viabiliza a comunicação com GameServer/JoinServer, mantendo a fila de mensagens e repassando para handlers específicos.

💻 Como Funciona?

RecvMessage percorre a fila Incoming() da conexão, desempacota e despacha de acordo com msg.header.id.

while(true) {
    if (!gProtocolSend.SocketConnect->Incoming().empty()) {
        auto msg = gProtocolSend.SocketConnect->Incoming().pop_front().msg;
        switch(msg.header.id) {
            case ProtocolHead::SERVER_CONNECT:
                PMSG_CONNECT_CLIENT_RECV pMsg; msg >> pMsg;
                gProtocolSend.RecvJoinServerNew(&pMsg);
                break;
            case ProtocolHead::BOTH_CONNECT_LOGIN:
                gProtocolSend.RecvLoginNew((PMSG_SIMPLE_RESULT_RECV*)msg.body.data());
                break;
            case ProtocolHead::BOTH_CONNECT_CHARACTER:
                ReceiveCharacterList((BYTE*)msg.body.data());
                break;
        }
    } else { break; }
}

Cliente – Envio de Login e Lista de Personagens
📘 O Que é?

Funções que enviam as requisições de login e recuperação da lista de personagens.

🎯 Para Que Serve?

Controla o estado do protocolo (CurrentProtocolState) e valida versão antes de liberar a seleção de personagem.

💻 Como Funciona?

void CProtocolSend::SendRequestLogInNew(char* account, char* password) {
    PMSG_CONNECT_ACCOUNT_SEND pMsg = { 0 };
    LogIn = 1;
    CurrentProtocolState = REQUEST_LOG_IN;
    strncpy(pMsg.account, account, MAX_ID_SIZE);
    strncpy(pMsg.password, password, MAX_PASSWORD_SIZE);
    pMsg.TickCount = GetTickCount();
    for (int i = 0; i < SIZE_PROTOCOLVERSION; i++)
        pMsg.ClientVersion[i] = (BYTE)(Version[i] - (i + 1));
    SendPacket(ProtocolHead::BOTH_CONNECT_LOGIN,(uint8_t*)&pMsg,sizeof(pMsg));
}
void CProtocolSend::SendRequestCharactersListNew() {
    PMSG_SIMPLE_RESULT_SEND pMsg = { 0 };
    pMsg.result = 1;
    SendPacket(ProtocolHead::BOTH_CONNECT_CHARACTER,(uint8_t*)&pMsg,sizeof(pMsg));
}

Cliente – Tratamento da resposta de login
📘 O Que é?

Handler que interpreta os códigos de retorno e atualiza o estado de protocolo e mensagens de erro.

🎯 Para Que Serve?

Define as transições de CurrentProtocolState e aciona janelas de popup específicas para cada motivo de falha.

💻 Como Funciona?

void CProtocolSend::RecvLoginNew(PMSG_SIMPLE_RESULT_RECV* pMsg) {
    switch (pMsg->result) {
        case 0x20:
        case 0x01:
            CurrentProtocolState = RECEIVE_LOG_IN_SUCCESS;
            LogIn = 2;
            CheckHack();
            break;
        case 0x00: CUIMng::Instance().PopUpMsgWin(RECEIVE_LOG_IN_FAIL_PASSWORD); break;
        case 0x06: CUIMng::Instance().PopUpMsgWin(RECEIVE_LOG_IN_FAIL_VERSION); break;
        case 0x09: CUIMng::Instance().PopUpMsgWin(RECEIVE_LOG_IN_FAIL_NO_PAYMENT_INFO); break;
        default:  CUIMng::Instance().PopUpMsgWin(RECEIVE_LOG_IN_FAIL_CONNECT); break;
    }
}

Implementação em Unreal Engine 5

Use um UActorComponent de rede no PlayerController do cliente para encapsular socket e fila. No servidor, use o sistema de networking próprio de UE5 ou sockets nativos em um AGameSession customizado.

Para cenários web/mobile, você pode combinar sockets com uma camada HTTP usando VaRest + Node.js que valide login diretamente em um banco SQL antes de abrir a sessão de jogo, espelhando o comportamento de SendRequestLogInNew e RecvLoginNew.

UCLASS(ClassGroup=(Network))
class UMuClientNetComponent : public UActorComponent {
    GENERATED_BODY()
public:
    void Connect(const FString& Host, int32 Port);
    void TickComponent(float DeltaTime, enum ELevelTick TickType, FActorComponentTickFunction* ThisTickFunction) override {
        // ler fila de mensagens e despachar
    }
    void SendLogin(const FString& User, const FString& Pass);
};

Passo a Passo em Unreal Engine 5

  1. Criar componente de rede e anexar ao APlayerController.
  2. Implementar conexão TCP/UDP usando FSocket do UE5.
  3. Espelhar as structs de pacotes (PMSG_CONNECT_ACCOUNT_SEND) em USTRUCT() para serialização.
  4. Despachar mensagens recebidas no TickComponent, refletindo o switch(msg.header.id) original.
  5. Atualizar UI em Blueprints após RecvLoginNew equivalente sinalizar sucesso.
  6. Para autenticação via HTTP, criar endpoint Node.js com SQL que responde JSON; usar VaRest no cliente para pegar token antes de abrir socket.
  7. Persistir estado de login em UGameInstance e impedir transições de mapa sem CurrentProtocolState válido.
  8. Implementar mensagens de erro localizadas em Widgets, mapeando cada código de falha.
  9. Criar testes automatizados com AutomationTest que simulam respostas do servidor e verificam troca de telas.

Checklist Final

  • Cliente UE5 conecta, envia login e recebe resposta de sucesso ou erro.
  • Fila de recebimento trata pacotes de login e lista de personagens.
  • Estados de protocolo reproduzem CurrentProtocolState do projeto original.
