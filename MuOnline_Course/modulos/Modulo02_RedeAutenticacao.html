Conceitos do Código Original

Cliente – Conexão e recebimento (CProtocolSend)
📘 O Que é?

Classe cliente que abre a conexão, envia ping e despacha mensagens recebidas para handlers específicos.

🎯 Para Que Serve?

Controla a conexão TCP com o servidor e faz o roteamento inicial de pacotes como login, lista de personagens e movimentos.

💻 Como Funciona?

ConnectServer instancia CustomClient e chama Connect. O loop de recebimento (reduzido no código) consome a fila Incoming() e, conforme msg.header.id, chama handlers como RecvLoginNew ou ReceiveMovePosition.

bool CProtocolSend::ConnectServer(char* IP,uint16_t Port) {
    this->SocketConnect = new CustomClient;
    if (this->SocketConnect->Connect(IP,Port)) { return true; }
    return false;
}

Servidor – Conexões auxiliares (GameMainInit)
📘 O Que é?

Função de inicialização que conecta o GameServer aos serviços de JoinServer e DataServer.

🎯 Para Que Serve?

Garante que autenticação e persistência de dados sejam acessíveis antes de aceitar jogadores.

💻 Como Funciona?

Após inicializar entidades (gObjInit) e tabelas de experiência, a função cria conexões com JoinServerProtocolCore e DataServerProtocolCore e prepara o estado de servidor.

void GameMainInit(HWND hwnd) {
    gObjInit();
    InitHackCheck();
    gObjSetExperienceTable();
    gMonsterManager.SetMonsterData();
    gJoinServerConnection.Init(hwnd,JoinServerProtocolCore);
    gDataServerConnection.Init(hwnd,DataServerProtocolCore);
}

Servidor – Roteador de pacotes (ProtocolCore)
📘 O Que é?

Função central que recebe um pacote de cliente e despacha para handlers de chat, posição, itens, trade, skills etc.

🎯 Para Que Serve?

Implementa a tabela de protocolos do servidor, garantindo que cada cabeçalho (head) seja tratado pela lógica correta.

💻 Como Funciona?

A função recebe head e dados brutos. Um switch aciona funções como CGChatRecv, gAttack.CGAttackRecv, gMove.CGTeleportRecv e operações de item/trade. Pacotes especiais são logados para depuração.

void ProtocolCore(BYTE head,BYTE* lpMsg,int size,int aIndex,int encrypt,int serial) {
    switch(head) {
        case 0x00: CGChatRecv((PMSG_CHAT_RECV*)lpMsg,aIndex); break;
        case PROTOCOL_CODE2: gAttack.CGAttackRecv((PMSG_ATTACK_RECV*)lpMsg,aIndex); break;
        case 0x1C: gMove.CGTeleportRecv((PMSG_TELEPORT_RECV*)lpMsg,aIndex); break;
        case 0x22: gItemManager.CGItemGetRecv((PMSG_ITEM_GET_RECV*)lpMsg,aIndex); break;
        case 0x3F: gPersonalShop.CGPShopSetItemPriceRecv((PMSG_PSHOP_SET_ITEM_PRICE_RECV*)lpMsg,aIndex); break;
        ...
    }
}

Implementação em Unreal Engine 5

O stack de rede de UE5 usa UNetDriver e APlayerController para replicação.

  • Substitua CProtocolSend por uma UActorComponent em um APlayerController que abra um FSocket custom (ou use o sistema de replicação padrão).
  • Implemente roteamento de pacotes com FPacketHandler ou mensagens RPC. Cada case de ProtocolCore vira um Server/Client RPC.
  • Conexões auxiliares (Join/Data) podem ser simuladas com UGameInstanceSubsystem que abre sockets adicionais ou faz chamadas HTTP para serviços externos.

Passo a Passo em Unreal Engine 5

  1. Criar um componente de rede no APlayerController para abrir sockets ou usar replicação padrão.
  2. Implementar RPCs de login/lista de personagens equivalentes aos handlers do cliente.
  3. Criar um subsystem para conexões auxiliares (Join/Data) simulando GameMainInit.
  4. Adicionar logs de pacotes recebidos para depuração, espelhando ProtocolCore.

Checklist Final

  • Cliente UE5 consegue abrir conexão e receber respostas de autenticação.
  • Pacotes de lista de personagem e movimento são roteados para handlers apropriados.
  • Serviços auxiliares (Join/Data) respondem e mantêm sessão ativa.
  • Logs de rede exibem cabeçalhos/códigos de mensagem recebidos.
