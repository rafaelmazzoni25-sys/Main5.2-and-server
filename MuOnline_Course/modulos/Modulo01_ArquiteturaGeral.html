Inicialização do GameServer – GameMainInit
📘 O Que é?

Rotina de boot do GameServer que valida mutex, inicializa tabelas, monstros e conexões com JoinServer/DataServer.

void GameMainInit(HWND hwnd) {
    if(CreateMutex(0,0,gServerInfo.m_ServerMutex)==0 || GetLastError()==ERROR_ALREADY_EXISTS) {
        ErrorMessageBox("Could not open GameServer");
        return;
    }
    gObjInit();
    InitHackCheck();
    InitBattleSoccer();
    gServerInfo.ReadInit();
    gObjSetExperienceTable();
    gMonsterManager.SetMonsterData();
    gJoinServerConnection.Init(hwnd,JoinServerProtocolCore);
    gDataServerConnection.Init(hwnd,DataServerProtocolCore);
}

🎯 Para Que Serve?

Garante exclusividade do processo, carrega configuração, popula tabelas de experiência e monstros, e liga sockets com os servidores auxiliares.

💻 Como Funciona?

Após validar mutex, chama inicializações de objetos e sistemas de segurança, lê configuração, monta tabelas e prepara conexões TCP.

gObjInit();
InitHackCheck();
gServerInfo.ReadInit();

Loop principal do cliente – WinMain e Scene()
📘 O Que é?

Laço de mensagens do executável Win32 que despacha eventos de janela e roda o rendering Scene quando não há mensagens pendentes.

while( 1 )
{
    if( PeekMessage( &msg, NULL, 0, 0, PM_NOREMOVE ) )
    {
        if( !GetMessage( &msg, NULL, 0, 0 ) ) break;
        TranslateMessage(&msg);
        DispatchMessage(&msg);
    }
    else
    {
        if (g_bUseWindowMode == TRUE || g_bWndActive)
            Scene(g_hDC);
        // ... gerenciamento de minimização
    }

    if(SceneFlag < CHARACTER_SCENE)
        ProtocolCompiler();
    g_pChatRoomSocketList->ProtocolCompile();
    gProtocolSend.RecvMessage();
}

🎯 Para Que Serve?

Controla o ciclo de vida do cliente, intercalando processamento de mensagens, renderização e processamento de pacotes de rede.

💻 Como Funciona?

O loop verifica mensagens com PeekMessage; quando não há, chama Scene para desenhar e, em seguida, executa os compiladores de protocolo.

// Winmain.cpp

Implementação em Unreal Engine 5

Em UE5, centralize a inicialização em um UGameInstance customizado para cliente e em um AGameModeBase para o servidor dedicado.

  • Globais do cliente: criar um UGameInstance que guarda singletons (UI Manager, timer) usando UPROPERTY() para gerenciamento automático.
  • Bootstrap de servidor: em um servidor dedicado UE5, usar AGameModeBase::StartPlay para carregar tabelas (Data Assets) e abrir conexões a serviços externos.
UCLASS()
class UMuGameInstance : public UGameInstance {
    GENERATED_BODY()
public:
    virtual void Init() override {
        Super::Init();
        // Inicializar sistema de áudio e UI
    }
    virtual void Shutdown() override {
        // Salvar preferências e liberar recursos
    }
};

Passo a Passo em Unreal Engine 5

  1. Criar um projeto C++ em UE5 e adicionar uma classe derivada de UGameInstance para conter referências globais (UI, sockets, timers).
  2. Registrar a classe no Project Settings > Maps & Modes e habilitar suporte a Dedicated Server se for compilar o servidor.
  3. Adicionar um AGameModeBase customizado para o servidor dedicado (ou modo listen) que inicializa tabelas e conexões, chamando helpers de carga no StartPlay.
  4. Implementar carga de configurações (equivalente a gServerInfo.ReadInit()) usando Data Assets ou arquivos JSON lidos por FFileHelper; validar mutex/porta antes de continuar.
  5. Configurar um subsystem de áudio para tocar trilhas de fundo, com checagens de estado similares a PlayMp3/StopMp3; expor volumes em UUserSettings para salvar no Shutdown.
  6. Recriar o loop principal com FTickableGameObject ou um UActorComponent tickável que processa fila de rede mesmo sem input, chamando renderização e compiladores de protocolo equivalentes.
  7. Criar um UUserWidget de splash/loading que dispara a inicialização de sockets/HTTP antes de entrar no mapa, bloqueando input até concluir.
  8. Para o servidor dedicado, criar um executável alvo "Server" no Unreal Build Tool e um script de serviço (systemd ou Windows Service) que instancia o mapa inicial e valida exclusividade similar a GameMainInit.
  9. Modelar o equivalente ao g_ErrorReport com um logger assíncrono (por exemplo, AsyncTask + gravação em arquivo) que registre versão, GPU e resolução, e que seja inicializado no Init da GameInstance.
  10. Usar FScopedSlowTask para exibir progresso enquanto dados (tabelas de monstros/mapa) são carregados, correspondendo à leitura de config.ini e Data\\Enc1.dat.
  11. Configurar watchdog para minimizar e restaurar janela quando perder foco, replicando checagens de g_bUseWindowMode e timers de inatividade usando eventos de UGameViewportClient.
  12. Adicionar testes manuais: iniciar cliente, verificar abertura da janela, áudio de fundo, logs de GPU/resolução e criação de assets em memória sem crash.
  13. Configurar um comando de console (ex.: mu.DumpInit) para verificar se todos os subsistemas estão carregados, ajudando a depurar como no g_ErrorReport.
  14. Documentar os pontos de extensão (UI Manager, sistema de áudio, loader de mapas) no README do projeto UE5 para corresponder aos globais do WinMain.

Checklist Final

  • Cliente UE5 inicializa UI, áudio e configurações sem recursos não inicializados.
  • Servidor UE5 executa uma rotina de boot que valida exclusividade e carrega dados.
  • Estrutura de classes UE5 mapeia claramente os papéis de Winmain.cpp e GameMain.cpp.
