Módulo 1 – Arquitetura e Bootstrap

Mapeamos os pontos de entrada e inicialização do cliente (Main 5.2) e do GameServer (Update 15), preparando o terreno para recriar a mesma organização em UE5.

Pré-requisitos

  • Leitura do index do curso.
  • Noções de C++ 17 e ciclo de vida de aplicações Win32.
  • Familiaridade com o modelo de subsistemas de um jogo cliente/servidor.

Inicialização do GameServer – GameMainInit
📘 O Que é?

Rotina de boot do GameServer que valida mutex, inicializa tabelas, monstros e conexões com JoinServer/DataServer.

void GameMainInit(HWND hwnd) {
    if(CreateMutex(0,0,gServerInfo.m_ServerMutex)==0 || GetLastError()==ERROR_ALREADY_EXISTS) {
        ErrorMessageBox("Could not open GameServer");
        return;
    }
    gObjInit();
    InitHackCheck();
    InitBattleSoccer();
    gServerInfo.ReadInit();
    gObjSetExperienceTable();
    gMonsterManager.SetMonsterData();
    gJoinServerConnection.Init(hwnd,JoinServerProtocolCore);
    gDataServerConnection.Init(hwnd,DataServerProtocolCore);
}

🎯 Para Que Serve?

Garante exclusividade do processo, carrega configuração, popula tabelas de experiência e monstros, e liga sockets com os servidores auxiliares.

💻 Como Funciona?

Após validar mutex, chama inicializações de objetos e sistemas de segurança, lê configuração, monta tabelas e prepara conexões TCP.

gObjInit();
InitHackCheck();
gServerInfo.ReadInit();
gJoinServerConnection.Init(hwnd,JoinServerProtocolCore);

Loop principal do cliente – WinMain e Scene()
📘 O Que é?

Laço de mensagens do executável Win32 que despacha eventos de janela e roda o rendering Scene quando não há mensagens pendentes.

while( 1 )
{
    if( PeekMessage( &msg, NULL, 0, 0, PM_NOREMOVE ) )
    {
        if( !GetMessage( &msg, NULL, 0, 0 ) ) break;
        TranslateMessage(&msg);
        DispatchMessage(&msg);
    }
    else
    {
        if (g_bUseWindowMode == TRUE || g_bWndActive)
            Scene(g_hDC);
        // ... gerenciamento de minimização
    }

    if(SceneFlag < CHARACTER_SCENE)
        ProtocolCompiler();
    g_pChatRoomSocketList->ProtocolCompile();
    gProtocolSend.RecvMessage();
}

🎯 Para Que Serve?

Controla o ciclo de vida do cliente, intercalando processamento de mensagens, renderização e processamento de pacotes de rede.

💻 Como Funciona?

O loop verifica mensagens com PeekMessage; quando não há, chama Scene para desenhar e, em seguida, executa os compiladores de protocolo.

// Winmain.cpp
if(SceneFlag < CHARACTER_SCENE)
    ProtocolCompiler();

Implementação em Unreal Engine 5

Em UE5, centralize a inicialização em um UGameInstance customizado para cliente e em um AGameModeBase para o servidor dedicado.

  • Globais do cliente: criar um UGameInstance que guarda singletons (UI Manager, timer) usando UPROPERTY() para gerenciamento automático.
  • Bootstrap de servidor: em um servidor dedicado UE5, usar AGameModeBase::StartPlay para carregar tabelas (Data Assets) e abrir conexões a serviços externos.
UCLASS()
class UMuGameInstance : public UGameInstance {
    GENERATED_BODY()
public:
    virtual void Init() override {
        Super::Init();
        // Inicializar sistema de áudio e UI
    }
    virtual void Shutdown() override {
        // Salvar preferências e liberar recursos
    }
};

UCLASS()
class AMuServerMode : public AGameModeBase {
    GENERATED_BODY()
public:
    virtual void StartPlay() override {
        Super::StartPlay();
        // Carregar dados e iniciar conexões (sockets ou HTTP)
    }
};

Passo a Passo em Unreal Engine 5

  1. Criar um projeto C++ em UE5 e adicionar uma classe derivada de UGameInstance para conter referências globais (UI, sockets, timers).
  2. Registrar a classe no Project Settings > Maps & Modes e habilitar suporte a Dedicated Server se for compilar o servidor.
  3. Adicionar um AGameModeBase customizado para o servidor dedicado (ou modo listen) que inicializa tabelas e conexões, chamando helpers de carga no StartPlay.
  4. Implementar carga de configurações (equivalente a gServerInfo.ReadInit()) usando Data Assets ou arquivos JSON lidos por FFileHelper; validar mutex/porta antes de continuar.
  5. Configurar um subsystem de áudio para tocar trilhas de fundo, com checagens de estado similares a PlayMp3/StopMp3; expor volumes em UUserSettings para salvar no Shutdown.
  6. Recriar o loop principal com FTickableGameObject ou um UActorComponent tickável que processa fila de rede mesmo sem input, chamando renderização e compiladores de protocolo equivalentes.
  7. Criar um UUserWidget de splash/loading que dispara a inicialização de sockets/HTTP antes de entrar no mapa, bloqueando input até concluir.
  8. Para o servidor dedicado, criar um executável alvo "Server" no Unreal Build Tool e um script de serviço (systemd ou Windows Service) que instancia o mapa inicial e valida exclusividade similar a GameMainInit.
  9. Modelar o equivalente ao g_ErrorReport com um logger assíncrono (por exemplo, AsyncTask + gravação em arquivo) que registre versão, GPU e resolução, e que seja inicializado no Init da GameInstance.
  10. Usar FScopedSlowTask para exibir progresso enquanto dados (tabelas de monstros/mapa) são carregados, correspondendo à leitura de config.ini e Data\\Enc1.dat.
  11. Configurar watchdog para minimizar e restaurar janela quando perder foco, replicando checagens de g_bUseWindowMode e timers de inatividade usando eventos de UGameViewportClient.
  12. Adicionar testes manuais: iniciar cliente, verificar abertura da janela, áudio de fundo, logs de GPU/resolução e criação de assets em memória sem crash.
  13. Configurar um comando de console (ex.: mu.DumpInit) para verificar se todos os subsistemas estão carregados, ajudando a depurar como no g_ErrorReport.
  14. Documentar os pontos de extensão (UI Manager, sistema de áudio, loader de mapas) no README do projeto UE5 para corresponder aos globais do WinMain.

Tutorial clique a clique em Blueprints (iniciante)

  1. Abrir o Content Browser e criar uma pasta /MU/Bootstrap. Dentro dela, clicar com o direito > Blueprint Class > derivar de GameInstance e nomear BP_MuGameInstance. Repetir criando BP_MuServerMode derivado de GameModeBase.
  2. Abrir Project Settings > Maps & Modes e em Game Instance Class selecionar BP_MuGameInstance. Em Default GameMode definir BP_MuServerMode. Salvar.
  3. No BP_MuGameInstance, na guia Event Graph, adicionar um Event Init. Colocar um Sequence com três saídas nomeadas LoadConfig, InitAudio, InitSockets. Cada saída alimenta um Run Blueprint Function que chama funções colapsadas:
    • LoadConfig: adicionar um Read File (plugin Victory ou C++ helper) apontando para Saved/Config/Windows/Game.ini, parsear JSON via VaRest Json Object e popular variáveis ServerHost, ServerPort, MusicVolume. Exibir toast usando Create Widget > WBP_Toast (classe simples com texto).
    • InitAudio: criar variável AmbientSound do tipo AudioComponent, instanciar com Spawn Sound 2D usando MusicVolume lido; salvar referência em AudioRef. Se volume 0, chamar Set Paused (Audio) para replicar StopMp3 do código legado.
    • InitSockets: se o projeto usar plugin de sockets HTTP, adicionar VaRestSubsystem ref com Get Game Instance Subsystem. Em seguida, Set Timer by Function Name (intervalo 5s) chamando PingServer para simular heartbeats de disponibilidade.
  4. Criar um Widget WBP_Splash em /MU/UI com fundo preto e texto centralizado (Anchor Full Screen) indicando "Inicializando". No BP_MuGameInstance, ainda no Event Init, usar Create Widget > WBP_Splash e Add to Viewport antes de inicializar sockets; remover após terminar com Remove from Parent.
  5. Para reproduzir o DestroyWindow legado, adicionar em BP_MuGameInstance um evento custom SaveAndShutdown. Incluir VaRestRequest JSON (POST) para rota /config/save com payload {"Volume": MusicVolume}; ao completar, chamar Quit Game.
  6. Em BP_MuServerMode, abrir o Event Graph e ligar Event BeginPlay a um Sequence com saídas MutexCheck, LoadTables, ConnectServices:
    • MutexCheck: adicionar variável bool bServerAlreadyRunning controlada por arquivo lock em Saved/Locks/gs.lock usando Does File Exist. Se existir, registrar log com Print String (vermelho) e chamar Quit Game; senão, criar arquivo com Write File contendo timestamp.
    • LoadTables: criar Data Table DT_Monsters (estrutura com ID, HP, PosX, PosY). No Blueprint, usar Load Data Table Row em um For Each Row e popular um Map<int, FMonsterRow>. Exibir barra de progresso com FScopedSlowTask equivalente usando ProgressBar em widget WBP_ServerBoot (Ancora centro, 600x30 px).
    • ConnectServices: usar VaRestRequest (GET) para /health do JoinServer e DataServer. Em caso de falha, setar um timer de retry 10s e mostrar alerta em WBP_ServerBoot (texto vermelho, alinhamento topo-direita com margem 24px).
  7. No Level Blueprint do mapa inicial (Persistent_Level), adicionar node Get Game Instance -> Cast to BP_MuGameInstance -> Call SaveAndShutdown ao pressionar tecla Esc, replicando o encerramento seguro.
  8. Para espelhar o Loop principal, criar um Actor chamado BP_TickRouter com Tick Enabled. No Event Tick adicionar Branch se bIsMinimized (bool controlada por On Window Focus Changed via GameViewportClient C++ ou plugin). Se true, chamar Delay 0.5 para reduzir carga; se false, executar funções ProcessNetwork e RenderUI (colapsadas em Blueprint) para centralizar a lógica de atualização.
  9. Checklist visual: abrir Play in Editor (PIE), verificar que WBP_Splash aparece e some; apertar Esc e checar request /config/save no console VaRest; desconectar rede e confirmar retries de ConnectServices; ajustar volume para 0 e validar que AudioRef pausa.
  10. Registrar um comando de console mu.dumpinit em C++ (FAutoConsoleCommand) que imprime no log valores de ServerHost/Port, estado de áudio e status dos serviços. Documentar no final do módulo como macro de depuração que o aluno deve copiar/colar.

Checklist Final

  • Cliente UE5 inicializa UI, áudio e configurações sem recursos não inicializados.
  • Servidor UE5 executa uma rotina de boot que valida exclusividade e carrega dados.
  • Estrutura de classes UE5 mapeia claramente os papéis de Winmain.cpp e GameMain.cpp.
