Módulo 1 – Arquitetura e Bootstrap

Visão geral dos pontos de entrada do cliente e do servidor, evidenciando como o loop principal, recursos gráficos e conexões são inicializados.

Pré-requisitos

  • Conhecimentos básicos de C++ legado (Win32) e gerenciamento de janela.
  • Conceitos de loops de renderização e tratamento de mensagens.
  • Noções de criação de projetos C++ em Unreal Engine 5.

Conceitos do Código Original

Loop principal do cliente – WinMain
📘 O Que é?

Ponto de entrada Win32 do cliente que configura a janela, OpenGL, áudio e despacha o loop principal.

int APIENTRY WinMain(HINSTANCE hInstance, HINSTANCE hPrevInstance, PSTR szCmdLine, int nCmdShow)
{
    ...
    while(1)
    {
        if(PeekMessage(&msg,NULL,0,0,PM_NOREMOVE)) { ... }
        else { Scene(g_hDC); }
        ProtocolCompiler();
    }
}

🎯 Para Que Serve?

Inicializa log, resolução, fontes, input, áudio, sistemas de UI e executa o loop que alterna entre processamento de mensagens Win32 e renderização da cena, além de compilar pacotes de rede.

💻 Como Funciona?

Após ler versão e chaves de criptografia, a função cria janela/OpenGL, fontes e subsistemas (input, UI, som). O loop verifica mensagens com PeekMessage; se não houver, chama Scene(g_hDC) para renderizar. A cada iteração, chama ProtocolCompiler() e, no modo novo protocolo, gProtocolSend.RecvMessage().

g_hWnd = StartWindow(hInstance,nCmdShow);
if(!CreateOpenglWindow()) return FALSE;
...
while( 1 ) {
    if( PeekMessage(&msg,NULL,0,0,PM_NOREMOVE) ) { ... }
    else { Scene(g_hDC); }
    ProtocolCompiler();
    gProtocolSend.RecvMessage();
}

⏱️ Quando é Executado?

Executado ao iniciar o executável do cliente (WinMain padrão). O loop roda até WM_QUIT ser recebido, chamando Scene sempre que não há mensagens.

if( !GetMessage(&msg,NULL,0,0) ) { break; }
TranslateMessage(&msg);
DispatchMessage(&msg);
// sem mensagens
Scene(g_hDC);

Bootstrap do servidor – GameServer::WinMain
📘 O Que é?

Ponto de entrada Win32 do GameServer que registra janela, inicializa sockets, timers e subsistemas de jogo.

🎯 Para Que Serve?

Configura título/janela, carrega configurações, inicia sockets TCP/UDP, conecta-se a JoinServer/DataServer e ativa timers do loop de jogo.

💻 Como Funciona?

Após registrar classe de janela, lê GameServerInfo, inicia WSAStartup e gSocketManager. Chama GameMainInit para alocar entidades e tabelas, depois conecta a servidores auxiliares e agenda timers via gQueueTimer.CreateTimer. O loop principal processa mensagens com GetMessage.

if(WSAStartup(MAKEWORD(2,2),&wsa) == 0) {
    if(gSocketManager.Start((WORD)gServerInfo.m_ServerPort)) {
        GameMainInit(hWnd);
        JoinServerConnect(WM_JOIN_SERVER_MSG_PROC);
        DataServerConnect(WM_DATA_SERVER_MSG_PROC);
        gQueueTimer.CreateTimer(QUEUE_TIMER_MONSTER,100,&QueueTimerCallback);
        ...
    }
}
while(GetMessage(&msg,0,0,0)!=0) {
    TranslateMessage(&msg);
    DispatchMessageA(&msg);
}

⏱️ Quando é Executado?

Ao iniciar o executável do GameServer. A inicialização ocorre antes de entrar no loop de mensagens; timers e conexões são configurados imediatamente após GameMainInit.

Implementação em Unreal Engine 5

Em UE5, os pontos de entrada são substituídos por módulos e classes de GameInstance.

  • Crie um módulo C++ e use UGameInstance para inicialização de recursos (equivalente ao bloco antes do loop).
  • Use FSlateApplication ou uma janela customizada apenas se necessário; normalmente a viewport já é criada pela engine.
  • O loop de jogo é gerenciado pela engine; implemente lógica recorrente em Tick de UGameInstance ou AActor para substituir o while manual.
  • Para timers, utilize FTimerManager em vez de SetTimer Win32.
// GameInstance customizado
UCLASS()
class UMuGameInstance : public UGameInstance {
    GENERATED_BODY()
public:
    virtual void Init() override {
        // carregar configs e inicializar sockets
    }
    virtual void Shutdown() override {
        // liberar conexões
    }
};

Passo a Passo em Unreal Engine 5

  1. Criar um projeto C++ em UE5 e adicionar uma classe derivada de UGameInstance.
  2. Inicializar leitura de configuração e sockets no método Init.
  3. Configurar FTimerManager para tarefas recorrentes que substituem SetTimer.
  4. Usar Tick de UGameInstance ou um Subsystem para lógica recorrente equivalente ao loop while(1).

Checklist Final

  • Janela/viewport do projeto UE5 abre e renderiza a cena base.
  • UGameInstance lê configurações iniciais e registra logs.
  • Timers recorrentes configurados para substituir chamadas periódicas do cliente.
  • Sockets ou serviços necessários inicializados sem bloquear a thread principal.
