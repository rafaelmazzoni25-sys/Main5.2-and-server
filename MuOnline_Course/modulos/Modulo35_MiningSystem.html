Módulo 35 – Sistema de Mineração

Aborda o sistema de mineração do GameServer: leitura de estágios, checagens de interface, consumo de picareta e pacotes 0x4C para início/sucesso/falha. Inclui adaptação completa para UE5 com componentes, UI e backend opcional.

Conceitos do Código Original

CMiningSystem::Load/GetMiningInfo – Configuração de estágios e recompensas
📘 O Que é?

Carrega do script os estágios, valores de dano na picareta e recompensas; fornece busca por índice/classe.

void CMiningSystem::Load(char* path) {
  CMemScript* lpMemScript = new CMemScript;
  if(lpMemScript->SetBuffer(path) == 0) { ErrorMessageBox(lpMemScript->GetLastError()); return; }
  m_MiningInfo.clear();
  while(true) {
    if(lpMemScript->GetToken() == TOKEN_END) break;
    if(strcmp("end",lpMemScript->GetString()) == 0) break;
    MINING_INFO info; info.Index = lpMemScript->GetNumber(); info.Stage = lpMemScript->GetAsNumber(); info.Value = lpMemScript->GetAsNumber(); info.ItemRate = lpMemScript->GetAsNumber(); info.ItemIndex = lpMemScript->GetAsNumber(); info.ItemCount = lpMemScript->GetAsNumber(); info.BonusItemRate = lpMemScript->GetAsNumber(); info.BonusItemIndex = lpMemScript->GetAsNumber(); info.BonusItemCount = lpMemScript->GetAsNumber(); m_MiningInfo.push_back(info);
  }
}
bool CMiningSystem::GetMiningInfo(int index,int stage,MINING_INFO* lpInfo) {
  for(auto it=m_MiningInfo.begin(); it!=m_MiningInfo.end(); it++) {
    if(it->Index == index && it->Stage == stage) { (*lpInfo)=(*it); return 1; }
  }
  return 0;
}

🎯 Para Que Serve?

Define quantos estágios uma pedra possui, quanto de durabilidade consome na picareta e quais itens/bonus ela pode conceder.

💻 Como Funciona?

Parseia cada linha do script e guarda numa lista; GetMiningInfo busca pelo índice do monstro e estágio pedido, retornando a configuração usada nos handlers.

CGMiningStartRecv – Validações e avanço de estágio
📘 O Que é?

Handler do pacote 0x4C, subcódigo 0x00, que verifica permissões, estado da interface e consumo de picareta.

🎯 Para Que Serve?

Evita exploração (ex.: outro player já minerando, mapa diferente, interface ocupada) e controla avanço de estágio, atualizando durabilidade e interface.

💻 Como Funciona?

void CMiningSystem::CGMiningStartRecv(PMSG_MINING_START_RECV* lpMsg,int aIndex) {
  if(gObjIsConnectedGP(aIndex) == 0) return; if(lpMsg->index != aIndex) return; if(gObjIsConnected(lpMsg->MonsterIndex) == 0) return;
  MINING_INFO MiningInfo; if(GetMiningInfo(lpMsg->MonsterClass,(lpMsg->stage+1),&MiningInfo) == 0) { GCMiningStartSend(...,0,3); return; }
  if(gObj[lpMsg->MonsterIndex].Map != lpObj->Map) { GCMiningStartSend(...,0,3); return; }
  if(OBJECT_RANGE(gObj[lpMsg->MonsterIndex].MiningIndex) != 0 && gObj[lpMsg->MonsterIndex].MiningIndex != aIndex) { GCMiningStartSend(...,0,8); return; }
  if(lpObj->Change >= 0) { GCMiningStartSend(...,0,10); return; }
  if(gItemManager.GetInventoryEmptySlotCount(lpObj) < MAX_MINING_JEWEL_PACK) { GCMiningStartSend(...,0,11); return; }
  if(lpObj->Inventory[0].IsItem() == 0 || lpObj->Inventory[0].m_Index != GET_ITEM(0,41) || lpObj->Inventory[0].m_Durability < MiningInfo.Value) { GCMiningStartSend(...,0,18); return; }
  if((GetLargeRand()%10000) < MiningInfo.ItemRate) {
    lpObj->Inventory[0].m_Durability -= MiningInfo.Value; gItemManager.GCItemDurSend(aIndex,0,(BYTE)lpObj->Inventory[0].m_Durability,0);
    lpObj->Interface.use = 1; lpObj->Interface.type = INTERFACE_MINING; lpObj->MiningStage++; lpObj->MiningIndex = lpMsg->MonsterIndex;
    gObj[lpMsg->MonsterIndex].MiningStage = 1; gObj[lpMsg->MonsterIndex].MiningIndex = aIndex;
    GCMiningStartSend(aIndex,lpMsg->MonsterIndex,lpMsg->MonsterClass,lpMsg->map,lpObj->MiningStage,MiningInfo.ItemCount,(lpObj->MiningStage==MAX_MINING_STAGE)?1:0);
  } else { /* falha */ GCMiningStartSend(aIndex,lpMsg->MonsterIndex,lpMsg->MonsterClass,lpMsg->map,lpMsg->stage,0,2); }
}

CGMiningSuccessRecv/FailureRecv – Conclusão, drop e reset de interface
📘 O Que é?

Handlers para concluir mineração com sucesso ou falha, limpando interface, aplicando recompensas e matando o monstro.

🎯 Para Que Serve?

Fecha o fluxo garantindo consistência: remove link entre jogador e monstro, zera interface, entrega item e executa CharacterLifeCheck.

💻 Como Funciona?

void CMiningSystem::CGMiningSuccessRecv(PMSG_MINING_SUCCESS_RECV* lpMsg,int aIndex) {
  if(gObjIsConnectedGP(aIndex) == 0) return; if(lpMsg->index != aIndex) return; if(gObjIsConnected(lpMsg->MonsterIndex) == 0) return;
  if(lpObj->Interface.use == 0 || lpObj->Interface.type != INTERFACE_MINING) return; if(lpObj->MiningIndex != lpMsg->MonsterIndex) return;
  if(GetMiningInfo(lpMsg->MonsterClass,lpObj->MiningStage,&MiningInfo) == 0) { GCMiningSuccessSend(...,0); return; }
  // entrega recompensa e reseta
  lpObj->Interface.use = 0; lpObj->Interface.type = INTERFACE_NONE; lpObj->Interface.state = 0; lpObj->MiningStage = 0; lpObj->MiningIndex = -1;
  gObj[lpMsg->MonsterIndex].Life = 0; gObj[lpMsg->MonsterIndex].MiningStage = 0; gObj[lpMsg->MonsterIndex].MiningIndex = -1;
  gObjectManager.CharacterLifeCheck(lpObj,&gObj[lpMsg->MonsterIndex],0,0,0,0,0,0);
  GCMiningSuccessSend(aIndex,lpMsg->MonsterIndex,lpMsg->MonsterClass,lpMsg->map,lpMsg->stage,3);
}
void CMiningSystem::CGMiningFailureRecv(...) {
  // lógica semelhante, mas sem recompensa; também reseta interface e mata o monstro
}

Implementação em Unreal Engine 5

Implemente como um componente de interação com um actor "Veia de Minério" e um sistema de loot replicado.

  1. Modele FMiningStage (Stage, DamageCost, ItemRate, RewardId/Count) em um DataTable.
  2. Crie um AResourceNode derivado de AActor com variáveis CurrentStage, OwnerPlayer e RemainingLife.
  3. Adicione um componente UInteractionComponent que chama um Server RPC para iniciar mineração; valide jogador único, mapa/nível correto e ferramenta equipada.
  4. Em caso de sucesso, desconte durabilidade da ferramenta (Item Component) e incremente estágio; se atingir o máximo, gere loot usando uma tabela de recompensas e GiveItem.
  5. Envie feedback ao cliente via Client RPC (HUD de progresso). Em falha, apenas desconte durabilidade e reset, similar ao código legado.
  6. Opcional: registrar eventos no Node.js via VaRest (/api/mining/log) com account, stage e reward, gravando no SQL.
