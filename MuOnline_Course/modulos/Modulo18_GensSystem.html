Módulo 18 – Sistema Gens (Facções e Contribuição)

Mapeamos o fluxo completo do sistema Gens no GameServer e na UI do cliente, cobrindo cálculo de símbolos, interação com NPCs Duprian/Varnert, atualização de contribuição em mortes e exibição de ranking. Em seguida mostramos como replicar o comportamento em UE5 usando componentes de facção, replicação e VaRest/Node.js/SQL.

Pré-requisitos

  • Concluir os módulos 4, 5 e 11 para ter base de combate, inventário e party/social.
  • Conhecer replicação em UE5 (APlayerState, AGameStateBase) e uso de UActorComponent.
  • Ter o stack Node.js + SQL configurado (ver Módulo 9) e VaRest instalado no cliente UE5.

Conceitos do Código Original

CGensSystem::CalcGensMemberInfo – Ranking e Símbolos
📘 O Que é?

Função que calcula o símbolo e o próximo requisito de contribuição para um membro Gens com base no rank e pontos atuais.

void CGensSystem::CalcGensMemberInfo(LPOBJ lpObj)
{
    if(lpObj->GensFamily == 0) { return; }
    if(lpObj->GensContribution >= 10000) {
        if(lpObj->GensRank == 1) { lpObj->GensSymbol = 1; }
        else if(lpObj->GensRank >= 2 && lpObj->GensRank <= 5) { lpObj->GensSymbol = 2; }
        ...
    } else {
        if(lpObj->GensContribution >= 0 && lpObj->GensContribution <= 499) { lpObj->GensSymbol = 14; }
        ...
    }
    lpObj->GensNextContribution = gGensSystemContributionTable[(lpObj->GensSymbol-1)];
}

🎯 Para Que Serve?

Define visual e progressão do jogador em uma das facções Gens, calculando o símbolo exibido na UI e o próximo patamar de contribuição.

💻 Como Funciona?

Avalia primeiro se o jogador pertence a alguma família. Compara contribuição e rank para atribuir símbolos de 1 a 9 (alta contribuição) ou 10 a 14 (faixas iniciais). Em seguida lê a tabela gGensSystemContributionTable para armazenar o requisito do próximo nível.

if(lpObj->GensContribution >= 10000) {
    if(lpObj->GensRank == 1) { lpObj->GensSymbol = 1; }
    ...
} else {
    if(lpObj->GensContribution >= 6000 && lpObj->GensContribution <= 9999) {
        lpObj->GensSymbol = 10;
    }
}

⏱️ Quando é Executado?

Invocado sempre que a contribuição ou rank mudam (por exemplo, ao sincronizar com o DataServer ou após mortes). A chamada de envio ocorre via CGensSystem::GDGensSystemUpdateSend depois de UserDieProc ajustar os pontos.

CGensSystem::NpcGensDuprianSteward / Varnert – Diálogo e Interface
📘 O Que é?

Handlers que inicializam a interface de interação com os NPCs de cada família, preenchendo contribuição atual e disparando um pacote 0xF9 0x01.

lpObj->Interface.use = 1;
lpObj->Interface.type = INTERFACE_QUEST_WORLD;
pMsg.header.set(0xF9,0x01,sizeof(pMsg));
pMsg.MonsterClass = lpNpc->Class;
pMsg.contribution = (lpObj->GensFamily == GENS_FAMILY_VARNERT)
    ? lpObj->GensContribution : 0;
DataSend(lpObj->Index,(BYTE*)&pMsg,pMsg.header.size);

🎯 Para Que Serve?

Abre a UI de adesão/consulta Gens para o jogador, diferenciando Duprian e Varnert e mostrando a contribuição atual somente se o jogador pertence à mesma família.

💻 Como Funciona?

Habilita a interface do tipo INTERFACE_QUEST_WORLD, salva a classe do NPC para verificar o altar mais tarde e envia o pacote 0xF9/0x01 com classe do NPC e contribuição válida. O valor de contribuição é zerado quando a família não coincide.

if(lpObj->GensFamily == GENS_FAMILY_DUPRIAN) {
    pMsg.contribution = lpObj->GensContribution;
} else {
    pMsg.contribution = 0;
}
DataSend(lpObj->Index,(BYTE*)&pMsg,pMsg.header.size);

CGensSystem::UserDieProc / CheckGens – Contribuição por Mortes
📘 O Que é?

Rotina que ajusta contribuição de Gens após PvP válido em mapas de batalha, verificando flood de vítimas e níveis para aplicar bônus e penalidades.

if(this->CheckGens(lpObj,lpTarget) == 0) { return; }
if(this->VerifyGensVictimList(lpObj,lpTarget) == 0) { return; }
int ContributionIncrease = gServerInfo.m_GensSystemKillerContributionIncrease;
int ContributionDecrease = gServerInfo.m_GensSystemVictimContributionDecrease;
...
lpObj->GensContribution -= ContributionDecrease;
this->GDGensSystemUpdateSend(lpObj->Index);
ContributionIncrease = ((ContributionIncrease>gServerInfo.m_GensSystemKillerMaxContributionIncrease)?...);
lpTarget->GensContribution += ContributionIncrease;
this->GDGensSystemUpdateSend(lpTarget->Index);

🎯 Para Que Serve?

Garante que apenas mortes entre famílias rivais, em mapas permitidos e sem flood de kills, modifiquem a contribuição. Aplica limites de ganho/perda conforme configuração do servidor.

💻 Como Funciona?

Primeiro valida tipos (somente usuários) e mapas com gMapManager.GetMapGensBattle; depois bloqueia se famílias são iguais. A lista de vítimas evita contagem excessiva em curto intervalo. Ajusta contribuição de acordo com diferença de nível e símbolo, clampa aos limites configurados e envia atualização ao DataServer.

if(gMapManager.GetMapGensBattle(lpObj->Map) == 0) { return 0; }
if(lpObj->GensFamily != lpTarget->GensFamily) { return 1; }
...
lpObj->GensContribution -= ContributionDecrease;
GDGensSystemUpdateSend(lpObj->Index);
lpTarget->GensContribution += ContributionIncrease;
GDGensSystemUpdateSend(lpTarget->Index);

Implementação em Unreal Engine 5

Para recriar o sistema Gens em UE5, mapeie:

  • Símbolos/Rank: use APlayerState com UPROPERTY(Replicated) para família, contribuição, símbolo e rank.
  • Lógica de contribuição: coloque em um UActorComponent anexado ao APlayerState ou APlayerController para rodar no servidor.
  • UI: crie um UUserWidget (UMG) que consome os campos replicados e recebe atualizações via eventos.
  • Persistência: exponha endpoints REST em Node.js (por exemplo, POST /gens/update, GET /gens/rank) e chame-os do cliente com VaRest.

Exemplo de componente de facção

UCLASS(ClassGroup=(Custom), meta=(BlueprintSpawnableComponent))
class UGensComponent : public UActorComponent
{
    GENERATED_BODY()
public:
    UPROPERTY(ReplicatedUsing=OnRep_Contribution) int32 Contribution = 0;
    UPROPERTY(Replicated) int32 Rank = 0;
    UPROPERTY(Replicated) int32 Symbol = 14;
    UPROPERTY(Replicated) uint8 Family = 0; // 0 none, 1 Duprian, 2 Varnert

    UFUNCTION(Server, Reliable)
    void ServerRegisterKill(APlayerState* Victim, const FGensConfig& Config);

protected:
    UFUNCTION() void OnRep_Contribution();
};

No método ServerRegisterKill, replique o cálculo de UserDieProc, usando curvas configuráveis (FGensConfig) para limites, e ao final:

  • Atualize os campos replicados e chame um endpoint VaRest para persistir no SQL via Node.js.
  • Dispare um Multicast para atualizar UI dos clientes próximos.

UI de Ranking em UMG

Monte um widget com barra de rolagem e textos ligados a propriedades do APlayerState. Use um UDataTable ou DataAsset para armazenar thresholds de símbolo equivalentes a CalcGensMemberInfo. Exemplo de binding:

int32 UMG_GensPanel::ComputeSymbol(int32 Contribution, int32 Rank) const
{
    if(Contribution >= 10000) {
        if(Rank == 1) return 1;
        if(Rank >=2 && Rank <=5) return 2;
        ...
    } else if(Contribution >= 6000) { return 10; }
    return 14;
}

Chamadas REST (VaRest + Node.js + SQL)

  1. No servidor Node.js, exponha POST /gens/kill para registrar ganho/perda de contribuição com validações de mapa/família (replicando CheckGens).
  2. No cliente UE5, ao confirmar um kill válido no servidor de jogo, envie UVaRestRequestJSON com killerId, victimId, mapId, symbol e receba os novos valores para replicar.
  3. Salve rankings em tabela SQL gens_ranking com índices por família e rank.

Passo a Passo em Unreal Engine 5

  1. Crie um APlayerState customizado com campos Family, Contribution, Rank e Symbol (replicados).
  2. Implemente um UGensComponent no servidor que valida mapas permitidos (use um DataAsset com IDs de mapa de batalha) e chama ServerRegisterKill quando um dano letal é aplicado.
  3. Implemente uma função de cálculo de símbolo/thresholds espelhando CalcGensMemberInfo e aplique sempre que Contribution ou Rank mudarem.
  4. Monte endpoints Node.js: /gens/register (adesão), /gens/kill (atualização), /gens/ranking (consulta). Cada um grava/retorna dados SQL.
  5. No cliente UE5, adicione um Widget "GensRanking" com barra de rolagem e marque o símbolo por família; popule com dados recebidos de /gens/ranking via VaRest.
  6. Para NPCs, crie AActor interativo (Duprian/Varnert) que abre um widget de confirmação e chama /gens/register; ao sucesso, define a família e ressincroniza contribuição.
  7. Teste em mapa de batalha replicado: mate um jogador da outra família, verifique ajuste de contribuição e símbolo, persista no SQL e exiba na UI.

Checklist Final

  • PlayerState replica família, contribuição, símbolo e rank corretamente.
  • Kills entre famílias rivais em mapas habilitados ajustam contribuição conforme regras.
  • NPCs de facção abrem UI e registram adesão via VaRest/Node.js/SQL.
  • Widget de ranking exibe símbolo, título e lista com dados vindos do backend.
  • Dados persistem no banco e recarregam ao reconectar.

Guia Blueprint ultra detalhado (iniciante)

Como refazer o sistema Gens passo a passo com Blueprints, VaRest e SQL.

1) UI e posicionamento

  • WBP_GensHUD (1920x1080):
    • Banner superior (X=40, Y=30, W=420, H=90) com símbolo à esquerda (64x64) e texto de família/rank à direita.
    • Painel de contribuição (X=40, Y=140, W=420, H=160) com barra de progresso (W=380, H=22) e label "Contribution: 00000".
    • Botão "Ranking" (X=40, Y=320, W=180, H=48) abre modal WBP_GensRanking.
  • WBP_GensRanking (800x620): cabeçalho com filtros (família/tier) e ScrollBox preenchido por WBP_GensRow (linha 64px: símbolo 48x48, nome, contribuição, rank).

2) PlayerState e Componentes

  1. Crie BP_PS_Gens (deriva de PlayerState) com variáveis replicadas: Family (Enum: Duprian/Varnert), Contribution (int), Rank (int), SymbolTexture (SoftObject).
  2. No Character, adicione componente BP_GensComponent com função ServerRegisterKill(VictimFamily, KillerFamily) (Server, Reliable) e ApplyContributionDelta (Authority).
  3. Event BeginPlay (client): cria WBP_GensHUD e associa bindings a OnRep das variáveis do PlayerState.

3) NPC de adesão

  • Actor BP_GensNPC com Box Collision (150x150) e TextRender "Join Gens". OnOverlap → mostra Press E em um widget flutuante.
  • Input E (client): abre WBP_GensJoin com dois botões (Duprian, Varnert) e aviso de requisito de nível.
  • Ao clicar, chama RequestJoinFamily(Family) (veja VaRest) e, em sucesso, seta Family no PlayerState, carrega textura do símbolo e fecha UI.

4) VaRest + SQL

  • Endpoints:
    • POST /gens/register → body {account, family} → grava em gens_members (family, contribution, rank, symbol).
    • POST /gens/kill → body {killerAccount, victimAccount} → atualiza contribuição e devolve {delta, newContribution, rank}.
    • GET /gens/ranking?family=Duprian → retorna lista ordenada para o widget.
  • No BP_GensComponent (Authority): quando ServerRegisterKill é chamado, dispara VaRest POST /gens/kill; no retorno, chama ApplyContributionDelta e replica Contribution/Rank.
  • No WBP_GensRanking, OnConstruct chama VaRest GET ranking e preenche o ScrollBox criando linhas dinâmicas.

5) Debug e validação

  • Console command gens.debug mostra widget com valores atuais e último delta recebido.
  • Ative Print String no client quando OnRep_Contribution disparar para confirmar replicação.
  • Checklist do aluno: falar com NPC, escolher família, ver símbolo no HUD, matar rival em mapa permitido e ver contribuição/ ranking atualizar na UI e no backend.
