Módulo 39 – Sistema de Casamento

Explora o MarrySystem do GameServer: leitura de script, envio de informações ao cliente, proposta/aceite e validações de posição/sexo. Inclui mapeamento completo para UE5 com UI, replicação e backend via VaRest/Node.js/SQL.

Pré-requisitos

  • Módulo 6 – Eventos e Timers.
  • Módulo 13 – MiniMapa (para trabalhar com coordenadas).
  • Conhecimento de UUserWidget e RPCs em UE5.

Conceitos do Código Original

LoadData – Configuração do casamento via script
📘 O Que é?

Rotina que lê um arquivo de script para habilitar/desabilitar o sistema, definir mapa/tempo máximo, coordenadas de proposta/aceite e custos de divórcio.

🎯 Para Que Serve?

Centraliza parâmetros ajustáveis sem recompilar, permitindo configurar mapa permitido, posições exatas e custos.

💻 Como Funciona?

Usa CMemScript para percorrer seções numeradas e popular os campos do sistema.

this->Enabled = FALSE;
if(lpMemScript->SetBuffer(FilePath) == 0) { ErrorMessageBox(...); return; }
while(true) {
  if(lpMemScript->GetToken() == TOKEN_END) break;
  int section = lpMemScript->GetNumber();
  if(section == 0) { this->Enabled = lpMemScript->GetNumber(); this->MarryMap = lpMemScript->GetAsNumber(); ... }
  else if(section == 1) { this->ProposeX = lpMemScript->GetNumber(); this->ProposeY = lpMemScript->GetAsNumber(); ... }
  else if(section == 2) { this->CostDivorce = lpMemScript->GetNumber(); ... }
  else if(section == 3) { int Level = lpMemScript->GetNumber(); this->MapIndex[Level] = lpMemScript->GetAsNumber(); }
}

SendInfo – Envio de custos e coordenadas ao cliente
📘 O Que é?

Mensagem enviada ao cliente com nome do parceiro, custos de divórcio e posições de proposta/aceite.

🎯 Para Que Serve?

Atualiza a UI do cliente com dados atuais do casamento e restrições de posição.

💻 Como Funciona?

Preenche SDHP_RECV_MARRY com custos, mapa e coordenadas e envia com DataSend.

SDHP_RECV_MARRY lpInfo; PHeadSubSetB((LPBYTE)&lpInfo,0xFA,0x10,sizeof(lpInfo));
memcpy(lpInfo.Name,lpObj->MarryCharacterInfo.MarriedName,sizeof(lpInfo.Name));
lpInfo.CostDivorce = this->CostDivorce; lpInfo.MAP = this->MarryMap;
lpInfo.ProposeX = this->ProposeX; lpInfo.AcceptY = this->AcceptY;
DataSend(lpObj->Index,(LPBYTE)&lpInfo,sizeof(lpInfo));

Propose – Validações de gênero, posição e timers
📘 O Que é?

Fluxo de proposta de casamento: verifica se ambos estão solteiros, no mapa/posições corretas e de gênero diferente.

🎯 Para Que Serve?

Evita casamentos inválidos e inicia o temporizador de resposta do alvo.

💻 Como Funciona?

Obtém o alvo por nome, verifica status e posições (GetPos), compara sexos e inicia contadores/avisos.

int lpTargetID = gObjGetIndex(Wife);
if(lpObj->MarryCharacterInfo.Married == 1) { gNotice.NewNoticeSend(...); return; }
if(this->GetPos(lpObj) > 0 && this->GetPos(&gObj[lpTargetID]) > 0) {
  if(lpObjSex != lpTargetSex) {
    lpObj->MarryCharacterInfo.MarrySeconds = 0;
    gObj[lpTargetID].MarryCharacterInfo.MarrySeconds = this->MarryMaxTime;
    gNotice.NewNoticeSend(gObj[lpTargetID].Index,0,0,0,0,0,"[Propose] Accept marry with %s?",lpObj->Name);
  }
}

Implementação em Unreal Engine 5

  1. Defina um AGameModeBase com um UDataTable de configuração (mapa, coordenadas, custos) carregado no BeginPlay.
  2. Crie um UUserWidget para exibir status/custos e botões de propor/aceitar; vincule a um APlayerController com RPCs Server/Client.
  3. No servidor UE5, implemente funções ServerPropose e ServerAccept que validam mapa/posição (GetActorLocation()) e sexos (campo no APlayerState), replicando a lógica original.
  4. Persistência: use VaRest para gravar o estado de casamento em Node.js + SQL (/marry/propose, /marry/accept, /marry/status). Sincronize no login chamando o endpoint e popular o widget.
  5. Implemente timers (FTimerManager) para expirar propostas após MarryMaxTime, enviando notificações replicadas.

Passo a Passo em Unreal Engine 5

  1. Criar USTRUCT FMarryConfig e carregar de DataTable com mapa/posições/custos.
  2. No login, chamar endpoint Node.js para obter status atual e preencher APlayerState (nome do parceiro, tempo restante).
  3. Adicionar widget de casamento ao viewport com botões que disparam ServerPropose/ServerAccept (RPCs confiáveis).
  4. Validar posições no servidor UE5 comparando FVector com tolerância em relação a ProposeX/Y e AcceptX/Y.
  5. Persistir aceite/divórcio via VaRest em endpoints SQL e atualizar todos os clientes por multicast.

Guia detalhado para iniciantes

  1. DataTable: crie Content/Data/Marry_Config.csv com colunas Map, ProposeX, ProposeY, AcceptX, AcceptY, CostZen, GiftItemID. Importe como DataTable de FMarryConfig.
  2. Componentes: adicione BP_MarryComponent ao PlayerState. Variáveis replicadas: PartnerName (String), IsMarried (bool), PendingProposalFrom (String), ProposalExpireAt (float).
  3. UI: crie WBP_Marry com painel 400×260 ancorado topo-esquerda (Offset 30,120). Botões “Propor” e “Aceitar”, texto de status e contador regressivo. Bindings: texto de parceiro mostra PartnerName; contador usa ProposalExpireAt - GetGameTime.
  4. Fluxo de proposta: botão “Propor” chama ServerPropose(TargetPlayerState). No servidor: valide sexo/mapa/posições comparando GetActorLocation com ProposeX/Y do DataTable; se ok, set PendingProposalFrom no alvo e ProposalExpireAt = Now + MarryMaxTime; use ClientReceiveProposal para abrir UI no alvo.
  5. Aceite: botão “Aceitar” no alvo chama ServerAccept. Servidor valida expirado, custo Zen (checar inventário), grava via VaRest POST /marry/accept ({accountA, accountB, map, pos}). Em caso de sucesso, set IsMarried=true em ambos e sincronize por MulticastUpdateMarriage.
  6. Persistência: no login, chame GET /marry/status/{account} via VaRest; atualize PartnerName/IsMarried. Em divórcio, botão “Divorciar” chama /marry/divorce e limpa campos.
  7. Testes: abra 2 clientes PIE + servidor. Posicione ambos nas coordenadas do DataTable (use Teleport na barra de comandos). Clique “Propor” no cliente A, aceite no B antes do timer expirar; confirme que UI mostra parceiro e que o endpoint recebeu a escrita SQL. Depois teste expiração deixando o timer acabar.

Checklist Final

  • Configurações de mapa/posições/custos carregadas de tabela.
  • UI mostra parceiro, custos e tempo restante; botões replicam proposta/aceite.
  • Validação de posição/sexo espelha o servidor legado.
  • Estado persistente gravado em Node.js/SQL e sincronizado via VaRest.

Guia passo a passo para principiantes

  1. Preparar UI: em WBP_Marry, posicione rótulos: “Parceiro”, “Custo Zen”, “Mapa permitido” alinhados à esquerda, com valores à direita. Use fonte 14, cor branca, sombra preta para leitura.
  2. Painéis visuais: adicione um quadro vermelho “Requisitos não atendidos” (visibilidade colapsada) e quadro verde “Pronto para casar”. Troque visibilidade quando qualquer validação falhar (mapa errado, sexo igual, distância > 150 unidades das coordenadas).
  3. Botão Propor: no evento OnClicked, monte sequência: Get Player Under Crosshair → Cast to PlayerState → ServerPropose. Antes de chamar, valide localmente Zen >= custo e distância usando Vector Length entre GetActorLocation e vetor (ProposeX, ProposeY, Z do chão).
  4. Botão Aceitar: exiba somente se PendingProposalFrom não vazio. No clique, chame ServerAccept. Se retornar sucesso (RPC client), feche quadro vermelho, abra quadro verde e mostre texto “Casados: <Parceiro>”.
  5. Sequência VaRest: crie função Blueprint SaveMarriage → VaRest Make JSON com accountA, accountB, map, pos, timestamp → POST /marry/accept. No sucesso, chame RefreshStatus (GET) para garantir dados sincronizados.
  6. Teleporte rápido para teste: adicione no GameMode um comando ce marry_tp que faz Teleport do personagem para as coordenadas (ProposeX, ProposeY) da tabela, garantindo que iniciantes consigam alinhar posição.
  7. Checklist visual: crie um widget lateral WBP_MarryChecklist com checkboxes “Mapa correto”, “Distância <=150”, “Parceiros sexos diferentes”, “Zen suficiente”, “Timer ativo”. Cada checkbox usa Set Is Checked conforme validações locais para guiar o aluno.
  8. Cenário de erro: force falta de Zen (set 0) e clique Propor. Mostre toast “Sem Zen” e mantenha quadro vermelho visível. Em seguida, adicione Zen via console ce addzen 1000000 e repita para demonstrar recuperação.
