CInvasionManager::Load – Script de horários, mensagens e grupos
📘 O Que é?

Leitura de um script dividido em seções para horários, mensagens, grupos de respawn e monstros de cada invasão.

void CInvasionManager::Load(char* path) {
  CMemScript* lpMemScript = new CMemScript;
  if(lpMemScript->SetBuffer(path) == 0) { ErrorMessageBox(lpMemScript->GetLastError()); return; }
  for(int n=0;n < MAX_INVASION;n++) { m_InvasionInfo[n].RespawnMessage = -1; ... m_InvasionInfo[n].MonsterInfo.clear(); }
  while(true) {
    if(lpMemScript->GetToken() == TOKEN_END) break;
    int section = lpMemScript->GetNumber();
    while(true) {
      if(section == 0) { /* horários */ INVASION_START_TIME info; int index = lpMemScript->GetNumber(); info.Year = lpMemScript->GetAsNumber(); ... info.Second = lpMemScript->GetAsNumber(); m_InvasionInfo[index].StartTime.push_back(info); }
      else if(section == 1) { int index = lpMemScript->GetNumber(); m_InvasionInfo[index].RespawnMessage = lpMemScript->GetAsNumber(); m_InvasionInfo[index].DespawnMessage = lpMemScript->GetAsNumber(); m_InvasionInfo[index].BossIndex = lpMemScript->GetAsNumber(); m_InvasionInfo[index].BossMessage = lpMemScript->GetAsNumber(); m_InvasionInfo[index].InvasionTime = lpMemScript->GetAsNumber(); }
      else if(section == 2) { INVASION_RESPWAN_INFO info; int index = lpMemScript->GetNumber(); info.Group = lpMemScript->GetAsNumber(); info.Map = lpMemScript->GetAsNumber(); info.Value = lpMemScript->GetAsNumber(); m_InvasionInfo[index].RespawnInfo[info.Group].push_back(info); }
      else if(section == 3) { INVASION_MONSTER_INFO info; int index = lpMemScript->GetNumber(); info.Group = lpMemScript->GetAsNumber(); info.MonsterClass = lpMemScript->GetAsNumber(); info.RegenType = lpMemScript->GetAsNumber(); info.RegenTime = lpMemScript->GetAsNumber(); m_InvasionInfo[index].MonsterInfo.push_back(info); }
      else { break; }
    }
  }
}

🎯 Para Que Serve?

Carrega toda a configuração de cada invasão (horário, mensagens, boss, grupos, monstros e tempos de regen) para ser usada pelo loop principal.

💻 Como Funciona?

Inicializa arrays, limpa vetores e percorre seções numeradas do script; cada seção popula estruturas específicas que serão lidas pelo agendador e pelo spawn.

// Exemplo de preenchimento de horários
if(section == 0) {
  INVASION_START_TIME info; int index = lpMemScript->GetNumber();
  info.Hour = lpMemScript->GetAsNumber(); info.Minute = lpMemScript->GetAsNumber(); info.Second = lpMemScript->GetAsNumber();
  m_InvasionInfo[index].StartTime.push_back(info);
}

MainProc/SetState – Agendamento, avisos e troca de estado
📘 O Que é?

Loop por invasão que atualiza timers, envia avisos e alterna entre EMPTY/START com base no relógio.

void CInvasionManager::MainProc() {
  for(int n=0;n < MAX_INVASION;n++) {
    INVASION_INFO* lpInfo = &m_InvasionInfo[n];
    DWORD elapsed = GetTickCount()-lpInfo->TickCount; if(elapsed < 1000) continue;
    if(lpInfo->State == INVASION_STATE_BLANK) { if (gServerDisplayer.EventInvasion[n] != -1) gServerDisplayer.EventInvasion[n] = -1; }
    else { if (lpInfo->State == INVASION_STATE_EMPTY) { gServerDisplayer.EventInvasion[n] = lpInfo->RemainTime; } else { if (gServerDisplayer.EventInvasion[n] != 0) gServerDisplayer.EventInvasion[n] = 0; } }
    lpInfo->TickCount = GetTickCount();
    lpInfo->RemainTime = (int)difftime(lpInfo->TargetTime,time(0));
    switch(lpInfo->State) { case INVASION_STATE_EMPTY: ProcState_EMPTY(lpInfo); break; case INVASION_STATE_START: ProcState_START(lpInfo); break; }
  }
}
void CInvasionManager::ProcState_EMPTY(INVASION_INFO* lpInfo) {
  if(lpInfo->RemainTime <= 0) { if(lpInfo->RespawnMessage != -1) gNotice.GCNoticeSendToAll(...,gMessage.GetMessage(lpInfo->RespawnMessage)); SetState(lpInfo,INVASION_STATE_START); }
}
void CInvasionManager::ProcState_START(INVASION_INFO* lpInfo) {
  if(lpInfo->RemainTime <= 0) { if(lpInfo->DespawnMessage != -1) gNotice.GCNoticeSendToAll(...,gMessage.GetMessage(lpInfo->DespawnMessage)); SetState(lpInfo,INVASION_STATE_EMPTY); }
}

🎯 Para Que Serve?

Coordena o ciclo do evento: agenda próximo horário, anuncia início e fim e mantém o painel do servidor atualizado.

💻 Como Funciona?

Usa RemainTime e TargetTime para decidir quando enviar avisos. CheckSync calcula o próximo horário e SetState_START faz o spawn.

void CInvasionManager::CheckSync(INVASION_INFO* lpInfo) {
  if(lpInfo->StartTime.empty()!=0) { SetState(lpInfo,INVASION_STATE_BLANK); return; }
  CScheduleManager ScheduleManager; for(auto it: lpInfo->StartTime) { ScheduleManager.AddSchedule(...); }
  if(ScheduleManager.GetSchedule(&ScheduleTime)==0) { SetState(lpInfo,INVASION_STATE_BLANK); return; }
  lpInfo->RemainTime = (int)difftime(ScheduleTime.GetTime(),time(0)); lpInfo->TargetTime = (int)ScheduleTime.GetTime();
}

SetState_START/SetMonster – Spawn por grupo e marcação de boss
📘 O Que é?

Seleciona um grupo de respawn, instancia monstros, define MaxRegenTime e registra o boss para avisos.

void CInvasionManager::SetState_START(INVASION_INFO* lpInfo) {
  for(int n=0;n < MAX_INVASION_RESPAWN_GROUP;n++) {
    if(lpInfo->RespawnInfo[n].empty()==0) {
      INVASION_RESPWAN_INFO* lpRespawnInfo = &lpInfo->RespawnInfo[n][(GetLargeRand()%lpInfo->RespawnInfo[n].size())];
      for(auto it=lpInfo->MonsterInfo.begin(); it!=lpInfo->MonsterInfo.end(); it++) {
        if(it->Group == lpRespawnInfo->Group) { SetMonster(lpInfo,lpRespawnInfo,&(*it)); }
      }
    }
  }
  lpInfo->RemainTime = lpInfo->InvasionTime; lpInfo->TargetTime = (int)(time(0)+lpInfo->RemainTime);
}
void CInvasionManager::SetMonster(INVASION_INFO* lpInfo,INVASION_RESPWAN_INFO* lpRespawnInfo,INVASION_MONSTER_INFO* lpMonsterInfo) {
  for(int n=0;n < gMonsterSetBase.m_count;n++) {
    MONSTER_SET_BASE_INFO* lpMsbInfo = &gMonsterSetBase.m_MonsterSetBaseInfo[n];
    if(lpMsbInfo->Type != 3 || lpMsbInfo->MonsterClass != lpMonsterInfo->MonsterClass || lpMsbInfo->Map != lpRespawnInfo->Map || lpMsbInfo->Value != lpRespawnInfo->Value) continue;
    int index = gObjAddMonster(lpMsbInfo->Map); if(OBJECT_RANGE(index)==0) continue;
    if(gObjSetPosMonster(index,n)==0 || gObjSetMonster(index,lpMsbInfo->MonsterClass)==0) { gObjDel(index); continue; }
    lpObj->MaxRegenTime = ((lpMonsterInfo->RegenType==0)?(lpInfo->InvasionTime*1000):lpMonsterInfo->RegenTime);
    if(lpObj->Class == lpInfo->BossIndex && lpInfo->BossMessage != -1) { LogAdd(LOG_EVENT,"[Invasion Manager] Index(%d) Boss Position (Map: %d X: %d Y: %d)",lpInfo->Index,lpObj->Map,lpObj->X,lpObj->Y); }
    if(this->AddMonster(lpInfo,index) == 0) { gObjDel(index); }
  }
}

🎯 Para Que Serve?

Garante que cada invasão usa um grupo aleatório válido, preenche slots de tracking e registra coordenadas do boss para avisos e monitoramento.

💻 Como Funciona?

Itera os grupos e, para cada respawn escolhido, percorre MonsterInfo; cria monstros com gObjAddMonster, aplica posição de script e guarda índices para limpeza posterior.

Implementação em Unreal Engine 5

Mapeie o CInvasionManager para um UInvasionSubsystem (UWorldSubsystem) ou um AGameState especializado que gerencie datas, timers e spawn de AActors.

  1. Crie uma USTRUCT FInvasionSchedule com campos de data/hora e um FInvasionMonsterGroup com grupo, mapa (Level/WorldPartition) e classe de inimigo.
  2. Carregue um DataTable (CSV/JSON) equivalente ao script lido em Load e converta para arrays em InitializeSubsystem.
  3. Implemente um timer (GetWorld()->GetTimerManager()) que chama TickInvasions a cada segundo, replicando a lógica de MainProc (controle de estado e avisos).
  4. Quando o estado mudar para START, selecione um grupo aleatório e use UWorld::SpawnActorDeferred para instanciar os inimigos. Salve os TWeakObjectPtr em um array para limpeza.
  5. Para avisos globais, use um AGameState replicado e notifique os clientes via Multicast ou GameplayMessageSubsystem.
  6. Se usar VaRest + Node.js + SQL para telemetria, poste o horário da invasão e mortes de boss para um endpoint HTTP assíncrono; armazene em tabela invasions_log com data, mapa, bossClass e vencedor.
// Exemplo de subsystem UE5
USTRUCT(BlueprintType)
struct FInvasionMonsterGroup { GENERATED_BODY(); UPROPERTY(EditAnywhere) int32 GroupId; UPROPERTY(EditAnywhere) TSoftClassPtr MonsterClass; UPROPERTY(EditAnywhere) int32 Count; };

UCLASS()
class UInvasionSubsystem : public UWorldSubsystem {
  GENERATED_BODY()
public:
  virtual void Initialize(FSubsystemCollectionBase& Collection) override { LoadDataTable(); ScheduleNext(); GetWorld()->GetTimerManager().SetTimer(TickHandle,this,&UInvasionSubsystem::TickInvasions,1.0f,true); }
  void TickInvasions();
  void SpawnGroup(const FInvasionMonsterGroup& Group);
private:
  void ScheduleNext();
  TArray Schedules; TArray Groups; FDateTime TargetTime; int32 State; TArray> Spawned;
};

Passo a Passo em Unreal Engine 5

  1. Crie um Plugin ou módulo C++ com UInvasionSubsystem e structs para horário e grupos.
  2. Importe um CSV que replique as seções 0-3 do script e converta para DataTable no Editor.
  3. No Initialize, leia o DataTable, defina State = Empty e compute TargetTime com FDateTime.
  4. Implemente TickInvasions para: (a) decrementar tempo restante, (b) quando chegar a zero e em EMPTY, disparar multicast de aviso e chamar SpawnGroup; (c) quando em START e tempo expirar, destruir atores e voltar para EMPTY.
  5. Em SpawnGroup, escolha um grupo compatível com o mapa atual e chame SpawnActorDeferred para cada instância; armazene em um array para limpeza.
  6. Crie um UUserWidget replicado com HUD de countdown usando dados do GameState e gatilhos de aviso.
  7. Integre VaRest para registrar início/fim em um endpoint Node.js (rotas /api/invasions/start e /api/invasions/end) salvando no SQL o mapa, horário e jogador que matou o boss.

Checklist Final

  • DataTable com horários, mensagens, grupos e monstros carregada em runtime.
  • HUD mostra countdown da próxima invasão e esconde durante START.
  • Spawns surgem no mapa correto e limpam ao fim ou ao reiniciar o estado.
  • Avisos globais de início/fim e de morte do boss replicados para todos os clientes.
  • Logs HTTP gravados via VaRest/Node.js em tabela SQL com histórico das invasões.

Guia Blueprint minucioso (iniciante)

  1. DataTables e assets
    • Monte DT_InvasionTime (Index, Year, Month, Day, Hour, Minute, Second) e DT_InvasionGroup (Index, Group, Map, Value, MonsterId, Count, X, Y).
    • DataAsset DA_InvasionMessages com RespawnMessage, DespawnMessage, BossMessage, InvasionTime.
  2. Orquestração em Blueprint
    • No GameState, crie componente BP_InvasionManager com variáveis NextStartTime, CurrentIndex e arrays de grupos.
    • No BeginPlay, leia as tabelas e chame ScheduleNext (diferencial usando Now → NextTime e SetTimer by Event).
  3. Spawns e tracking
    • Evento StartInvasion: para cada linha de DT_InvasionGroup do índice, use SpawnActor do monstro (Location = (X*100, Y*100, 120)).
    • Guarde referências em ActiveMonsters; no OnDestroyed, faça ActiveCount--; quando chegar a zero, chame EndInvasion.
  4. UI e avisos
    • Widget W_InvasionBanner top-center (X=640, Y=32, 480×64) com texto animado. Crie Timeline piscando a borda quando boss spawna.
    • Contador no W_Countdown (TextBlock X=900, Y=32) atualizado por timer de 1s; quando zero, troca para “Invasão ativa”.
    • Som de alerta SoundCue_Alarm tocado via Play Sound 2D em todos os clientes (Multicast).
  5. Mapa de arquivos e posicionamento 1:1:
    • /Game/UI/Events/Invasions/W_InvasionBanner (Canvas 1920x1080) âncora topo-centro com Border 480x64 em X=640, Y=32 e TextBlock Txt_Message centralizado.
    • /Game/UI/Events/Invasions/W_Countdown TextBlock 220x48 em X=900, Y=32, fonte 28, cor amarela; alimentado por binding GetRemainingText.
    • /Game/UI/Events/Invasions/W_DebugStatus (opcional) 420x60 em X=24, Y=700 com três TextBlocks (HTTP, Spawn, Timer) alinhados verticalmente.
  6. Persistência VaRest/SQL
    • Start: VaRest POST /invasion/start {index,map,startTime}. Progress: a cada 60s POST /invasion/progress {index, aliveCount}. End: POST /invasion/end {index, duration, bossKiller}.
    • Exiba status de rede em widget de debug (X=24, Y=700) mudando cor Verde/Amarelo/Vermelho conforme HTTP 200/429/500.
  7. Checklist visual final
    • Banner e countdown sempre visíveis na HUD.
    • Spawns aparecem exatamente nas coordenadas do script.
    • Logs REST registrados e mostrados no painel de debug em tempo real.
