CGuild::GetMaxGuildUser – Cálculo de vagas
📘 O Que é?

Define quantos membros uma guild pode ter, considerando classe, resets e leadership.

int CGuild::GetMaxGuildUser(LPOBJ lpObj) {
  int MaxGuildUser = 0;
  if(lpObj->Class == CLASS_DL) {
    MaxGuildUser = ((lpObj->Reset==0)?(((lpObj->Level+lpObj->MasterLevel)/10)+(lpObj->Leadership/10)):gServerInfo.m_GuildInsertMaxUser2);
    MaxGuildUser = ((MaxGuildUser>gServerInfo.m_GuildInsertMaxUser2)?gServerInfo.m_GuildInsertMaxUser2:MaxGuildUser);
  } else {
    MaxGuildUser = ((lpObj->Reset==0)?((lpObj->Level+lpObj->MasterLevel)/10):gServerInfo.m_GuildInsertMaxUser1);
    MaxGuildUser = ((MaxGuildUser>gServerInfo.m_GuildInsertMaxUser1)?gServerInfo.m_GuildInsertMaxUser1:MaxGuildUser);
  }
  return ((MaxGuildUser>MAX_GUILD_USER)?MAX_GUILD_USER:MaxGuildUser);
}

🎯 Para Que Serve?

Limita o tamanho da guild conforme progressão do jogador e classe Dark Lord, prevenindo convites acima do limite configurado.

💻 Como Funciona?

Ajusta o limite base por reset; para DL soma leadership/10; faz clamp pelos valores máximos do ServerInfo; retorna o mínimo entre o clamp e MAX_GUILD_USER.

// Ajuste por configuração e clamp
MaxGuildUser = ((MaxGuildUser>gServerInfo.m_GuildInsertMaxUser1)?gServerInfo.m_GuildInsertMaxUser1:MaxGuildUser);
return ((MaxGuildUser>MAX_GUILD_USER)?MAX_GUILD_USER:MaxGuildUser);

⏱️ Quando é Executado?

Chamado durante o convite/aceite para validar capacidade:

if(lpTarget->Guild->TotalCount >= this->GetMaxGuildUser(lpTarget)) {
  this->GCGuildResultSend(aIndex,2);
  return;
}

CGGuildRequestRecv/ResultRecv – Convite e aceite
📘 O Que é?

Handlers de pacotes 0x50/0x51 que coordenam convite e resposta de guild.

🎯 Para Que Serve?

Controla o handshake entre convidar e aceitar, bloqueando interfaces em uso, guerra ativa ou conflito com Gens.

💻 Como Funciona?

// Convite (C1:50)
int bIndex = MAKE_NUMBERW(lpMsg->index[0],lpMsg->index[1]);
if((lpTarget->Option & 1) == 0 || lpTarget->GuildNumber == 0) { GCGuildResultSend(aIndex,0/4); return; }
... // locks e Gens
lpObj->Interface.use = 1; lpObj->Interface.type = INTERFACE_GUILD;
lpTarget->Interface.use = 1; lpTarget->Interface.type = INTERFACE_GUILD;
PMSG_GUILD_REQUEST_SEND pMsg; pMsg.header.set(0x50,sizeof(pMsg)); DataSend(bIndex,(BYTE*)&pMsg,pMsg.header.size);

// Aceite (C1:51)
if(lpMsg->result == 0) { GCGuildResultSend(bIndex,0); goto CLEAR_JUMP; }
... // checa liderança, guerra, nível, limite, família Gens
GDGuildMemberAdd(bIndex,lpObj->Guild->Name,lpTarget->Name);
CLEAR_JUMP:
// limpa interfaces
lpObj->Interface.use = 0; lpTarget->Interface.use = 0;

📁 Onde Encontrar?

Source MuServer Update 15/GameServer/GameServer/Guild.cpp, linhas 104-341.

⏱️ Quando é Executado?

É acionado quando o cliente envia 0x50 para convidar ou 0x51 para responder. O aceite dispara gravação no DataServer via GDGuildMemberAdd (linha 326) após todas as checagens.

CGGuildListRecv – Lista de membros e rival
📘 O Que é?

Envia a lista completa da guild (membros, status, rival) no pacote 0x52.

🎯 Para Que Serve?

Atualiza o cliente com presença online, status e rivalidade para exibir UI de guild.

💻 Como Funciona?

pMsg.header.set(0x52,0);
pMsg.TotalScore = lpObj->Guild->TotalScore;
GUILD_INFO_STRUCT* lpRivalGuild = gGuildClass.SearchGuild_Number(lpObj->Guild->GuildRival);
if(lpRivalGuild == 0) { memset(pMsg.RivalGuild,0,...); }
for(int n=0;n < MAX_GUILD_USER;n++) {
  if(lpObj->Guild->Use[n] == 0) continue;
  memcpy(info.name,lpObj->Guild->Names[n],sizeof(info.name));
  info.connected = (lpObj->Guild->Server[n] & 0x7F) | ((lpObj->Guild->Server[n]>=0)?0x80:0);
  memcpy(&send[size],&info,sizeof(info));
  pMsg.count++;
}
DataSend(aIndex,send,size);

Implementação em Unreal Engine 5

Estruture a lógica de guild em um GameMode ou GameState com componentes de dados replicados.

  1. Crie um UGuildInfoComponent (UActorComponent) anexado ao APlayerState contendo nome da guild, papel e ponteiros para o líder.
  2. Implemente um AGuildManager derivado de AInfo com UFUNCTION(Server) para SendInvite e AcceptInvite, armazenando PendingInvites e limites por classe.
  3. Use ENetRole e ReplicatedUsing para sincronizar lista de membros com o time de APlayerState; replique um TArray<FGuildMember> (USTRUCT).
  4. Adapte o lock de Gens em um UGameInstanceSubsystem que consulta backend Node.js/SQL via VaRest antes de autorizar o convite.
  5. Para guerras, crie um AGuildWarManager que dispara Multicast com placar e rivais, replicando no AGameStateBase.

Passo a Passo em Unreal Engine 5

  1. Adicionar ao projeto um AGuildManager com método int32 GetMaxMembers(const FGuildStats& Stats) replicando a lógica de level/reset/leadership.
  2. Criar endpoints REST em Node.js/SQL (/guild/invite, /guild/accept) para persistência; consumir no cliente com VaRest dentro de UGuildService.
  3. No APlayerController, mapear input para abrir UI de guild e chamar ServerSendInvite(TargetPlayer); exibir diálogos via UMG.
  4. Replicar lista de membros: UPROPERTY(ReplicatedUsing=OnRep_GuildMembers) TArray<FGuildMember> GuildMembers;; atualizar UI quando OnRep for chamado.
  5. Implementar guerra: ServerDeclareWar(OtherGuildId) registra no backend; MulticastUpdateWarState notifica todos os membros e agenda timers equivalentes aos estados de WarState.
  6. Checklist: convite bloqueia quando alvo está em UI/Trade; aceitar dispara gravação; lista de membros mostra online/offline e rival; guerra envia placar replicado.

Checklist Final

  • Limite de membros respeita level/reset/leadership como no servidor original.
  • Convite/aceite replica estados de interface e impede conflitos (trade, guerra, Gens).
  • Lista de guild mostra membros, status e rival replicados no cliente UE5.
  • Persistência de guild/uniões integrada a Node.js + SQL via VaRest.
  • Guerra de guild envia notificações e placar para todos os membros.

Tutorial Blueprint ultra detalhado (convite, lista e guerra)

  1. Crie pasta /Guild/. Adicione DataTable GuildConfig_DT com campos MaxBase, MaxDL, LeadershipDivisor, WarDurationSeconds, ScorePerKill. Isso replica GetMaxGuildUser.
  2. Blueprint BP_GuildManager (Actor replicado, colocado no nível persistente). Variáveis: Guilds (Map<int, FGuildData>), PendingInvites (Array<FGuildInvite>). Eventos RPC: ServerSendInvite(TargetPlayerId), ServerRespondInvite(InviteId, bAccept), ServerDeclareWar(GuildId). Todos chamam VaRest POST para /guild/invite, /guild/accept, /guild/war.
  3. FGuildData mínimo: GuildId, Name, LeaderName, Members (Array<FGuildMember>), RivalId. Marque Members como RepNotify para disparar atualização de UI.
  4. UI convite (Widget WBP_GuildInvite, 420x160, âncora centro): texto "{Leader} convidou você para {Guild}"; botões "Aceitar" e "Recusar" chamam ServerRespondInvite. Mostre temporizador regressivo 20s (ProgressBar width 360, Y=120).
  5. UI lista (Widget WBP_GuildWindow, 960x580):
    1. Lista lateral esquerda (240x540, X=18 Y=20) com nomes, nível e status (bolinha verde/vermelha).
    2. Painel central (460x540, X=270) mostrando rival atual e botões "Declarar Guerra" e "Sair da Guild".
    3. Painel direito (200x540, X=750) para logs recentes (scrollable) alimentado por VaRest GET /guild/logs?guildId=.
  6. Cálculo de vagas no Blueprint: função GetMaxMembersFor(PlayerState):
    1. Leia GuildConfig_DT.
    2. Se classe = DL → Max = clamp(((Level+MasterLevel)/10)+(Leadership/LeadershipDivisor), MaxDL); senão Max = clamp((Level+MasterLevel)/10, MaxBase).
    3. Retorne min(Max, 80).
  7. Guerra de guild passo a passo:
    1. Ao clicar "Declarar Guerra" → ServerDeclareWar(RivalId) → VaRest POST /guild/war → ao sucesso, set ActiveWar com timer WarDurationSeconds.
    2. Crie widget WBP_GuildWarHUD (500x120, âncora topo centro) com barras de score (width 200) para guild e rival e timer central. Atualize em OnRep_ActiveWar.
    3. No evento de morte de jogador (OnAnyDamage no GameMode), se ambas guilds são rivais e guerra ativa, acrescente ScorePerKill e faça Multicast MC_UpdateWarScore.
    4. Ao expirar timer, dispare VaRest POST /guild/war/finish com vencedor e encerre HUD.
  8. Debug para iniciantes: widget WBP_GuildDebug (250x180, canto inferior direito X=1620 Y=880) com botões "Forçar Aceitar" (auto aceita primeiro convite pendente), "Limpar Invites" e "Reset War" chamando RPCs protegidos por flag GM.
  9. Testes guiados:
    1. Envie convite de A para B sem guild → B recebe UI, aceita em 20s → vê nome na lista replicada.
    2. Ultrapasse limite: configure MaxBase=2 e tente adicionar terceiro membro → mensagem de bloqueio.
    3. Inicie guerra: declare, mate um jogador da guild rival → score sobe e HUD atualiza; expire timer para ver POST final.
    4. Desligue rede durante POST de convite → entrada permanece em PendingInvites e reenvia a cada 5s até sucesso.
