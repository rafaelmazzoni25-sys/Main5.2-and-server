Conceitos do Código Original

CPersonalShop::CheckPersonalShop / Open – Validação de slots e preços
📘 O Que é?

Funções de verificação antes de abrir loja pessoal, checando slots de inventário e valores definidos pelo jogador.

bool CPersonalShop::CheckPersonalShop(int aIndex) {
  for(int n=INVENTORY_EXT4_SIZE;n < INVENTORY_FULL_SIZE;n++) {
    if(gObj[aIndex].Inventory[n].IsItem() != 0) { return 0; }
  }
  return 1;
}
bool CPersonalShop::CheckPersonalShopOpen(int aIndex) {
  int count = 0;
  for(int n=INVENTORY_EXT4_SIZE;n < INVENTORY_FULL_SIZE;n++) {
    if(gObj[aIndex].Inventory[n].IsItem() != 0) {
#if(GAMESERVER_UPDATE>=802)
      if(gObj[aIndex].Inventory[n].m_PShopValue <= 0 && gObj[aIndex].Inventory[n].m_PShopJoBValue <= 0 &&
         gObj[aIndex].Inventory[n].m_PShopJoSValue <= 0 && gObj[aIndex].Inventory[n].m_PShopJoCValue <= 0)
#else
      if(gObj[aIndex].Inventory[n].m_PShopValue <= 0)
#endif
      { return 0; }
      else { count++; }
    }
  }
  return ((count==0)?0:1);
}

🎯 Para Que Serve?

Impede abrir loja sem itens/preços válidos e evita itens fora das extensões específicas do inventário.

💻 Como Funciona?

  1. Itera do slot INVENTORY_EXT4_SIZE ao INVENTORY_FULL_SIZE.
  2. Rejeita se houver item sem preço configurado.
  3. Conta itens elegíveis para garantir que ao menos um produto existe.

Trechos do roteamento central que despacham handlers de trade e de loja pessoal.

case 0x36: gTrade.CGTradeRequestRecv((PMSG_TRADE_REQUEST_RECV*)lpMsg,aIndex); break;
case 0x37: gTrade.CGTradeResponseRecv((PMSG_TRADE_RESPONSE_RECV*)lpMsg,aIndex); break;

    case 0x01: gPersonalShop.CGPShopSetItemPriceRecv(...); break;
    case 0x02: gPersonalShop.CGPShopOpenRecv(...); break;
    case 0x03: gPersonalShop.CGPShopCloseRecv(aIndex); break;
    case 0x05: gPersonalShop.CGPShopItemListRecv(...); break;
    case 0x06: gPersonalShop.CGPShopBuyItemRecv(...); break;
    case 0x07: gPersonalShop.CGPShopLeaveRecv(...); break;
  }
  break;

🎯 Para Que Serve?

Define o fluxo de requisição/resposta de trade (negociação direta) e de loja pessoal (vitrine persistente enquanto aberta).

💻 Como Funciona?

  1. Recebe pacotes com cabeçalho 0x36–0x3D para trade e 0x3F para loja.
  2. Despacha para gTrade ou gPersonalShop, que validam itens, moedas e status de sessão.
  3. Envia respostas de confirmação/erro para ambos jogadores ou compradores.

Implementação em Unreal Engine 5

O comércio é dividido em duas camadas: interação direta (trade) e loja persistente, com backend para logging e segurança.

  1. Implemente um UTradeComponent em APlayerController com RPCs ServerRequestTrade, ServerAcceptTrade, ServerConfirmTrade validando inventário e moedas.
  2. Use arrays replicados de slots de trade (UPROPERTY(Replicated)) para mostrar itens e valores na UI UMG.
  3. Para loja pessoal, crie UPersonalShopComponent que guarda lista de itens e preços; exponha ServerOpenShop, ServerCloseShop, ServerBuyFromShop com verificações semelhantes a CheckPersonalShopOpen.
  4. Persistência e auditoria: quando abrir/fechar loja ou concluir venda, envie via VaRest um POST /shop/log para um servidor Node.js que grava em SQL (itens, vendedor, comprador, valores).
  5. Adicione checagens de integridade: valide que itens estão em slots permitidos e que o preço é maior que zero antes de replicar a vitrine.
  6. Crie widgets UMG para trade bilateral e para vitrine (lista de itens do vendedor com botão de compra) consumindo dados replicados.
  7. No servidor UE5, sincronize moedas e inventário usando uma camada de autoridade no GameState ou um serviço dedicado que aplica as mudanças apenas após confirmação do backend SQL.
  8. Teste em multiplayer: simule duas conexões, abra loja, compre item, realize trade direto e valide replicação/desconto de moedas.

Checklist Final

  • Trade bilateral funcionando com confirmação dupla e replicação de slots.
  • Loja pessoal abre apenas com itens precificados e replica lista para visitantes.
  • Logs de venda e trade são enviados ao Node.js/SQL via VaRest.
  • Itens e moedas atualizam corretamente após compras/trocas.
