Conceitos do Código Original

CPersonalShop::CheckPersonalShop / Open – Validação de slots e preços
📘 O Que é?

Funções de verificação antes de abrir loja pessoal, checando slots de inventário e valores definidos pelo jogador.

bool CPersonalShop::CheckPersonalShop(int aIndex) {
  for(int n=INVENTORY_EXT4_SIZE;n < INVENTORY_FULL_SIZE;n++) {
    if(gObj[aIndex].Inventory[n].IsItem() != 0) { return 0; }
  }
  return 1;
}
bool CPersonalShop::CheckPersonalShopOpen(int aIndex) {
  int count = 0;
  for(int n=INVENTORY_EXT4_SIZE;n < INVENTORY_FULL_SIZE;n++) {
    if(gObj[aIndex].Inventory[n].IsItem() != 0) {
#if(GAMESERVER_UPDATE>=802)
      if(gObj[aIndex].Inventory[n].m_PShopValue <= 0 && gObj[aIndex].Inventory[n].m_PShopJoBValue <= 0 &&
         gObj[aIndex].Inventory[n].m_PShopJoSValue <= 0 && gObj[aIndex].Inventory[n].m_PShopJoCValue <= 0)
#else
      if(gObj[aIndex].Inventory[n].m_PShopValue <= 0)
#endif
      { return 0; }
      else { count++; }
    }
  }
  return ((count==0)?0:1);
}

🎯 Para Que Serve?

Impede abrir loja sem itens/preços válidos e evita itens fora das extensões específicas do inventário.

💻 Como Funciona?

  1. Itera do slot INVENTORY_EXT4_SIZE ao INVENTORY_FULL_SIZE.
  2. Rejeita se houver item sem preço configurado.
  3. Conta itens elegíveis para garantir que ao menos um produto existe.

Trechos do roteamento central que despacham handlers de trade e de loja pessoal.

case 0x36: gTrade.CGTradeRequestRecv((PMSG_TRADE_REQUEST_RECV*)lpMsg,aIndex); break;

🎯 Para Que Serve?

Define o fluxo de requisição/resposta de trade (negociação direta) e de loja pessoal (vitrine persistente enquanto aberta).

💻 Como Funciona?

  1. Recebe pacotes com cabeçalho 0x36–0x3D para trade e 0x3F para loja.
  2. Despacha para gTrade ou gPersonalShop, que validam itens, moedas e status de sessão.
  3. Envia respostas de confirmação/erro para ambos jogadores ou compradores.

Implementação em Unreal Engine 5

O comércio é dividido em duas camadas: interação direta (trade) e loja persistente, com backend para logging e segurança.

  1. Implemente um UTradeComponent em APlayerController com RPCs ServerRequestTrade, ServerAcceptTrade, ServerConfirmTrade validando inventário e moedas.
  2. Use arrays replicados de slots de trade (UPROPERTY(Replicated)) para mostrar itens e valores na UI UMG.
  3. Para loja pessoal, crie UPersonalShopComponent que guarda lista de itens e preços; exponha ServerOpenShop, ServerCloseShop, ServerBuyFromShop com verificações semelhantes a CheckPersonalShopOpen.
  4. Persistência e auditoria: quando abrir/fechar loja ou concluir venda, envie via VaRest um POST /shop/log para um servidor Node.js que grava em SQL (itens, vendedor, comprador, valores).
  5. Adicione checagens de integridade: valide que itens estão em slots permitidos e que o preço é maior que zero antes de replicar a vitrine.
  6. Crie widgets UMG para trade bilateral e para vitrine (lista de itens do vendedor com botão de compra) consumindo dados replicados.
  7. No servidor UE5, sincronize moedas e inventário usando uma camada de autoridade no GameState ou um serviço dedicado que aplica as mudanças apenas após confirmação do backend SQL.
  8. Teste em multiplayer: simule duas conexões, abra loja, compre item, realize trade direto e valide replicação/desconto de moedas.

Checklist Final

  • Trade bilateral funcionando com confirmação dupla e replicação de slots.
  • Loja pessoal abre apenas com itens precificados e replica lista para visitantes.
  • Logs de venda e trade são enviados ao Node.js/SQL via VaRest.
  • Itens e moedas atualizam corretamente após compras/trocas.

Passo a passo Blueprint (mínimo detalhe para qualquer iniciante)

  1. Pasta /Commerce/: crie DataTable ShopPricing_DT com campos ItemID, MinPrice, MaxPrice, Currency (Zen/Jewel). Use para validar preço.
  2. Componente BP_TradeComponent no PlayerController: variáveis replicadas TradeSlotsSelf[12], TradeSlotsOther[12], TradeZen, bBothConfirmed. Marque OnRep_TradeSlots para atualizar UI.
  3. Fluxo Trade:
    1. ServerRequestTrade(TargetPC): verifica distância <= 400u (use GetDistanceTo) e estado livre. Se ok, chama ClientTradeInvite no alvo.
    2. ServerAcceptTrade: cria TradeSessionID (GUID) salvo em ambos componentes.
    3. ServerAddTradeItem(Slot, ItemID): valida item no inventário e insere em TradeSlotsSelf; dispara Multicast MC_UpdateTrade.
    4. ServerConfirmTrade: seta flag bConfirmedSelf=true; se ambos confirmados, chama FinalizeTrade().
    5. FinalizeTrade: troca itens/Zen entre inventários (autoridade no servidor), limpa slots e envia VaRest POST /api/trade/complete com {seller,buyer,items,zen,sessionId}.
  4. UI Trade (Widget WBP_Trade, 900x520, âncora centro):
    1. Grid esquerda 6x2 para itens do jogador (slot 64x64, espaçamento 8). Grid direita idêntica para o outro.
    2. Campo Zen (entrada numérica 140x40, Y=420) e botão "Confirmar" (180x46, Y=470). Use cor verde quando bConfirmedSelf true.
    3. Texto de status no topo (X=360 Y=18): "Sessão {GUID abreviado}".
  5. Loja pessoal (Componente BP_PShopComponent no Controller):
    1. Variáveis replicadas ShopSlots[24] (struct {ItemID,Price,Currency}), bShopOpen, ShopTitle (string).
    2. RPC ServerOpenShop: valida usando ShopPricing_DT (preço dentro do range) e se slots 0-23 estão preenchidos; seta bShopOpen=true e chama VaRest POST /api/shop/open.
    3. RPC ServerBuyFromShop(SlotIndex): verifica se vendedor tem slot preenchido e comprador tem moedas suficientes; aplica desconto das moedas e move item para inventário do comprador; envia VaRest POST /api/shop/buy com dados da venda.
    4. RPC ServerCloseShop: define bShopOpen=false, limpa visitantes e POST /api/shop/close.
  6. HUD Loja (Widget WBP_ShopBoard, 980x560):
    1. Topo (Y=16): campo texto para título (width 520) e botão "Abrir/Fechar" (140x44).
    2. Grade produtos 6x4 (slot 80x80, espaçamento 6) centralizada (X≈180 Y=80). Cada slot mostra ícone + preço e moeda.
    3. Painel visitantes (200x520, ancorado direita X=760): lista de compradores conectados (apelido e ping).
  7. Segurança para iniciantes:
    1. Adicione checagem de duplicação: antes de finalizar trade/compra, compare LastInventoryHash (hash MD5 de itens) salvo no GameState; se divergir, aborte.
    2. Timeout: SetTimer de 90s após abrir trade; se expirar, chama CancelTrade() em ambos.
    3. Anti-spam: mantenha LastTradeRequestTime e bloqueie novas requisições em < 2s.
  8. Testes passo a passo:
    1. Cliente A solicita trade a B → B aceita → ambos adicionam um item e 1000 Zen → Confirmar → validar troca cruzada.
    2. Abrir loja com 3 itens precificados dentro do range → Cliente B compra 1 item → inventários atualizados e POST log recebido.
    3. Simular falha de rede: desconecte internet ao clicar Confirmar → verificar que FinalizeTrade reenvia POST ao reconectar e mantém itens congelados até resposta.
