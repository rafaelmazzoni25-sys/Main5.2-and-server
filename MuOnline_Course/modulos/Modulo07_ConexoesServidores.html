Módulo 7 – Conexões JoinServer/DataServer

Detalhamos como o GameServer sobe e mantém conexões com serviços auxiliares (JoinServer e DataServer).

Pré-requisitos

  • Módulos 1 e 2 concluídos.
  • Conhecimento de sockets WinSock e mensagens de janela (FD_READ/FD_WRITE).

Conceitos do Código Original

Abertura de conexões – JoinServerConnect/DataServerConnect
📘 O Que é?

Funções que abrem sockets para os servidores auxiliares e enviam o pacote inicial de identificação.

🎯 Para Que Serve?

Permite que o GameServer registre-se e troque dados de contas/personagens com JoinServer e DataServer.

💻 Como Funciona?

bool JoinServerConnect(DWORD wMsg) {
    if(gJoinServerConnection.Connect(gServerInfo.m_JoinServerAddress,(WORD)gServerInfo.m_JoinServerPort,wMsg) == 0) {
        return 0;
    }
    GJServerInfoSend();
    return 1;
}

bool DataServerConnect(DWORD wMsg) {
    if(gDataServerConnection.Connect(gServerInfo.m_DataServerAddress,(WORD)gServerInfo.m_DataServerPort,wMsg) == 0) {
        return 0;
    }
    GDServerInfoSend();
    return 1;
}

Processamento de mensagens de socket – JoinServerMsgProc/DataServerMsgProc
📘 O Que é?

Handlers de eventos de socket que respondem a FD_READ, FD_WRITE e FD_CLOSE.

🎯 Para Que Serve?

Garante envio/recebimento de pacotes e encerra conexões limpidamente.

💻 Como Funciona?

void JoinServerMsgProc(WPARAM wParam,LPARAM lParam) {
    switch(LOWORD(lParam)) {
        case FD_READ: gJoinServerConnection.DataRecv(); break;
        case FD_WRITE: gJoinServerConnection.DataSendEx(); break;
        case FD_CLOSE:
            gJoinServerConnection.Disconnect();
            gObjAllDisconnect();
            break;
    }
}

Implementação em Unreal Engine 5

Em um servidor dedicado UE5, encapsule as conexões auxiliares em um USubsystem iniciado pelo AGameModeBase.

UCLASS()
class UMuBackendSubsystem : public UGameInstanceSubsystem {
    GENERATED_BODY()
public:
    virtual void Initialize(FSubsystemCollectionBase& Collection) override {
        // Abrir sockets para Join/Data servers
    }
    virtual void Deinitialize() override {
        // Fechar sockets
    }
    void Tick(float DeltaTime);
};

Passo a Passo em Unreal Engine 5

  1. Criar um UGameInstanceSubsystem para manter sockets persistentes de JoinServer/DataServer e armazenar configurações (IP/porta) carregadas de JSON.
  2. Implementar callbacks de leitura/escrita usando FUdpSocketReceiver ou FTicker para simular o FD_READ e manter o game thread livre.
  3. Enviar mensagem de identificação ao estabelecer conexão, espelhando GJServerInfoSend/GDServerInfoSend, e aguardar ack antes de processar demais pacotes.
  4. Em caso de FD_CLOSE equivalente, derrubar sessões de jogadores como gObjAllDisconnect(), replicando a remoção forçada em gObjAllDisconnectCustom() se existir.
  5. Persistir o estado das conexões (Join/Data) em um actor de gerenciamento que possa reiniciar sockets sem derrubar o servidor UE5; incluir backoff exponencial para reconexão.
  6. Adicionar health-check periódico via HTTP para backup da conexão (usando VaRest) quando o socket falhar, atualizando um painel web Node.js/SQL.
  7. Registrar métricas por conexão (latência, bytes, número de pacotes) em UAnalyticsProvider customizado e salvar snapshots em disco.
  8. Escrever testes que simulam queda de JoinServer/DataServer e verificam reconexão automática e retomada de envios pendentes.
  9. Expor comandos de console para reiniciar manualmente cada canal de conexão e forçar re-handshake com Join/Data.
  10. Documentar o fluxo de boot: carregar config, abrir socket, enviar info, esperar ack, sinalizar GameMode para liberar jogadores.

Guia Blueprint minucioso (Join/Data + VaRest)

Objetivo: conectar JoinServer/DataServer com Blueprints, VaRest e sockets, mesmo para quem nunca programou.

  1. No Content Browser, crie Blueprint Class → GameInstance chamada BP_GI_Backend. Em Project Settings → Maps & Modes, defina-a como Game Instance Class.
  2. Adicione Variables:
    • JoinServerURL (String) → padrão http://127.0.0.1:3001.
    • DataServerURL (String) → padrão http://127.0.0.1:3002.
    • JoinSocket e DataSocket (Object → Socket se usar plugin de sockets).
    • ReconnectDelay (Float) = 2.0.
  3. No Event Init do BP_GI_Backend:
    • Chame Create Socket (TCP) duas vezes para Join/Data. Guarde o retorno nas variáveis.
    • Use Connect (Node do plugin de sockets) com IP/porta configurados. Se falhar, chame Set Timer by Function Name (Function: TryReconnect, Time: ReconnectDelay, Looping: true).
    • Para cada socket, crie Bind Event to OnMessage apontando para OnJoinMessage e OnDataMessage.
  4. Implemente OnJoinMessage:
    • Use Parse JSON (VaRest) se a mensagem vier como texto; se binário, repasse para um Blueprint Function Library BP_PacketParser com função DecodeJoinHeader.
    • Se detectar evento de desconexão (flag custom FD_CLOSE), chame Multicast EvictAllPlayers no GameMode.
    • Mostre status em um widget BP_ServerStatus: Set Text para "JoinServer ON" (verde) ou "OFF" (vermelho).
  5. Implemente OnDataMessage de forma similar, mas roteando para handlers HandleCharacterList, HandleCharacterInfo. Cada handler usa For Each para preencher um Data Table local (ex.: lista de personagens) e dispara evento OnCharacterListReady para a HUD.
  6. Crie função TryReconnect: para cada socket inválido, Print String "Reconectando..." → Connect novamente. Se sucesso, chame Clear and Invalidate Timer para parar o loop de reconexão.
  7. Adicione um painel visual para iniciantes: crie widget BP_LinkPanel com 2 círculos (Join/Data) usando Image e altere cor (vermelho/verde) via Set Brush Tint. Coloque o widget no Viewport do GameInstance (chame Add to Viewport no Event Init) para ver status sem abrir logs.
  8. Inclua testes de sala de aula: abra 2 instâncias PIE, derrube o serviço Join (parar Node.js) e verifique se o círculo volta a verde quando o serviço retornar. Marque cada passo em uma checklist visível dentro do widget (usando CheckBox + Text).
  9. Persistência: sempre que conectar, dispare Create VaRestRequest (POST) em /bootstrap enviando ServerCode e MaxUsers e grave o token de sessão retornado em variável AuthToken para ser anexado nos próximos pacotes.

Checklist Final

  • Servidor UE5 conecta automaticamente a serviços auxiliares no boot.
  • Loop de recebimento envia e lê pacotes sem bloquear o game thread.
  • Desconexões forçam logout dos jogadores conectados.
