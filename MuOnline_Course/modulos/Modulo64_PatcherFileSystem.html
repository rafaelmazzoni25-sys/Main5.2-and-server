Módulo 64 – Patcher, FileSystem e CRC

Mapeia o carregamento de assets do cliente C++ (BMD/OZ*/MAP/ATT/OBJ), verificação de CRC e como reproduzir o fluxo de patch/update na UE5.

Pré-requisitos

  • Pipeline de conversão de assets configurado (Módulo 14 e 50).
  • Infra de rede/VaRest para download e checagem de versões.

Conceitos do Código Original

Loader de arquivos (OZFile.cpp, MemoryChecker.cpp)

O cliente abre OZJ/OZT/OZB/OZP/OZD, BMD e scripts via offsets de diretório e valida CRC antes de usar.

  • OZ::Load lê cabeçalhos comprimidos, descompacta com tabelas RLE e valida Header.CRC32.
  • Funções auxiliares LoadImage, LoadBMD, LoadMap compartilham a mesma rotina de CRC.
  • MemoryChecker compara o hash do executável e de pastas críticas (Data, Local) com valores do patcher.
Patcher (Launcher/Main.cpp, UpdateServer.cpp)

O launcher consulta UpdateServer para lista de arquivos e CRC, baixa diffs e revalida antes de iniciar o cliente.

  • Lista de manifestos em Patch/ServerList.dat com campos: Nome, CRC, Tamanho, URL.
  • Regras de prioridade: DLLs e exe antes de assets; falha em CRC aborta o start.

Adaptação UE5 (Blueprint/C++)

  1. Crie um serviço Node.js /patch-manifest que exponha JSON com campos Path, Hash, Size, Type (Texture/Mesh/Map/Pak).
  2. No launcher UE5 (projeto separado ou modo standalone), adicione um BP_Patcher com steps:
    • Consulta: VaRest GET em /patch-manifest, parse para um array de structs.
    • Verificação local: calcule SHA256/CRC32 de cada arquivo em Content/Paks e Saved/Converted; compare com o manifest.
    • Download: para arquivos divergentes, baixe em Saved/Downloads, valide hash e mova para o destino.
  3. Implemente um Subsystem C++ ou Blueprint BP_FileSystem que registre caminhos convertidos (FBX, PNG, maps) em um DataTable DT_AssetRegistry com campos: LegacyPath, UEPath, Hash, Type, ConvertedAt.
  4. Durante o boot (Módulo 1), carregue DT_AssetRegistry e valide hashes críticos (UI atlases, meshes principais). Se faltar ou divergir, exiba modal de reparo chamando o BP_Patcher.
  5. Para MAP/ATT/OBJ convertidos, salve arquivos auxiliares (heightmap RAW + JSON de props) com hash no manifest e configure o BP_MapLoader para rejeitar mapas sem hash válido.

Checklist de Paridade

  • Todos os assets baixados/verificados antes do boot, tal como o patcher original.
  • Hashes/CRC registrados em tabela e validados na carga de UI, mapas e modelos.
  • Fluxo de reparo automático em caso de divergência, impedindo start se arquivos críticos faltarem.
  • Manifesto versionado garante sincronismo entre cliente UE5 e servidor de updates.
