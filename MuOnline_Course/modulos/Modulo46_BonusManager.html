Módulo 46 – Bonus Manager (Buffs Globais)

Descreve como o servidor agenda e aplica bônus globais (XP, drop, resets) usando o CBonusManager, e como reproduzir esse agendador em Unreal Engine 5 com backend VaRest/Node.js/SQL.

Pré-requisitos

  • Módulo 1 – Arquitetura Geral (inicialização do GameServer).
  • Módulo 18 – Sistema Gens (para entender filtros por facção, caso aplique a bônus).
  • Módulo 41 – Experiência/Reset (efeitos de multiplicadores sobre XP).

Conceitos do Código Original

Inicialização e carregamento – CBonusManager::Load/Init
📘 O Que é?

Rotinas que zeram os slots de bônus, leem horários/valores do script BonusManager.dat e colocam cada entrada em estado EMPTY para sincronizar com o horário mais próximo.

CBonusManager::CBonusManager() {
  for(int n=0;n < MAX_BONUS;n++) {
    BONUS_INFO* lpInfo = &this->m_BonusInfo[n];
    lpInfo->Index = n; lpInfo->State = BONUS_STATE_BLANK;
    lpInfo->RemainTime = 0; lpInfo->TargetTime = 0;
    lpInfo->TickCount = GetTickCount();
    lpInfo->StartTime.clear(); lpInfo->ValueInfo.clear();
  }
}
void CBonusManager::Init() {
  for(int n=0;n < MAX_BONUS;n++) {
    if(gServerInfo.m_BonusManagerSwitch == 0)
      this->SetState(&this->m_BonusInfo[n],BONUS_STATE_BLANK);
    else
      this->SetState(&this->m_BonusInfo[n],BONUS_STATE_EMPTY);
  }
}
void CBonusManager::Load(char* path) {
  CMemScript* lpMemScript = new CMemScript;
  if(lpMemScript->SetBuffer(path) == 0) { ErrorMessageBox(...); return; }
  for(int n=0;n < MAX_BONUS;n++) { this->m_BonusInfo[n].StartMessage = -1; ... }
  while(true) { if(lpMemScript->GetToken() == TOKEN_END) break; int section = lpMemScript->GetNumber();
    if(section == 0) { /* horários */ BONUS_START_TIME info; int index = lpMemScript->GetNumber(); info.Year = ...; info.Second = lpMemScript->GetAsNumber(); this->m_BonusInfo[index].StartTime.push_back(info); }
    else if(section == 1) { int index = lpMemScript->GetNumber(); this->m_BonusInfo[index].StartMessage = lpMemScript->GetAsNumber(); this->m_BonusInfo[index].FinalMessage = lpMemScript->GetAsNumber(); }
  }
}

🎯 Para Que Serve?

Prepara os slots de bônus para que cada entrada saiba quando deve começar, quais mensagens exibir e quais valores aplicar (XP/drop/reset etc.).

💻 Como Funciona?

O construtor zera tudo; Init decide se o sistema ficará ativo; Load popula horários e mensagens lendo o arquivo de configuração.

Máquina de estados e sincronismo – CBonusManager::MainProc/CheckSync
📘 O Que é?

Loop que, para cada entrada, sincroniza com o próximo horário agendado e alterna entre estados EMPTY (aguardando) e START (bônus ativo).

🎯 Para Que Serve?

Garante que os bônus globais iniciem e terminem exatamente nos horários definidos, enviando mensagens configuradas.

💻 Como Funciona?

void CBonusManager::MainProc() {
  for(int n=0;n < MAX_BONUS;n++) {
    BONUS_INFO* lpInfo = &this->m_BonusInfo[n];
    switch(lpInfo->State) {
      case BONUS_STATE_BLANK: this->ProcState_BLANK(lpInfo); break;
      case BONUS_STATE_EMPTY: this->ProcState_EMPTY(lpInfo); break;
      case BONUS_STATE_START: this->ProcState_START(lpInfo); break;
    }
  }
}
void CBonusManager::ProcState_EMPTY(BONUS_INFO* lpInfo) {
  if(lpInfo->RemainTime <= 0) { if(lpInfo->StartMessage != -1) gNotice.GCNoticeSendToAll(...); this->SetState(lpInfo,BONUS_STATE_START); }
}
void CBonusManager::ProcState_START(BONUS_INFO* lpInfo) {
  if(lpInfo->RemainTime <= 0) { if(lpInfo->FinalMessage != -1) gNotice.GCNoticeSendToAll(...); this->SetState(lpInfo,BONUS_STATE_EMPTY); }
}
void CBonusManager::CheckSync(BONUS_INFO* lpInfo) {
  if(lpInfo->StartTime.empty() != 0) { this->SetState(lpInfo,BONUS_STATE_BLANK); return; }
  CScheduleManager ScheduleManager;
  for(auto it : lpInfo->StartTime) { ScheduleManager.AddSchedule(it.Year,it.Month,it.Day,it.Hour,it.Minute,it.Second,it.DayOfWeek); }
  if(ScheduleManager.GetSchedule(&ScheduleTime) == 0) { this->SetState(lpInfo,BONUS_STATE_BLANK); return; }
  lpInfo->RemainTime = (int)difftime(ScheduleTime.GetTime(),time(0));
  lpInfo->TargetTime = (int)ScheduleTime.GetTime();
}

Aplicação de bônus – uso em XP e drops
📘 O Que é?

Chamadas diretas ao gBonusManager.GetBonusValue em pontos de cálculo de experiência e drops para multiplicar valores conforme bônus ativo.

🎯 Para Que Serve?

Permite configurar períodos de XP/drops/resets ampliados sem recompilar o servidor.

💻 Como Funciona?

// User.cpp – loop de eventos
gBonusManager.MainProc();

// ObjectManager.cpp – recompensa de XP
experience = (experience*gBonusManager.GetBonusValue(lpObj,BONUS_INDEX_EXPERIENCE_RATE,100,-1,-1,lpMonster->Class,lpMonster->Level))/100;

// Monster.cpp – drop rate
ItemDropRate = (ItemDropRate*gBonusManager.GetBonusValue(lpObj,BONUS_INDEX_ITEM_DROP_RATE,100,-1,-1,lpObj->Class,lpObj->Level))/100;

Implementação em Unreal Engine 5

Equivalências

  • Gerenciador de bônus: UGameInstanceSubsystem ou UWorldSubsystem com timers.
  • Configuração: UDataTable para agenda e valores; cache em FBonusConfig structs.
  • Aplicação: componentes em AGameState ou UAttributeSet (GAS) consultando o subsistema.

Passo a Passo

  1. Modele um UStruct FBonusSchedule com campos (Data/Hora, Mensagens, Duração, Multiplicadores).
  2. Carregue um UDataTable no UGameInstanceSubsystem; calcule o próximo horário e inicie um FTimerHandle para mudar de estado (EMPTY → START → EMPTY).
  3. No AGameState, replique CurrentBonusState e multiplicadores ativos; use rep-notify para atualizar HUD.
  4. Intercepte recompensas (XP, drop) em componentes de combate/inventário e multiplique pelo valor ativo do subsistema.
  5. Persistência: ao iniciar/encerrar um bônus, chame VaRest → endpoint Node.js → SQL para registrar histórico e manter valores sincronizados entre shards/servidores.

Checklist Final

  • Agenda de bônus carregada de DataTable/SQL e sincronizada no servidor.
  • HUD mostra estado/mensagens do bônus replicadas.
  • Cálculos de XP, drop e resets usam multiplicadores ativos.
  • Logs/histórico de bônus são salvos via VaRest/Node.js/SQL.

Guia ultra-detalhado para iniciantes (Blueprints + VaRest/SQL)

Passos literais para montar o agendador de bônus globais em UE5 sem escrever C++.

1) Dados e backend
  1. No UE5, crie Struct ST_BonusSlot com: Nome (String), HoraInicio (DateTime), DuracaoMin (Int), MsgInicio (Text), MsgFim (Text), MultXP (Float), MultDrop (Float), MultReset (Float).
  2. Crie DataTable DT_BonusManager (RowName = “MorningXP”, “WeekendDrop”, etc.). Exemplos:
    MorningXP: HoraInicio 08:00, Duracao 120, MsgInicio “XP x2 ON”, MultXP=2.0;
    WeekendDrop: HoraInicio Sábado 18:00, Duracao 180, MsgInicio “Drop x1.5 ON”, MultDrop=1.5.
  3. Banco SQL: tabelas BonusSchedule(Id, Name, StartAt, DurationMin, MultXP, MultDrop, MultReset) e BonusHistory(Id, Name, StartedAt, EndedAt, WinnerShard).
  4. Endpoints Node.js/PHP:
    GET /bonus/next (retorna próximo agendamento para sincronizar casos de queda de conexão);
    POST /bonus/start {name, startAt};
    POST /bonus/end {name, endAt};
    POST /logs/bonus {name, multXp, multDrop, multReset, server}.
  5. No Blueprint BP_SQLBridge, adicione funções FetchNextBonus (GET /bonus/next) e LogBonus (POST /logs/bonus).
2) Subsistema de bônus (Blueprint)
  1. Crie BP_BonusSubsystem herdando de GameInstanceSubsystem. Variáveis: BonusAtual (Struct), bAtivo (bool), TempoRestante (int), TimerHandle, MultiplicadorXP (float), MultiplicadorDrop, MultiplicadorReset.
  2. No Initialize: carregue DT_BonusManager para array; chame FetchNextBonus (VaRest) e inicie SetTimer que checa a cada 30s se chegou a HoraInicio.
  3. Função AtivarBonus (inputs: Slot): setar bAtivo=true, TempoRestante=Slot.DuracaoMin*60, copiar multiplicadores, disparar Multicast_ShowBonusMessage(Slot.MsgInicio), chamar LogBonus (start).
  4. Função TickBonus (chamada a cada 1s via timer separado): decrementa TempoRestante; quando chega a zero, chama EncerrarBonus.
  5. Função EncerrarBonus: zera multiplicadores (1.0), bAtivo=false, mensagem final, log via VaRest /bonus/end.
3) HUD e feedback
  1. Crie widget WBP_BonusBanner ancorado no topo centro (Position X=640, Y=10; Size X=620, Y=60).
  2. Elementos: retângulo semi-transparente, Texto “XP x2 + Drop x1.5”, subtítulo “Termina em 01:59:30”. Ícone de relógio 28x28 à esquerda.
  3. Binding: texto principal concatena multiplicadores ativos; contador usa TempoRestante (format HH:MM:SS). Visibilidade = bAtivo.
  4. Evento OnBonusChanged (Dispatch do subsistema) adiciona o widget ao viewport e toca som “Bonus_On”.
  5. No fim, animação “FadeOut” 1s e remoção do widget.
4) Aplicação em gameplay (Blueprint apenas)
  1. Em BP_CombatComponent, antes de dar XP, multiplique: XPBase * BP_BonusSubsystem.MultiplicadorXP.
  2. Em BP_LootComponent, ao calcular chance de drop, faça ChanceBase * MultiplicadorDrop e clamp 0–1.
  3. Em BP_ResetManager, ao cobrar custo ou dar pontos, aplique MultiplicadorReset.
  4. Todos esses componentes devem obter o subsistema via GetGameInstance → GetSubsystem (node pronto).
5) Painel de GM para testes
  1. Widget WBP_BonusGMPanel ancorado canto direito (Position X=1580, Y=420, Size X=300, Y=220).
  2. Lista (ComboBox) com RowNames do DT_BonusManager, botão “Forçar Início”, botão “Finalizar Agora”.
  3. OnClicked Forçar: pega linha selecionada → chama AtivarBonus direto (sem esperar hora). Atualiza HUD e envia /bonus/start.
  4. OnClicked Finalizar: chama EncerrarBonus e envia /bonus/end.
  5. Checklist visual: texto “Ativo? Sim/Não”, “Tempo Restante: 00:00:00”.
6) Testes rápidos
  1. Forçar bônus “XP x2”; verificar HUD e multiplicador de XP em combate (mate 1 monstro e compare).
  2. Esperar 30s e conferir decremento do contador.
  3. Finalizar manualmente e garantir que HUD some e multiplicadores voltam a 1.0.
  4. Derrubar o cliente e reconectar: checar se GET /bonus/next restaura estado e HUD.
  5. Consultar tabela BonusHistory no SQL para ver logs gravados.
