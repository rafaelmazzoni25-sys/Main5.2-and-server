Módulo 52 – Enums de Sons, Músicas e Mapas de Uso

Cataloga todos os enums do cliente/servidor legado relacionados a áudio (efeitos e trilhas), agrupados por utilidade, e explica como recriar o roteamento 1:1 na Unreal Engine 5.

Enums do Código Legado

Efeitos de Som (DSPlaySound.h)

Separados por categoria para facilitar a importação em DataTables:

  • Ambiente (0–23): vento, água, lava, portas (PLAY_SOUND_WIND, PLAY_SOUND_WATER...).
  • UI (25–42): hover, click, erro (PLAY_SOUND_BUTTON_CLICK, PLAY_SOUND_ERROR).
  • Movimento/Passos (60–70): passos por terreno e salto (PLAY_SOUND_STEP1, PLAY_SOUND_JUMP).
  • Combate (80–97): impacto físico, bloqueio, crítico (PLAY_SOUND_ATTACK01, PLAY_SOUND_HIT_CRITICAL).
  • Skills (111–133): por nome de skill (ex.: PLAY_SOUND_EVIL, PLAY_SOUND_ICE, PLAY_SOUND_TWISTER).
  • Eventos/Estado (140–159): level up, morte, alerta (PLAY_SOUND_LEVELUP, PLAY_SOUND_DIE).
  • NPC/Monster (160–210): rugidos e gritos indexados por BMD::Sounds[i] (ex.: PLAY_SOUND_MONSTER1...).

Localização: Source Main 5.2/source/DSPlaySound.h. Cada constante é um índice inteiro usado nos slots BMD::Sounds[10].

Músicas de Mapas (MusicList.h)

Enum de BGM por mapa: MUSIC_LORENCIA, MUSIC_NORIA, MUSIC_DUNGEON, MUSIC_ATLANS, MUSIC_TARKAN, MUSIC_ICARUS, MUSIC_AIDA, MUSIC_CRYWOLF, MUSIC_ELBELAND, MUSIC_URUK etc.

  • Cada entrada mapeia o ID do mapa (MAP_INDEX em MapClass.h) para um arquivo *.OZ* (convertido para .ogg / .wav na UE5).
  • IDs especiais para telas: MUSIC_LOGIN, MUSIC_CHARACTER_SELECT, MUSIC_CHAOS_CASTLE.

Localização: Source Main 5.2/source/Sound/MusicList.h e referências em Sound/OZSnd.cpp para carregar os bancos.

Enums de Prioridade/Canal

O cliente define prioridades para mixagem: SOUND_PRIORITY_ENV, SOUND_PRIORITY_UI, SOUND_PRIORITY_SKILL, SOUND_PRIORITY_BGM. Também separa canais: CHANNEL_ENV, CHANNEL_UI, CHANNEL_MONSTER, CHANNEL_PLAYER.

Localização: Source Main 5.2/source/Sound/SoundMng.h.

Replicação 1:1 na UE5

  1. DataTable de Efeitos: Crie DT_SoundEffects com colunas SoundId (int), Category (UI/Step/Skill/Monster), SoundCue, DefaultVolume, Pitch. Preencha com os índices acima. Armazene os assets em /Game/MU/Audio/SFX com nomes SFX_029_UI_GetItem, SFX_070_Attack01, SFX_160_Monster1.
  2. DataTable de Músicas: Crie DT_MapMusic com colunas MapId (mesmo MAP_INDEX do módulo 3), MusicId (enum), SoundWave, Loop (bool), FadeInSec. Assets em /Game/MU/Audio/BGM com nomes BGM_Lorencia, BGM_Dungeon etc.
  3. Blueprint BP_AudioRouter: Funções PlayEffect(SoundId, Location, Owner) e PlayMusic(MapId). Use Get Data Table Row nos DTs acima → Spawn Sound 2D para UI/skill → Spawn Sound at Location para passos/monstros. Configure Sound Class por Category (UI/Skill/Env).
  4. AnimNotifies/Sockets: Para personagens e mobs, adicione AnimNotify_PlaySoundId (int) nas montagens. No notify, chame BP_AudioRouter.PlayEffect. Para passos, use socket Foot_L/Foot_R para posicionar o áudio.
  5. Prioridade/Canal: Crie Sound Classes SC_UI, SC_Skill, SC_Monster, SC_BGM e mapeie Category → classe. Ajuste Volume e Concurrency para replicar a mixagem do legado (UI sempre audível, BGM com ducking em cutscenes).
  6. Verificação 1:1: Monte um mapa de teste e acione os enums em sequência (UI, passos, skill, BGM). Compare IDs e volumes com o cliente antigo. Ajuste DefaultVolume no DT_SoundEffects até alinhar.

Checklist Final

  • Todos os enums de efeito (DSPlaySound) categorizados e presentes em DT_SoundEffects.
  • Músicas mapeadas por ID de mapa e replicadas em BP_AudioRouter.PlayMusic.
  • AnimNotifies referenciam SoundId e respeitam os sockets/pinos corretos.
  • Sound Classes configuradas para prioridade e concorrência conforme o legado.
