CRaklion::Load – Delays, ovos e padrões de Selupan
📘 O Que é?

Carrega Raklion.dat para configurar atrasos de aparição/fechamento de portal e thresholds de ovos do boss.

void CRaklion::Load(char* path) {
    CMemScript* lpMemScript = new CMemScript;
    if(lpMemScript->SetBuffer(path) == 0) { ... }
    this->m_FileDataLoad = 0;
    while(true) {
        if(lpMemScript->GetToken() == TOKEN_END) break;
        int section = lpMemScript->GetNumber();
        while(true) {
            if(section == 0) {
                if(strcmp("end",lpMemScript->GetAsString()) == 0) break;
                this->m_AppearanceDelay = lpMemScript->GetNumber();
                this->m_BossZoneCloseDelay = lpMemScript->GetAsNumber();
                this->m_BossZoneOpenDelay = lpMemScript->GetAsNumber();
            }
            else if(section == 1) {
                if(strcmp("end",lpMemScript->GetAsString()) == 0) break;
                this->m_BossEggHalf = lpMemScript->GetNumber();
                this->m_BossEggMax = lpMemScript->GetAsNumber();
            }
            else if(section == 2) {
                if(strcmp("end",lpMemScript->GetAsString()) == 0) break;
                this->m_RaklionBattleOfSelupan.SetSelupanSkillDelay(lpMemScript->GetNumber());
            }
            else if(section == 3) {
                if(strcmp("end",lpMemScript->GetAsString()) == 0) break;
                this->m_RaklionBattleOfSelupan.SetPatternCondition(0,lpMemScript->GetNumber());
                this->m_RaklionBattleOfSelupan.SetPatternCondition(1,lpMemScript->GetAsNumber());
                this->m_RaklionBattleOfSelupan.SetPatternCondition(2,lpMemScript->GetAsNumber());
                this->m_RaklionBattleOfSelupan.SetPatternCondition(3,lpMemScript->GetAsNumber());
                this->m_RaklionBattleOfSelupan.SetPatternCondition(4,lpMemScript->GetAsNumber());
                this->m_RaklionBattleOfSelupan.SetPatternCondition(5,lpMemScript->GetAsNumber());
            }
            else { break; }
        }
    }
    this->m_FileDataLoad = 1;
}

🎯 Para Que Serve?

Define tempos de abertura/fechamento do boss, quantidade de ovos necessária e padrões de habilidade do Selupan para conduzir o ciclo do evento.

💻 Como Funciona?

Lê seções numeradas do script; cada seção preenche campos específicos. As condições de padrão alimentam RaklionBattleOfSelupan, que controla fases de ataque.

CRaklion::MainProc – Estados do boss Selupan
📘 O Que é?

Loop de processamento do evento que checa usuários, estados e direciona para handlers de notificação, standby, batalha e encerramento.

void CRaklion::MainProc() {
    if(gServerInfo.m_RaklionEvent == 0) return;
    gRaklionBattleUserMng.CheckUserOnRaklionBossMap();
    gRaklionBattleUserMng.CheckUserState();
    switch(this->m_RaklionState) {
        case RAKLION_STATE_IDLE: this->ProcState_IDLE(); break;
        case RAKLION_STATE_NOTIFY1: this->ProcState_NOTIFY1(); break;
        case RAKLION_STATE_STANDBY: this->ProcState_STANDBY(); break;
        case RAKLION_STATE_NOTIFY2: this->ProcState_NOTIFY2(); break;
        case RAKLION_STATE_READY: this->ProcState_READY(); break;
        case RAKLION_STATE_START_BATTLE: this->ProcState_START_BATTLE(); break;
        case RAKLION_STATE_NOTIFY3: this->ProcState_NOTIFY3(); break;
        case RAKLION_STATE_CLOSE_DOOR: this->ProcState_CLOSE_DOOR(); break;
        case RAKLION_STATE_ALL_USER_DIE: this->ProcState_ALL_USER_DIE(); break;
        case RAKLION_STATE_NOTIFY4: this->ProcState_NOTIFY4(); break;
        case RAKLION_STATE_END: this->ProcState_END(); break;
    }
}

🎯 Para Que Serve?

Gerencia o ciclo de vida do evento, controlando avisos, entrada/saída de jogadores, fechamento de portais e progressão das fases do boss.

💻 Como Funciona?

Primeiro valida se o evento está ativo, depois sincroniza usuários no mapa. Cada estado chama um método específico; por exemplo, ProcState_IDLE verifica se todos os ovos foram destruídos para iniciar Standby.

void CRaklion::ProcState_IDLE() {
    if(this->m_BossEggCountTotal > 0 && this->GetBossEggCount() == 0) {
        this->SetState(RAKLION_STATE_STANDBY);
        return;
    }
}

Implementação em Unreal Engine 5

Modele Raklion com um AGameState que possui FSM semelhante. Armazene delays e thresholds em Data Assets e use UActorComponent para as fases de notificação, standby e batalha. Sincronize contagem de ovos e estados via RPCs e VaRest para um serviço Node.js/SQL que pode registrar progresso diário.

Passo a Passo em Unreal Engine 5

  1. Crie um USTRUCT FRaklionConfigRow e um UDataTable com campos para delays, BossEggHalf, BossEggMax e padrões de habilidade.
  2. Implemente URaklionStateMachineComponent para manter o estado atual e expor funções StartNotify, StartStandby, StartBattle etc., cada uma com timers replicados.
  3. No AGameState (ex.: AMURaklionState), carregue a tabela no BeginPlay, inicialize contagem de ovos e configure Multicast RPCs para avisos e fechamento de portais.
  4. Monstre o Selupan como um ABossCharacter com UAbilitySystemComponent ou lógica customizada que lê o array de PatternCondition e dispara habilidades em intervalos.
  5. Implemente um componente em jogadores (URaklionPlayerComponent) para registrar entrada/saída do mapa e notificar o GameState.
  6. Integre VaRest em UGameInstance para reportar início/fim do evento a um endpoint Node.js, que grava em SQL quais grupos/horários participaram.

Checklist Final

  • Delays e thresholds do Raklion.dat importados em tabelas UE5.
  • FSM replicada com estados de notificação, standby, batalha e encerramento.
  • Spawn e habilidades do Selupan reproduzidas conforme PatternCondition.
  • Portais/portões sincronizados para entrada/fechamento conforme estado.
  • Logs/telemetria enviados via VaRest para backend Node.js/SQL.
