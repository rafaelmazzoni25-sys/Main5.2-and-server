Módulo 10 – Interface, Input e Loop do Cliente

Detalhamos o subsistema de UI, captura de entrada e o loop de processamento do cliente para replicar a responsividade do cliente original em UE5.

Pré-requisitos

  • Módulos 1 e 2 concluídos.
  • Conhecimento de criação de Widgets em UE5 e binding de input.
  • Noções de arquitetura de loop de jogo e threading.

Conceitos do Código Original

Gerenciador de UI – CUIManager
📘 O Que é?

Classe central que abre/fecha janelas do HUD (guilda, trade, inventário) e controla permissões simultâneas.

class CUIManager
{
public:
    void Init();
    POINT RenderWindowBase(int nHeight, int nOriginY=-1);
    bool PressKey(int nKey);
    bool IsInputEnable();
    void UpdateInput();
    void Render();
    void CloseAll();
    bool IsOpen(DWORD dwInterface);
    bool Open(DWORD dwInterface, DWORD dwExtraData=0);
};

🎯 Para Que Serve?

Centraliza a lógica de interface, garantindo que apenas combinações válidas de janelas sejam exibidas e coordenando input específico de cada tela.

💻 Como Funciona?

Mantém uma lista de interfaces ativas e fornece métodos de abertura/fechamento que checam conflitos antes de renderizar.

bool CUIManager::Open(DWORD dwInterface, DWORD dwExtraData) {
    // verifica se pode abrir e atualiza lista de flags
}

bool CUIManager::PressKey(int nKey) {
    // encaminha teclas para a janela ativa
}

Source Main 5.2/source/UIManager.h

⏱️ Quando é Executado?

Instanciado em Winmain.cpp (g_pUIManager) e utilizado a cada frame por Scene durante o loop principal.

Inicialização de input, UI e audio – WinMain
📘 O Que é?

Bloco de bootstrap do cliente que cria input, widgets e áudio antes de entrar no loop.

🎯 Para Que Serve?

Prepara fontes, captura de teclado/mouse, criação do novo sistema de UI e inicialização de DirectSound/Mp3.

💻 Como Funciona?

Implementação em Unreal Engine 5

Mapeie o gerenciador de UI para UGameInstanceSubsystem que registra Widgets e um UInputComponent customizado no PlayerController. Use FSlateApplication para input cru quando necessário.

UCLASS()
class UMuUIRegistry : public UGameInstanceSubsystem {
    GENERATED_BODY()
public:
    UPROPERTY() TMap<FName, TSubclassOf<UUserWidget>> Screens;
    UPROPERTY() UUserWidget* ActiveScreen;

    void OpenScreen(FName Id) {
        if (ActiveScreen) ActiveScreen->RemoveFromViewport();
        if (TSubclassOf<UUserWidget>* Cls = Screens.Find(Id)) {
            ActiveScreen = CreateWidget(GetWorld(), *Cls);
            ActiveScreen->AddToViewport();
        }
    }
};

UCLASS()
class AMuPlayerController : public APlayerController {
    GENERATED_BODY()
    virtual void SetupInputComponent() override {
        Super::SetupInputComponent();
        InputComponent->BindAxis("MoveForward", this, &AMuPlayerController::OnMove);
        InputComponent->BindAction("OpenInventory", IE_Pressed, this, &AMuPlayerController::ToggleInventory);
    }
};

Passo a Passo em Unreal Engine 5

  1. Criar um UGameInstanceSubsystem que registra todas as telas necessárias (Login, Inventário, Trade, Party) e expõe métodos Open/Close com checagem de estado.
  2. No AMuPlayerController, configurar UInputComponent com binds equivalentes aos atalhos usados pelo cliente (abrir mapa, inventário, chat, party).
  3. Adicionar Widgets em UMG para cada interface e registrar no subsystem. Use UPROPERTY para manter referências fortes e evitar GC.
  4. Implementar um FTickableGameObject ou usar Tick do PlayerController para disparar atualizações da UI a cada frame, similar ao CUIManager::Render, incluindo animações de contagem e cooldown.
  5. Criar um gerenciador de áudio via USoundClass e USoundMix para replicar VolumeLevel; persistir preferências com UGameUserSettings e salvar no Shutdown.
  6. Para input de chat, adicionar um UEditableTextBox que captura foco e bloqueia binds de movimento enquanto ativo, espelhando g_pMercenaryInputBox; habilitar histórico de mensagens.
  7. Encadear inicialização no Init do UGameInstance: carregar Widgets, aplicar áudio, registrar binds, inicializar rede e só então entrar no mapa inicial.
  8. Testar em janela e fullscreen validando que o loop continua processando input/renderização mesmo em mudanças de foco (equivalente às checagens de g_bUseWindowMode) e que a UI pausa adequadamente quando minimizada.
  9. Criar um overlay de depuração que exibe FPS, estado da fila de rede, foco da janela e status de sockets/HTTP.
  10. Adicionar um UInputAction dedicado para alternar cursores/lock do mouse, espelhando as chamadas Win32 ShowCursor e SetFocus, e exibir ícone de modo ativo.
  11. Automatizar cenários de UI com testes AutomationDriver, clicando sequencialmente em login, seleção de personagem, inventário e janela de trade para validar fluxo completo.
  12. Expor comandos de console (via Exec functions) para reiniciar UI/audio em tempo de execução, limpar caches de widgets e recarregar estilos.
  13. Publicar um manual de navegação (teclas + ações) dentro do jogo, garantindo paridade com os atalhos do cliente Win32.

Checklist Final

  • Todas as telas críticas estão registradas e alternam corretamente sem sobreposição indevida.
  • Input de teclado/mouse é roteado para o Widget ativo e para o personagem conforme esperado.
  • Áudio inicia e respeita preferências salvas; UI continua responsiva quando a janela muda de foco.

Tutorial Blueprint da HUD (iniciante)

Guia clicável para posicionar e ligar a HUD base (HP/MP, barras, chat e hotbar) em Blueprints mantendo paridade visual com o cliente original 5.2.

  1. Crie o HUD raiz: Em Content/UI, crie WBP_HUDRoot (UserWidget) e defina o Class Settings para Player Controller Class do projeto. Dentro do Canvas principal, defina Screen Size para 1920x1080.
  2. Orb de HP/MP: Adicione dois Image circulares com textura radial. Posicione o HP em X=46, Y=858 (tamanho 180x180) e o MP em X=244, Y=858. Use Material Parameter Collection para controlar preenchimento por porcentagem (0–1) e amarre ao valor replicado do PlayerState.
  3. Barras de EXP e Stamina: Adicione um ProgressBar abaixo das orbs em X=48, Y=1048, W=640, H=18. Configure Percent via binding GetExpPercent (EXP atual / EXP necessária). A barra de stamina fica logo acima, com altura 12 px e cor azul.
  4. Hotbar de skills: Insira um Horizontal Box em X=640, Y=1012, largura 640, com 10 botões (64x64). Cada botão chama um evento Server_CastSkill(SlotIndex) (Run on Server). Adicione binding para ícone a partir de DA_Skills e exiba cooldown com um Overlay + Border semi-transparente.
  5. Chat com bloqueio de input: Adicione WBP_Chat ancorado em X=32, Y=620, largura 520, altura 220. Inclua ScrollBox para mensagens e EditableTextBox na base. Em OnTextCommitted, chame Server_SendChat. Quando o campo ganha foco, chame um evento SetInputModeUIOnly para bloquear movimentação.
  6. Mini HUD de party: Crie Vertical Box em X=48, Y=68 com entradas WBP_PartySlot (largura 280, altura 56). Cada slot mostra HP/MP com barras de 120 px e ícone da classe. Atualize via OnRep_PartyStatus no PlayerState.
  7. Integração com VaRest para avisos: Adicione um Notification Panel em X=640, Y=120 que exibe textos vindos de /api/announcements (GET a cada 30s). Use um Timer by Event no Event Construct para chamar VaRest e preencher uma fila (array) mostrada com animação Fade In/Out.
  8. Atalhos e lock do mouse: No PlayerController Blueprint, mapear teclas (I para inventário, C para personagem, V para opções). Cada tecla chama UIRegistry->OpenScreen e alterna visibilidade. Use Set Show Mouse Cursor e Set Input Mode Game and UI para alternar o cursor ao abrir UI.
  9. Debug overlay: Sobreponha um TextBlock no canto superior esquerdo (X=20, Y=20) mostrando FPS, ping e estado de socket/HTTP. Alimente o valor de ping a partir do UNetConnection e do tempo de resposta VaRest.
  10. Teste visual rápido: No PIE com resolução 1920x1080, confirme: orbs alinhadas à esquerda sem sobrepor hotbar; chat não bloqueia a hotbar; barra de EXP inteira visível; atalhos funcionam e o cursor alterna corretamente.
