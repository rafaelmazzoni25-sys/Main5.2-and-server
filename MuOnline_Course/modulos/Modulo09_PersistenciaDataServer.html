Módulo 9 – Persistência e DataServer (SQL)

Exploramos como o DataServer acessa o banco via ODBC, recebe requisições do GameServer e devolve informações completas de personagem. Adaptamos isso para UE5 usando VaRest, Node.js e um banco SQL.

Pré-requisitos

  • Módulos 1 a 8 concluídos.
  • Conhecimento de ODBC/SQL e noções de serviços REST.
  • VaRest plugin instalado no projeto UE5.

Conceitos do Código Original

DataServerProtocolCore – despacho de pacotes de personagem
📘 O Que é?

Função central que roteia pacotes recebidos pelo DataServer para handlers específicos, incluindo operações de lista e carga de personagem.

switch(head)
{

🎯 Para Que Serve?

Coordena a persistência: o GameServer envia cabeçalhos 0x01–0x04 e o DataServer responde com listas, criação, remoção ou dados completos do personagem.

Atualiza o tempo do socket e, dependendo do head, invoca o handler que consulta o banco e envia a resposta.

CQueryManager – conexão ODBC e execução de queries
📘 O Que é?

Classe singleton do DataServer que gerencia handles ODBC e executa queries parametrizadas com tratamento de erro e reconexão.

bool CQueryManager::Connect(char* odbc,char* user,char* pass) {
    strcpy_s(this->m_odbc,odbc);
    if(SQL_SUCCEEDED(SQLAllocHandle(SQL_HANDLE_DBC,this->m_SQLEnvironment,&this->m_SQLConnection)) == 0)
        return 0;
    if(SQL_SUCCEEDED(SQLConnect(this->m_SQLConnection,(SQLCHAR*)this->m_odbc,SQL_NTS,(SQLCHAR*)this->m_user,SQL_NTS,(SQLCHAR*)this->m_pass,SQL_NTS)) == 0)
        return 0;
    if(SQL_SUCCEEDED(SQLAllocHandle(SQL_HANDLE_STMT,this->m_SQLConnection,&this->m_STMT)) == 0)
        return 0;
    else return 1;
}

🎯 Para Que Serve?

Abstrai o acesso ao banco: abre conexão, executa ExecQuery, faz bind de colunas e reconecta em caso de falha, alimentando todos os handlers do DataServer.

💻 Como Funciona?

Recebe uma query formatada, executa com SQLExecDirect e mapeia resultados em buffers de colunas; se houver erro, chama Diagnostic e tenta reconectar em códigos 08S01.

bool CQueryManager::ExecQuery(char* query,...) {
    vsprintf_s(buff,query,arg);
    if(SQL_SUCCEEDED((result=SQLExecDirect(this->m_STMT,(SQLCHAR*)buff,SQL_NTS))) == 0 && result != SQL_NO_DATA) {
        this->Diagnostic(buff);
        return 0;
    }
    SQLRowCount(this->m_STMT,&this->m_RowCount);
    SQLNumResultCols(this->m_STMT,&this->m_ColCount);
    for(int n=0;n < this->m_ColCount;n++) {
        SQLDescribeCol(this->m_STMT,(n+1),this->m_SQLColName[n],...);
        SQLBindCol(this->m_STMT,(n+1),SQL_C_CHAR,this->m_SQLData[n],sizeof(this->m_SQLData[n]),&this->m_SQLDataLen[n]);
    }
    return 1;
}

⏱️ Quando é Executado?

Chamado por todos os handlers de persistência (ex.: GDCharacterInfoRecv) antes de montar respostas. A conexão inicial ocorre no boot do DataServer e permanece enquanto o processo estiver ativo.

Guia Blueprint detalhado (VaRest + SQL + DataTables)

Objetivo: iniciante replicar o fluxo do DataServer sem C++, usando Blueprints, VaRest e tabelas SQL.

  1. Preparar o backend: suba um serviço Node.js com endpoints /character/list, /character/create, /character/delete, /character/info. Cada rota executa queries SQL equivalentes (tabela Character com colunas Name, Class, Level, Strength, Dexterity, Vitality, Energy, Map, X, Y, InventoryBlob).
  2. No UE5, crie Blueprint Function Library BP_SQLBridge com funções:
    • SendCharacterList (Inputs: Account String) → usa Create VaRestRequest (POST) para /character/list, Set Request Body (JSON) com account e authToken, chama Process URL. No OnRequestComplete, chama DecodeCharacterList.
    • DecodeCharacterList: use Get Response Object → Get Field Array (Characters) e preencha um DataTable (RowStruct FCharacterRow) via Add Data Table Row. Dispare OnCharacterListReady (Dispatcher).
    • SendCharacterInfo (Inputs: CharName) similar, chamando /character/info e salvando os campos em SaveGame SG_Character (atributos + InventoryBlob base64).
  3. Monte um GameInstance Blueprint (BP_GI_Persistence):
    • No Event Init, defina BaseURL (http://127.0.0.1:3003) e carregue AuthToken salvo.
    • Crie eventos RequestList, RequestCreate, RequestDelete e RequestInfo chamando as funções de BP_SQLBridge. Conecte o dispatcher OnCharacterListReady a um Widget (BP_SelectCharacter).
    • Para RequestCreate, use Create VaRestRequest (POST) em /character/create com campos do formulário (nome, classe inicial). Se erro, exiba Text vermelho; se sucesso, re-chame RequestList para refrescar.
  4. HUD amigável para iniciantes:
    • Crie widget BP_SelectCharacter com ListView (personagens) e botões "Criar", "Apagar", "Entrar".
    • No Event Construct do widget, ligue RequestList. Ao selecionar item da lista, preencha painel de atributos (TextBlocks para STR/DEX/VIT/ENE, Level, Map, Coordenadas).
    • Botão Criar: abre modal BP_CreateChar com campos Name, Class. No botão OK, chama RequestCreate.
    • Botão Apagar: chama Create VaRestRequest em /character/delete com confirmação (caixa de diálogo) e, no sucesso, recarrega lista.
    • Botão Entrar: chama RequestInfo e, ao receber SG_Character, faz Open Level com Options contendo ?CharName=... para persistir.
  5. Persistência de inventário no SaveGame:
    • Crie struct FInventorySlot (ItemId, Durability, SocketData, ExcellentFlags).
    • Em DecodeCharacterInfo, pegue InventoryBlob (base64) → VaRest Base64 Decode → armazene em Array of FInventorySlot no SG_Character.
    • Antes de deslogar, chame Create VaRestRequest (POST) em /character/save com o mesmo blob (re-encode base64). Assim espelha o envio 0x04 do DataServer.
  6. Checklist visual (adicione no widget BP_SelectCharacter):
    • Caixa 1: "Conectei ao serviço" → fica verde quando OnRequestComplete retorna 200.
    • Caixa 2: "Listei personagens" → verde quando a ListView tem > 0 itens.
    • Caixa 3: "Criei personagem" → verde após chamada de criação bem-sucedida.
    • Caixa 4: "Carreguei inventário" → verde quando SG_Character.Inventory receber slots.
  7. Teste guiado: desligue o serviço SQL e clique em "Listar". Confirme que o widget mostra aviso em vermelho e o botão "Tentar Novamente" refaz o POST quando o serviço voltar, simulando o retry/reconexão do DataServer.
GDCharacterInfoRecv – carga completa do personagem
📘 O Que é?

Handler que consulta a tabela Character e retorna ao GameServer todos os atributos, inventário, quests e resets de um personagem.

pMsg.result = ((CheckTextSyntax(lpMsg->name,sizeof(lpMsg->name))==0)?0:1);
if(pMsg.result == 0 || gQueryManager.ExecQuery("SELECT * FROM Character WHERE AccountID='%s' AND Name='%s'",lpMsg->account,lpMsg->name) == 0 || gQueryManager.Fetch() == SQL_NO_DATA) {
    pMsg.result = 0;
} else {
    pMsg.Level = (WORD)gQueryManager.GetAsInteger("cLevel");
    pMsg.Class = (BYTE)gQueryManager.GetAsInteger("Class");
    gQueryManager.GetAsBinary("Inventory",pMsg.Inventory[0],sizeof(pMsg.Inventory));
    pMsg.Map = (BYTE)gQueryManager.GetAsInteger("MapNumber");
    pMsg.X = (BYTE)gQueryManager.GetAsInteger("MapPosX");
    pMsg.Y = (BYTE)gQueryManager.GetAsInteger("MapPosY");
    gQueryManager.ExecQuery("UPDATE AccountCharacter SET GameIDC='%s' WHERE Id='%s'",lpMsg->name,lpMsg->account);
}
gSocketManager.DataSend(index,(BYTE*)&pMsg,sizeof(pMsg));

🎯 Para Que Serve?

Entrega ao GameServer um snapshot completo do personagem selecionado, validando nome e preenchendo campos de estatística, posição, inventário e efeitos ativos.

💻 Como Funciona?

Valida sintaxe do nome, executa SELECT, converte colunas binárias (inventário, skill, quests) e busca resets adicionais com stored procedures (WZ_GetResetInfo e WZ_GetMasterResetInfo). Atualiza o campo GameIDC antes de enviar via gSocketManager.DataSend.

Implementação em Unreal Engine 5

Para reproduzir a persistência em UE5 com VaRest e Node.js, separe a lógica de banco em um serviço web (Node) que expõe endpoints equivalentes aos handlers do DataServer.

  • Node.js + SQL: crie um serviço Express que execute queries SQL (ex.: mysql2 ou mssql) para carregar personagem, inventário e resets.
  • VaRest no UE5: use UVaRestRequestJSON para chamar os endpoints e popular um USTRUCT com os campos de personagem.
  • Replicação/segurança: mantenha a validação de nome/conta no backend (equivalente a CheckTextSyntax) e somente aplique mudanças no GameState após resposta positiva.
USTRUCT(BlueprintType)
struct FCharacterSnapshot {
    GENERATED_BODY()
    UPROPERTY(BlueprintReadOnly) int32 Level;
    UPROPERTY(BlueprintReadOnly) int32 Class;
    UPROPERTY(BlueprintReadOnly) TArray Inventory;
    UPROPERTY(BlueprintReadOnly) FVector2D Position;
};

UCLASS()
class UMuPersistenceComponent : public UActorComponent {
    GENERATED_BODY()
public:
    UFUNCTION(BlueprintCallable)
    void RequestCharacter(const FString& Account, const FString& Name) {
        auto* Request = UVaRestLibrary::ConstructVaRestRequest(this, EVaRestRequestVerb::GET, EVaRestRequestContentType::json);
        Request->SetURL(FString::Printf(TEXT("http://localhost:3000/character/info?account=%s&name=%s"), *Account, *Name));
        Request->OnRequestComplete.AddDynamic(this, &UMuPersistenceComponent::OnCharacterResponse);
        Request->ProcessRequest();
    }
private:
    UFUNCTION()
    void OnCharacterResponse(UVaRestRequestJSON* Req, bool bSuccess) {
        if(!bSuccess) return;
        FCharacterSnapshot Snapshot;
        Snapshot.Level = Req->GetResponseObject()->GetIntegerField("Level");
        Snapshot.Class = Req->GetResponseObject()->GetIntegerField("Class");
        // preencher inventário e posição conforme JSON
    }
};

// Node.js (Express) – rota equivalente a GDCharacterInfoRecv
app.get('/character/info', async (req,res) => {
  const {account, name} = req.query;
  const [rows] = await pool.query('SELECT * FROM Character WHERE AccountID=? AND Name=?',[account,name]);
  if(!rows.length) return res.status(404).json({result:0});
  const row = rows[0];
  res.json({
    result: 1,
    Level: row.cLevel,
    Class: row.Class,
    Map: row.MapNumber,
    MapPosX: row.MapPosX,
    MapPosY: row.MapPosY,
    Inventory: row.Inventory,
    Reset: row.Reset
  });
});

Passo a Passo em Unreal Engine 5

  1. Configurar um serviço Node.js com conexão SQL (ODBC ou driver nativo) que exponha endpoints para lista/criação/carga de personagem (espelhando cabeçalhos 0x01–0x04) e warehouse.
  2. Versionar scripts SQL/migrations que criam tabelas equivalentes às do DataServer (Character, Warehouse, Guild, AccountData) e popular dados de teste.
  3. No UE5, adicionar o plugin VaRest e criar um UActorComponent responsável por fazer requisições HTTP (GET/POST) ao Node.js, com headers de autenticação.
  4. Mapear o JSON retornado para structs UE (FCharacterSnapshot, FInventorySlot) e aplicar os dados no AGameState ou diretamente no ACharacter.
  5. Implementar cache local/segurança equivalente aos checks de CheckTextSyntax e bloqueio de slots (GameIDC), rejeitando nomes inválidos antes de chamar o backend.
  6. Garantir que a gravação (reset, inventário) use endpoints POST/PUT que executem procedures equivalentes a WZ_GetResetInfo e atualizações de inventário; validar sucesso via códigos HTTP.
  7. Adicionar camadas de retry e backoff no VaRest para erros HTTP/SQL, registrando falhas em log persistente e expondo estado (conectado/offline) na UI.
  8. Implementar testes automatizados que comparam um binário de inventário salvo pelo servidor original com o JSON retornado pelo serviço Node.js, garantindo correspondência de slots e quantidades.
  9. Documentar o contrato REST (método, rota, parâmetros, exemplos) em um arquivo incluído no projeto para consulta rápida e exposição na UI de debug.
  10. Mapear procedures SQL usadas pelo DataServer (ex.: WZ_GetResetInfo, WZ_GetWarehouse) para consultas parametrizadas em Node.js, validando tipos e limites e retornando erros padronizados.
  11. Criar um modo offline em UE5 que usa SQLite/local JSON para espelhar respostas do DataServer, permitindo testes sem conexão e fallback quando o backend estiver indisponível.
  12. Automatizar backups do banco e sincronização com ambiente de teste, registrando versão do schema no cliente para detectar incompatibilidades.

Checklist Final

  • Node.js expõe endpoints REST que correspondem aos handlers do DataServer (lista, criação, deleção e carga de personagem).
  • VaRest no UE5 consegue solicitar e receber dados completos do personagem, preenchendo estatísticas e inventário.
  • Consultas SQL reproduzem campos e procedimentos usados pelo DataServer original (inventário binário, resets, posição).
