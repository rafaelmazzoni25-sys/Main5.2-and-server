Módulo 53 – Enums e Catálogos de Animação (Personagem e Mobs)

Lista e separa todos os enums/índices de animação do código C++ legado para personagens e monstros, com instruções de replicação 1:1 em AnimBlueprints, DataTables e Montages na Unreal Engine 5.

Enums de Animação – Personagem (Action_t)

Em ZzzBMD.h e CharacterManager.cpp os personagens usam índices fixos no array Actions:

  • 0: Stand (PLAYER_STOP) – loop parado.
  • 1: Walk (PLAYER_WALK) – movimento básico.
  • 2: Run (PLAYER_RUN) – com haste/boots.
  • 3: Attack1 (PLAYER_ATTACK1) – ataque leve.
  • 4: Attack2 (PLAYER_ATTACK2) – ataque forte / skill melee.
  • 5: SpellCast (PLAYER_MAGIC1) – cast de skill.
  • 6: TakeHit (PLAYER_HIT).
  • 7: Die (PLAYER_DIE).
  • 8: Sit (PLAYER_SIT).
  • 9: Pose/Win (PLAYER_POSE).

Algumas classes acrescentam variações (ex.: PLAYER_BOW para Elf, PLAYER_POISON para Magic Gladiator).

Enums de Animação – Mobs (MonsterID + ActionIndex)

Os monstros compartilham convenção similar no array BMD::Actions:

  • 0: Idle (MONSTER_STAND).
  • 1: Walk (MONSTER_WALK).
  • 2: Run (MONSTER_RUN) quando há perseguição.
  • 3: Attack1 (MONSTER_ATTACK1).
  • 4: Attack2 (MONSTER_ATTACK2) – usado por bosses.
  • 5: Special (MONSTER_SPECIAL) – skills únicas.
  • 6: Hit (MONSTER_HIT).
  • 7: Die (MONSTER_DIE).

IDs específicos de monstros são definidos em MonsterID.h (MONSTER_BULL_FIGHTER, MONSTER_DRAGON, etc.) e combinados com a tabela BMD::Actions para carregar o gráfico correto.

Catálogos de Animação (Arquivos)

  • Personagem: Player\Player.bmd, Player\DL\DarkLord.bmd, Player\MG\MagicGladiator.bmd – cada um com array Actions[10] preenchido.
  • Monstros: Data\Monster\*.bmd (ex.: BullFighter.bmd, Skeleton.bmd, GoldenDragon.bmd), cada qual com Actions e Sounds[10].
  • Montagens de Skill: alguns BMDs incluem ações extras indexadas (>7) para skills especiais de boss (ex.: SELUPAN_FROST, MAYA_SUMMON).

Replicação 1:1 na UE5

  1. DataTable de Ações de Personagem: Crie DT_PlayerActions com colunas ActionIndex, Name, Montage, PlaySpeed, Loop, SoundId. Preencha seguindo os índices acima para cada classe. Diferencie arcos/armas com colunas WeaponType.
  2. DataTable de Ações de Mobs: Crie DT_MonsterActions (RowName = MonsterID). Colunas: ActionIndex, Montage/Skeleton, PlaySpeed, SoundId, FXOverride. Preencha usando os BMD convertidos.
  3. AnimBP do Personagem: Na State Machine, mapeie ActionIndex replicado do servidor para estados (Idle/Walk/Run/Attack1/Attack2/Hit/Die). Use BlendSpace para Walk/Run. No evento OnActionChanged, faça Get Data Table Row de DT_PlayerActions → Play Montage.
  4. AnimBP de Mobs: Use variável CurrentActionIndex replicada pelo BP_MonsterAI. Transições simples: Idle → Walk → Attack1/Attack2 → Hit → Die. Vincule sons via AnimNotify_PlaySoundId lendo DT_MonsterActions.
  5. Conversão de BMD para FBX: Para cada BMD, converta para FBX mantendo nomes das ações. Importe como Skeletal Mesh + Animation Sequence em /Game/MU/Characters e /Game/MU/Monsters. Certifique-se de marcar Use T0 As Ref Pose quando necessário para evitar offsets.
  6. PlaySpeed e Root Motion: Preserve Action_t.PlaySpeed em Rate Scale das montagens. Desative Root Motion para ações baseadas em deslocamento server-authoritative (Walk/Run/Attack), mantendo somente em golpes que precisam (dash de mobs específicos).
  7. Validação 1:1: Crie um mapa de teste com BP_MuCharacter e três mobs. Ciclo por todos os ActionIndex com um painel de debug (botões UI). Compare duração/velocidade com o cliente legado; ajuste PlaySpeed nas tabelas até coincidir.

Checklist Final

  • Enums de personagem (0–9) e variações específicas documentados e mapeados em DT_PlayerActions.
  • Enums de mob (0–7) para todos os MonsterID preenchidos em DT_MonsterActions.
  • Montagens importadas dos FBXs convertidos dos BMDs com PlaySpeed igual ao Action_t original.
  • AnimNotifies ligados ao BP_AudioRouter e aos efeitos de skill.
