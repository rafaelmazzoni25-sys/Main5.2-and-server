Módulo 21 – Kanturu (Maya & Nightmare)

Recrie o evento Kanturu, cobrindo leitura de script, máquina de estados, entrada de jogadores e transição para a Tower of Refinement.

Conceitos do Código Original

CKanturu::Load – Máquina de estados via script
📘 O Que é?

Método que lê Kanturu.dat e popula os estados/condições do evento antes do ciclo principal.
Exemplo real:

void CKanturu::Load(char* path) {
    CMemScript* lpMemScript = new CMemScript;
    ...
    this->ResetAllData();
    while(true) {
        if(lpMemScript->GetToken() == TOKEN_END) break;
        int section = lpMemScript->GetNumber();
        while(true) {
            if(section == 0) {
                if(strcmp("end",lpMemScript->GetAsString()) == 0) break;
                int state = lpMemScript->GetNumber();
                int condition = lpMemScript->GetAsNumber();
                int value = lpMemScript->GetAsNumber();
                this->m_StateInfo[this->m_StateInfoCount].SetStateInfo(state);
                this->m_StateInfo[this->m_StateInfoCount].SetCondition(condition);
                this->m_StateInfo[this->m_StateInfoCount].SetValue(((condition==1)?(value*1000):value));
                this->m_StateInfoCount++;
            }
            else if(section == 10) {
                if(strcmp("end",lpMemScript->GetAsString()) == 0) break;
                this->SetEnableCheckMoonStone(lpMemScript->GetNumber());
            }
            else { if(strcmp("end",lpMemScript->GetAsString()) == 0) break; }
        }
    }
    this->m_BattleStanby.Load(path);
    this->m_BattleOfMaya.Load(path);
    this->m_BattleOfNightmare.Load(path);
    this->m_TowerOfRefinement.Load(path);
}

🎯 Para Que Serve?

Carrega a sequência de fases (Standby, Maya, Nightmare, Tower) e configurações adicionais como checagem de MoonStone, preparando os subcontroladores de cada fase.

💻 Como Funciona?

Aloca CMemScript, lê tokens do arquivo, identifica seções, preenche m_StateInfo com estado/condição/valor (convertendo segundos em milissegundos quando necessário) e delega Load para os gerentes de subfase.

this->m_BattleStanby.Load(path);
this->m_BattleOfMaya.Load(path);
this->m_BattleOfNightmare.Load(path);
this->m_TowerOfRefinement.Load(path);

CKanturu::MainProc – Ciclo de estados Maya/Nightmare
📘 O Que é?

Loop principal que verifica tempo de estado e chama os processadores de cada fase (Standby, Maya, Nightmare, Tower, End).

void CKanturu::MainProc() {
    if(gServerInfo.m_KanturuEvent == 0) return;
    this->CheckStateTime();
    switch(this->m_KanturuState) {
        case KANTURU_STATE_NONE: this->ProcState_NONE(); break;
        case KANTURU_STATE_BATTLE_STANTBY: this->ProcState_BATTLE_STANDBY(); break;
        case KANTURU_STATE_BATTLE_OF_MAYA: this->ProcState_BATTLE_OF_MAYA(); break;
        case KANTURU_STATE_BATTLE_OF_NIGHTMARE: this->ProcState_BATTLE_OF_NIGHTMARE(); break;
        case KANTURU_STATE_TOWER_OF_REFINEMENT: this->ProcState_TOWER_OF_REFINEMENT(); break;
        case KANTURU_STATE_END: this->ProcState_END(); break;
    }
}

🎯 Para Que Serve?

Orquestra a progressão do evento, avaliando o tempo e movendo jogadores/monstros entre subfases até finalizar e liberar a Tower of Refinement.

💻 Como Funciona?

Valida se o evento está habilitado, atualiza tempos com CheckStateTime e envia o fluxo para o handler adequado. Por exemplo, ao terminar Standby chama Maya; ao encerrar Maya decide entre END ou Nightmare.

void CKanturu::ProcState_BATTLE_OF_MAYA() {
    if(this->m_BattleOfMaya.GetBattleOfMayaState() == KANTURU_MAYA_ENDCYCLE) {
        this->m_BattleOfMaya.SetState_NONE();
        this->SetState(((this->m_BattleOfMaya.GetSuccessValue()==0)?KANTURU_STATE_END:KANTURU_STATE_BATTLE_OF_NIGHTMARE));
        return;
    }
    this->m_BattleOfMaya.MainProc();
}

Implementação em Unreal Engine 5

Use um AGameState dedicado para controlar Kanturu, com componentes para cada subfase. Armazene configurações em Data Assets ou tabelas CSV lidas via UDataTable. Integre VaRest para sincronizar com backend Node.js/SQL se precisar de agenda/estado persistente.

Passo a Passo em Unreal Engine 5

  1. Crie um UDataTable baseado em USTRUCT FKanturuStateRow contendo estado, condição e valor (ms). Importe o CSV equivalente ao Kanturu.dat.
  2. Implemente UKanturuPhaseComponent derivado de UActorComponent para Standby, Maya, Nightmare e Tower; cada um possui um FTimerHandle e callbacks para spawn de monstros.
  3. No AGameState (ex.: AMUKanturuState), carregue a tabela no BeginPlay, instancie os componentes e armazene um índice de fase atual.
  4. Processe o loop via Tick ou FTimerManager, trocando de fase conforme o valor do estado (igual ao CheckStateTime). Atualize UI e envie RPCs multicast para clientes.
  5. Para entrada de jogadores, exponha um Server RPC em APlayerController (ex.: Server_RequestEnterKanturu) que valida contagem máxima e mapa, similar a CKanturuBattleUserMng.
  6. Crie spawns de monstros via UDataTable de FMonsterSpawnRow; use GetWorld()->SpawnActor em cada componente de fase. Guarde referências para checar alive count e disparar transições.
  7. Se precisar de agenda diária, adicione um serviço Node.js que persiste horários em SQL e exponha endpoints REST. Chame com VaRest no GameInstance ao iniciar a sessão.

Checklist Final

  • Estados carregados de um CSV/Tabela reproduzindo Kanturu.dat.
  • Transições automáticas Standby → Maya → Nightmare → Tower/End com timers.
  • RPCs informam o estado atual para todos os jogadores no mapa Kanturu.
  • Spawns e contagem de monstros bloqueiam/desbloqueiam a progressão.
  • Validação de entrada e remoção de jogadores sincronizada entre servidor UE5 e backend REST/SQL, se usado.

Guia Blueprint Hiper Detalhado

Use este passo a passo sem depender de C++ para replicar Kanturu com VaRest e SQL.

Setup de Estruturas e DataTables

  1. No Content Browser, crie um Blueprint Struct BST_KanturuState com campos: State (Enum), Condition, ValueMs, SpawnGroupId, NextState. Salve em Content/Data/Kanturu/.
  2. Crie uma DataTable baseada no struct e importe um CSV com linhas que imitam Kanturu.dat: Standby 30000ms, MayaPhase1 120000ms, MayaPhase2 120000ms, Nightmare 180000ms, Tower 300000ms.
  3. Adicione outra DataTable DT_KanturuSpawns contendo Wave, MonsterId, Location (Vector), Rotation (Rotator), Count. Use coordenadas baseadas no mapa original (ex.: Maya Stage1: X=14500,Y=4300,Z=120).

GameState e Componentes

  1. Derive um BP_KanturuState de GameState e marque Replicates. Adicione variáveis replicadas: CurrentState (Enum), RemainingMs (int), CurrentWave (int), PlayersInside (array).
  2. Crie componente BP_KanturuPhaseComponent com função StartPhase(StateRow) que inicia um Set Timer by Event usando ValueMs/1000. Armazene referência no GameState.
  3. No BeginPlay do GameState, carregue a DataTable, coloque em Map StateId → Row e chame StartPhase com Standby.
  4. Eventos de transição: use Switch on Enum para Maya/Nightmare/Tower. Para cada transição, chame Multicast OnKanturuStateChanged repassando CurrentState e RemainingMs.

UI com Coordenadas

  1. Widget WBP_KanturuHUD (Canvas 1920x1080): timer no canto superior direito (X=1420,Y=70,W=320,H=60), barra de progresso embaixo (X=1420,Y=110,W=320,H=16). Use cor #FFB347 para Standby, #1E90FF para Maya, #FF4D4D para Nightmare.
  2. Adicione um painel de objetivos em (X=60,Y=200,W=360,H=260) com três linhas: “Destruir estátuas”, “Derrotar Maya”, “Derrotar Nightmare”. Cada linha tem um CheckBox ligado ao CurrentState (marca quando o state é ≥ correspondente).
  3. Para Tower of Refinement, adicione botão “Teleportar para Tower” em (X=60,Y=480,W=220,H=40). No OnClicked invoque Server_RequestTower.

Fluxo de Entrada e Validação

  1. No PlayerController, crie RPC Server_RequestEnterKanturu(TicketId). Valide se CurrentState está em Standby/Notify e se o jogador tem o item MoonStone (array de inventário replicado).
  2. Em caso positivo, use Teleport para o mapa de Kanturu (ex.: LevelStreaming /Game/Maps/Kanturu_P) e registre no array PlayersInside. Se falhar, mostre Client toast “Evento fechado ou ticket inválido”.
  3. Para Tower of Refinement, exponha Server_RequestTower que só permite quando CurrentState == Tower. Teleporte para a subárea e ativa Buff “Refinement” por 300s.

Persistência e VaRest

  1. Configure endpoint POST /api/kanturu/state para gravar state, remainingMs e players. No GameState, ao mudar de estado, faça VaRest Request JSON enviando esses campos.
  2. No fim da Nightmare, chame endpoint /api/kanturu/rewards com lista de playerName e score. No sucesso, atualize UI com o retorno (ex.: joias, exp).
  3. Mantenha tabela SQL KanturuRuns(Id, State, StartAt, EndAt, PlayersJson) para histórico.

Debug e Segurança

  • Adicione console command kanturu.force <State> (executado no servidor) que chama SetState no GameState para testes locais.
  • Use Draw Debug Box nos pontos de spawn vindos da DT_KanturuSpawns ao carregar cada wave.
  • Crie um widget debug (X=1560,Y=200,W=320,H=120) mostrando contagem de players e ovo/estátua restantes para validar fluxo como no servidor legado.
