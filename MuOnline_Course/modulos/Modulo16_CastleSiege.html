Módulo 16 – Castle Siege (Ciclo e Sincronização)

Explora a preparação, leitura de configuração e estado do evento Castle Siege, incluindo sincronização com NPCs e minimapa.

Pré-requisitos

  • Completar módulos 6, 8 e 13 para dominar timers, roteamento de pacotes e minimapa.
  • Conhecimento de replicação e RPCs em UE5.
  • Acesso a um backend SQL/Node.js para persistir estado do evento.

Conceitos do Código Original

Inicialização e limpeza – CCastleSiege::Clear
📘 O Que é?

Rotina que zera estado do evento, reseta controles de NPC, guilds, timers e flags de carregamento.

🎯 Para Que Serve?

Garante que cada ciclo de Castle Siege começa sem resíduos de dados anteriores, evitando inconsistências.

💻 Como Funciona?

void CCastleSiege::Clear() {
    this->m_bCastleSiegeEnable = TRUE;
    this->m_bFileDataLoadOK = FALSE;
    this->m_bDbDataLoadOK = FALSE;
    this->m_iMapSvrGroup = -1;
    this->m_iCastleSiegeCycle = 14;
    this->m_iCastleSiegeState = -1;
    memset(&this->m_tmFixCastleCycleStartDate,0,sizeof(this->m_tmFixCastleCycleStartDate));
    this->m_iCastleDataLoadState = 0;
    this->m_dwDbDataLoadTickCount = 0;
    this->m_iCS_REMAIN_MSEC = -1;
    this->m_bCsBasicGuildInfoLoadOK = FALSE;
    this->m_btIsCastleOccupied = 0;
    EnterCriticalSection(&this->m_critScheduleData); this->m_vtScheduleData.clear(); LeaveCriticalSection(&this->m_critScheduleData);
    EnterCriticalSection(&this->m_critNpcData); this->m_vtNpcData.clear(); LeaveCriticalSection(&this->m_critNpcData);
    this->m_bDbNpcCreated = FALSE;
}

Leitura de configuração – CCastleSiege::LoadPreFixData
📘 O Que é?

Carrega parâmetros do evento a partir de arquivo INI (ciclo, datas fixas, estado específico).

🎯 Para Que Serve?

Determina quando o Castle Siege deve iniciar, o estado inicial forçado e datas limites, validando contra a data atual.

💻 Como Funciona?

Criação/entrada do ciclo – CCastleSiege::Ready
📘 O Que é?

Configura o servidor alvo do evento e reseta NPCs antes de carregar dados.

🎯 Para Que Serve?

Define o Map Server Group que hospedará o Castle Siege e estabelece que o estado de dados deve ser recarregado.

💻 Como Funciona?

int CCastleSiege::Ready(int iMapSvrGroup) {
    if(iMapSvrGroup < 0) { return false; }
    this->Clear();
    this->ClearAllNPC();
    this->m_iMapSvrGroup = iMapSvrGroup;
    this->m_iCastleDataLoadState = 1;
    return true;
}

Implementação em Unreal Engine 5

  • Mapear o ciclo do evento para um AGameStateBase específico de Castle Siege com variáveis replicadas de datas e estado.
  • Usar UDataTable ou UDataAsset para carregar configurações (datas, ciclo) no BeginPlay do GameMode.
  • Criar um serviço Node.js que leia/escreva as janelas de evento em SQL; consumir via VaRest no servidor dedicado UE5 para alinhar datas.
  • NPCs e minimapa: spawnar AActors (gates, coroas) registrados em um subsistema de mini-mapa replicado.

Passo a Passo em Unreal Engine 5

  1. Criar classe ACastleSiegeState derivada de AGameStateBase com enum do estado atual, datas fixas e métodos ResetState() e ApplyConfig().
  2. No GameMode, chamar ResetState() ao iniciar o servidor dedicado, espelhando Clear para limpar arrays e flags replicadas.
  3. Implementar um carregador de config que consome JSON/INI via VaRest (chamada HTTP ao Node.js) e preenche ACastleSiegeState; validar datas locais antes de salvar.
  4. Adicionar RPC ServerSetMapGroup(int32 MapGroup) no GameMode para definir o servidor-alvo, resetar NPCs e marcar DataLoadState replicado.
  5. Agendar timers que avançam estados (REGSIEGE → REGMARK → ... → STARTSIEGE) e notificam UI via OnRep_State.
  6. Minimapa: registrar NPCs/gates em um UActorComponent que publica coordenadas para widgets; atualizar a cada mudança de estado.

Checklist Final

  • Estado do Castle Siege resetado e replicado para clientes.
  • Configurações carregadas de backend Node.js/SQL e aplicadas.
  • Timers de transição de estado ativos e notificando UI.
  • NPCs/gates spawnados e visíveis no minimapa replicado.
  • Possibilidade de definir Map Server Group via RPC seguro.
