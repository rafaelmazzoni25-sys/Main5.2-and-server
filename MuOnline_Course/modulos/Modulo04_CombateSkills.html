Checagens de ataque, regras de PvP e despacho de skills entre cliente e servidor.

Conceitos do Código Original

Servidor – Validação de ataque (CAttack::Attack)
📘 O Que é?

Função central que processa um ataque entre atacante e alvo, aplicando checagens de PvP, mapa e teleporte.

🎯 Para Que Serve?

Garante que somente ataques válidos avancem para cálculo de dano/efeitos, evitando exploits de posição ou estado.

💻 Como Funciona?

A função aborta se atacante e alvo são o mesmo índice ou não estão conectados. Também verifica se estão no mesmo mapa e se o atacante não está em teleporte. Em PvP, valida flags DisablePvp e, em duelos, zera o flag com aviso. Só depois disso o dano é calculado (trecho omitido).

bool CAttack::Attack(LPOBJ lpObj,LPOBJ lpTarget,CSkill* lpSkill,bool send,BYTE flag,int damage,int count,bool combo) {
    if(lpObj->Index == lpTarget->Index) return 0;

}

Servidor – Despacho de pacotes de combate (ProtocolCore)
📘 O Que é?

Mapa de comandos que direciona cabeçalhos de ataque/skill para os sistemas corretos.

🎯 Para Que Serve?

Conecta o input de rede aos sistemas de cálculo de dano e duração de skills.

💻 Como Funciona?

No switch principal, PROTOCOL_CODE2 chama gAttack.CGAttackRecv; 0x19 aciona gSkillManager.CGSkillAttackRecv; 0x1B cancela skills e 0x1E trata skills de duração.

case PROTOCOL_CODE2:
    gAttack.CGAttackRecv((PMSG_ATTACK_RECV*)lpMsg,aIndex);
    break;
case 0x19:
    gSkillManager.CGSkillAttackRecv((PMSG_SKILL_ATTACK_RECV*)lpMsg,aIndex);
    break;
case 0x1B:
    gSkillManager.CGSkillCancelRecv((PMSG_SKILL_CANCEL_RECV*)lpMsg,aIndex);
    break;
case 0x1E:
    gSkillManager.CGDurationSkillAttackRecv((PMSG_DURATION_SKILL_ATTACK_RECV*)lpMsg,aIndex);
    break;

Passo a Passo em Unreal Engine 5

  1. Criar um componente de combate server-only (UCombatValidatorComponent) para validar alvos (mapa, PvP, distância) antes de aplicar dano.
  2. Mapear comandos de ataque/skill para RPCs no APlayerController ou AbilitySystemComponent, espelhando as mensagens de GCDamageSend.
  3. Modelar tabela de skills em DataTable com custo, alcance, animações e efeitos correspondentes ao gSkillManager; carregar no GameMode.
  4. Implementar filas de ataque e cancelamento/skills de duração com tarefas do GAS ou timers, replicando flags de SpecialSkill quando apropriado.
  5. Validar cooldowns no servidor e replicar apenas flags de disponibilidade para o cliente; recusar spam com logs que indiquem o motivo.
  6. Sincronizar estados de animação usando Montage + notifies para disparar partículas no momento correto, disparando eventos de dano no notify para coincidir com o servidor.
  7. Replicar resultados (dano, efeitos) para clientes afetados via Multicast ou OnRep, incluindo número de acertos e resistências.
  8. Criar feedback em UI (floating text, ícones) que represente AttackDamage e status (stun, slow) retornados pelo servidor.
  9. Registrar hooks de auditoria: quando um ataque for rejeitado (alvo incorreto, mapa proibido), gravar o motivo em arquivo/HTTP (VaRest) para análise.
  10. Adicionar testes de regressão que enviam pacotes de ataque falsos e garantem rejeição conforme regras do servidor original, incluindo limites de velocidade de ataque.
  11. Expor comandos de console para spawnar um dummy e testar DPS, garantindo que os valores batem com a tabela de skills.
  12. Documentar a matriz de interação (PvE, PvP, eventos) e validar manualmente em uma sessão multiplayer local.

Guia Blueprint minucioso (combate)

  1. Montar UI de combate
    • No WB_HUD, adicione barra de HP (Width=280, Height=24) em (42,620) e MP em (42,652); texto de alvo em (360,600) exibindo nome e HP do inimigo.
    • Crie uma Hotbar de 8 botões 64x64 alinhados em X=460..920, Y=660. Nomeie de Btn_Skill1 … Btn_Skill8 e vincule OnClicked para evento OnHotbarPressed(Index).
    • Adicione widget flutuante WB_DamageText (TextBlock vermelho 24pt) para spawnar sobre o alvo.
  2. Blueprint de validação server-side
    • No PlayerState, adicione componente BP_CombatValidator. Variáveis: DisablePvp (bool), IsTeleporting (bool), LastAttackTime (float).
    • Função CanAttack(Target): checa se Target != Self, ambos conectados (IsValid), mapa igual (variável MapID replicada) e IsTeleporting == false. Se PvP e DisablePvp true, retorna falso e envia log VaRest /combat/reject com motivo.
    • Adicione checagem de intervalo: Now - LastAttackTime >= AttackSpeed; se não, set Text “Velocidade inválida” no HUD debug.
  3. RPCs de ataque/skill
    • No Character BP, crie evento Server_Attack(Target) (Server, Reliable). Primeira linha: Branch CanAttack. Se falso, retorne.
    • Calcule dano simples: pegue DataTable DT_Skills linha BasicAttack, some Strength + WeaponDamage. Subtraia Target.Defense. Garanta Max(Dano,1).
    • Set LastAttackTime = Now, aplique Apply Damage no Target, depois chame Multicast_OnHit(Target,Dano).
  4. Skills com duração e cancelamento
    • Para skill de canalização, crie AbilityTask_WaitDelay 3s que a cada 0.5s chama Apply Damage. Guarde Handle_Cast e cancele se receber SkillCancel.
    • Implemente evento Server_CancelSkill (Server, Reliable) ligado ao botão direito do mouse. Ao cancelar, invalide o timer e chame Multicast_StopFX para esconder partículas.
    • Para efeitos em área, use Sphere Overlap Actors com raio 280 UU e filtre por Team. Replique apenas lista de atingidos (índices) para economizar banda.
  5. Feedback visual replicado
    • No Multicast_OnHit, toque Montage de impacto, spawn de partícula no socket “hand_r” e crie WB_DamageText posicionado com Project World to Screen.
    • Se o ataque for rejeitado, mostre texto amarelo “Bloqueado” e reproduza som curto (UI_Error).
    • Logue cada ataque em VaRest endpoint /combat/log com JSON {attacker, target, skillId, dano, mapa} para cruzar com SQL.
  6. Checklist para iniciantes
    • Botão “Testar DPS” no HUD cria dummy com 5.000 HP em frente ao jogador.
    • Sem alvo selecionado, hotbar pisca em vermelho e texto “Selecione um alvo” aparece.
    • Quando PvP bloqueado, borda da tela fica cinza por 1s e aviso “PvP desabilitado no mapa”.
    • Cooldown visível: cada botão mostra cronômetro regressivo sobreposto (texto branco).

Mapa de animações e sons (legado → UE5)

  • Ações de ataque do jogador: o código C++ mapeia golpes para enums PLAYER_ATTACK_* e PLAYER_ATTACK_SKILL_* (ex.: PLAYER_ATTACK_SWORD_RIGHT1, PLAYER_ATTACK_TWO_HAND_SWORD1, PLAYER_ATTACK_SKILL_SWORD5) definidos em _enum.h. Crie DT_PlayerAttackAnim (ActionId, WeaponType, AnimMontage, HitNotifyName) e, no AnimBP_MuCharacter, selecione o montage conforme ActionId. Use AnimNotify HitWindow para disparar o evento de dano no frame exato em que o pacote do servidor valida o ataque.
  • Skills e transições especiais: para ações como PLAYER_ATTACK_SKILL_WHEEL, PLAYER_ATTACK_SKILL_FURY_STRIKE e PLAYER_SKILL_HELL_START, configure Montages com root motion desativado (para manter o servidor autoritativo) e blend times curtos. Acrescente AnimNotifies nomeados Cast_Start/Cast_End para alinhar partículas e cooldowns; se o servidor cancelar a skill, chame Montage Stop usando o mesmo ActionId.
  • Sons de armas e impacto: os índices SOUND_BRANDISH_SWORD01..04, SOUND_ATTACK01, SOUND_EXPLOTION01 e as variações de arco/besta (SOUND_BOW01, SOUND_CROSSBOW01) estão definidos em DSPlaySound.h. Monte um DataTable DT_ActionAudio (ActionId, SoundCue) e associe o SoundCue ao AnimNotify de swing/impacto. Para gritinhos de dano, inclua SOUND_HUMAN_SCREAM0*/SOUND_FEMALE_SCREAM0* e toque-os quando o Character receber dano crítico.
  • Mobs: animação + som em ataque: reaproveite os IDs MONSTER01_ATTACK1/2/3 e MONSTER01_DIE de _define.h para preencher DT_MobAnimations (ActionId, AnimSequence, SoundCue). No AnimBP_Mob, cada notify AttackImpact deve tocar SoundCue derivado do índice armazenado em BMD.Sounds, mantendo o comportamento do cliente original.

Checklist Final

  • Skills são despachadas para lógica correta e podem ser canceladas.
  • Feedback visual/sonoro é replicado para todos os clientes relevantes.
  • Logs confirmam entrada de comandos de combate e aplicação de dano.
