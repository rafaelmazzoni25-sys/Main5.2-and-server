CImperialGuardian::Load – Horários e dificuldade
📘 O Que é?

Lê ImperialGuardian.dat para configurar tempos de notificação/evento/fechamento e parâmetros de IA/dificuldade de monstros.

void CImperialGuardian::Load(char* path) {
    #if(GAMESERVER_UPDATE>=501)
    CMemScript* lpMemScript = new CMemScript;
    if(lpMemScript->SetBuffer(path) == 0) { ... }
    while(true) {
        if(lpMemScript->GetToken() == TOKEN_END) break;
        int section = lpMemScript->GetNumber();
        while(true) {
            if(section == 0) {
                if(strcmp("end",lpMemScript->GetAsString()) == 0) break;
                this->m_NotifyTime = lpMemScript->GetNumber();
                this->m_EventTime = lpMemScript->GetAsNumber();
                this->m_CloseTime = lpMemScript->GetAsNumber();
            }
            else if(section == 1) {
                if(strcmp("end",lpMemScript->GetAsString()) == 0) break;
                this->m_DefaultMonsterAIUnitNumber = lpMemScript->GetNumber();
                this->m_SupportMonsterAIUnitNumber = lpMemScript->GetAsNumber();
            }
            else if(section == 2) {
                if(strcmp("end",lpMemScript->GetAsString()) == 0) break;
                IMPERIAL_GUARDIAN_MONSTER_DIFFICULT_INFO info;
                memset(&info,0,sizeof(info));
                info.Index = lpMemScript->GetNumber();
                info.Level = lpMemScript->GetAsNumber();
                info.Life = lpMemScript->GetAsFloatNumber();
                info.DamageMin = lpMemScript->GetAsFloatNumber();
                info.DamageMax = lpMemScript->GetAsFloatNumber();
                info.Defense = lpMemScript->GetAsFloatNumber();
                info.AttackSuccessRate = lpMemScript->GetAsFloatNumber();
                info.DefenseSuccessRate = lpMemScript->GetAsFloatNumber();
                if(info.Index >= 0 && info.Index < MAX_IG_MONSTER_DIFFICULT) {
                    this->m_MonsterDifficultInfo[info.Index] = info;
                }
            }
            else { break; }
        }
    }
    #endif
}

🎯 Para Que Serve?

Inicializa cronogramas diários do evento, associa AI default e suporte para mobs e registra a curva de dificuldade usada nas fases subsequentes.

💻 Como Funciona?

Processa seções numeradas: (0) tempos de notificação/evento/fecho; (1) unidades de AI para monstros; (2) matriz de dificuldade por índice, preenchendo campos de atributos usados no spawn.

CImperialGuardian::MainProc – Ciclo diário e gates
📘 O Que é?

Loop que calcula tempo restante, avança estados WAIT/PLAY e controla monstros e gates do evento.

void CImperialGuardian::MainProc() {
    #if(GAMESERVER_UPDATE>=501)
    DWORD elapsed = GetTickCount()-this->m_TickCount;
    if(elapsed < 1000) return;
    this->m_TickCount = GetTickCount();
    this->m_RemainTime = (int)(difftime(this->m_TargetTime,time(0))*1000);
    switch(this->m_State) {
        case IG_STATE_EMPTY: this->ProcState_EMPTY(); break;
        case IG_STATE_WAIT1: this->ProcState_WAIT1(); break;
        case IG_STATE_PLAY1: this->ProcState_PLAY1(); break;
        case IG_STATE_WAIT2: this->ProcState_WAIT2(); break;
        case IG_STATE_PLAY2: this->ProcState_PLAY2(); break;
        // ... demais estados até encerramento
    }
    #endif
}

🎯 Para Que Serve?

Sincroniza o relógio do evento, alterna períodos de espera e jogo, e garante spawn/limpeza de monstros além do bloqueio/desbloqueio de portões.

💻 Como Funciona?

Ignora processamento se menos de 1s passou, atualiza m_RemainTime com base em m_TargetTime e executa handlers de estado que criam monstros e gates. CleanUser/CleanMonster são usados na construção para zerar o mapa antes de iniciar.

CDoubleGoer::Load – Configuração multi-fase
📘 O Que é?

Lê DoubleGoer.dat para configurar tempos, AI de monstros e matriz de dificuldade para as várias fases de Double Goer.

🎯 Para Que Serve?

Define notificações, duração do evento, tempo de fechamento e atributos de monstros (por nível) usados em cada estágio.

💻 Como Funciona?

Segue a mesma abordagem de ImperialGuardian: seções 0/1/2 mapeiam tempos, IDs de AI e listas de dificuldade. Exemplo:

Implementação em Unreal Engine 5

Modele cada evento com um AGameState dedicado e componentes de fase. Use UDataTable para horários/dificuldade e RPCs para sincronizar com clientes. Utilize VaRest + Node.js + SQL para armazenar cronogramas e rankings.

Passo a Passo em Unreal Engine 5

  1. Crie UDataTable para FImperialGuardianConfig e FDoubleGoerConfig contendo tempos, IDs de AI e matrizes de atributo por nível.
  2. Implemente UImperialPhaseComponent e UDoubleGoerPhaseComponent com timers replicados, callbacks de spawn e referências aos gates/atores do mapa.
  3. No AGameMode, valide horário de entrada comparando FDateTime com os tempos carregados; rejeite conexões fora da janela e envie UI de aviso via Client RPC.
  4. Use UAbilitySystemComponent ou lógica customizada para aplicar dificuldade de monstros com base em info.Level/Life/Damage. Prefira Data Assets para tabelas de atributos.
  5. Para party, mantenha um UPartySessionComponent que guarda PartyId e replicação de membros, utilizado para entrada conjunta no evento.
  6. Integre VaRest para consultar um serviço Node.js que agenda o próximo evento e grava resultados em SQL. Em caso de falha, aplique fallback local usando SaveGame.
  7. Implemente UI progressiva (barras de tempo/gates) usando UMG; atualize via OnRep do estado atual e eventos multicast.

Checklist Final

  • Configurações de horário/AI importadas para tabelas UE5.
  • FSM de Imperial Guardian e Double Goer replicada com timers e gates.
  • Spawns de monstros ajustados pela dificuldade lida do script.
  • UI em clientes exibindo tempo restante, fase atual e status dos portões.
  • Persistência de resultados/agenda integrada a Node.js/SQL via VaRest.

Guia Blueprint Hiper Detalhado

Miniguia para iniciantes aplicarem Imperial Guardian e Double Goer somente com Blueprints.

Setup de Dados

  1. Crie o struct BST_IGSchedule contendo NotifySeconds, EventSeconds, CloseSeconds, GateLevel, MonsterAI_Default e MonsterAI_Support.
  2. Importe um CSV para DT_IGSchedule com 4 janelas diárias (00:30, 06:30, 12:30, 18:30) e os tempos correspondentes.
  3. Monte DT_IGMonsters com atributos por dificuldade (Index/Level/Life/Damage/Defense/AttackRate/DefenseRate) e posições de spawn: por exemplo mobs iniciais em X=12400,Y=5200,Z=120, elites em X=13600,Y=5200,Z=120.

Fluxo Blueprint

  1. Crie BP_IGState derivado de GameState com variáveis replicadas CurrentState (Idle/Notify/Open/Playing/Closing), RemainingSeconds, GateOpen (bool) e CurrentScheduleIndex.
  2. No BeginPlay, leia DT_IGSchedule, compare com Now (node Get Date Time) e arme timers para Notify. Use Switch on Enum em TickState para acionar Multicast OnStateChanged.
  3. Entrada: RPC Server_RequestIGEnter(Level) valida convite (item) e horário. Em sucesso, use Open Level (by Object Reference) para /Game/Maps/IG_Lv<Level> e posicione os players em PlayerStart (Y=5200) voltados para o portão.
  4. Spawns: em OnStatePlaying, faça ForEach na DT_IGMonsters filtrando por Level para Double Goer. Use Spawn Actor e aplique stats via Set Members in Struct em um componente MonsterStats.
  5. Fechamento: ao zerar RemainingSeconds ou derrotar boss, chame Client Travel de volta e dispare VaRest para registrar resultado.

HUD com Coordenadas

  1. Widget WBP_IGTimer (Canvas 1920x1080): barra de progresso em (X=70,Y=70,W=420,H=22) com três cores (amarelo=Notify, verde=Playing, cinza=Closing). Texto do estado em (X=70,Y=40) fonte 20.
  2. Painel de monstros em (X=70,Y=120,W=320,H=240) com ListView para Index/HP; atualize com eventos OnSpawned e OnDeath.
  3. Botão “Registrar Grupo” em (X=70,Y=380,W=240,H=40). OnClicked chama Server_RequestIGEnter; desabilite se CurrentState != Notify.

VaRest + SQL

  1. Endpoint GET /api/imperial/schedule para sincronizar horários na inicialização do servidor UE5.
  2. Endpoint POST /api/imperial/register com {level, partyMembers, scheduleIndex}; chame quando o líder clicar no botão.
  3. Endpoint POST /api/imperial/result com {level, duration, success, rewardList}; dispare em Closing e grave em tabela ImperialRuns.

Debug

  • Console command ig.force StateName (Server) que altera CurrentState e reinicia o timer.
  • Widget debug em (X=1500,Y=80,W=360,H=140) exibindo CurrentState, RemainingSeconds, GateOpen e índice de dificuldade.
  • Draw Debug Cylinder no portão (X=11800,Y=5200,Z=120, Raio=260) e Draw Debug Sphere nos spawns para alinhar com o mapa original.
