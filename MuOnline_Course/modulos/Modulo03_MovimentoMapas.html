Módulo 3 – Personagem e Movimentação

Sincronização de posição entre cliente e servidor, além de timers que processam movimentação.

Pré-requisitos

  • Ter lido os módulos 1 e 2.
  • Conhecimento básico de estruturas de personagem.

Conceitos do Código Original

Cliente – Aplicação de posição recebida (ReceiveMovePosition)
📘 O Que é?

Handler de rede do cliente que atualiza posição/target do personagem ao receber pacote de movimento.

🎯 Para Que Serve?

Sincroniza a posição local com o servidor, ajustando movimento, direção e efeitos (como bola com gravidade).

💻 Como Funciona?

O buffer é convertido em LPPRECEIVE_MOVE_POSITION. Busca o personagem pelo Key, atualiza campos de posição e, se for bola (MODEL_BALL), aplica física e efeitos sonoros/visuais.

void ReceiveMovePosition(BYTE* ReceiveBuffer) {
    LPPRECEIVE_MOVE_POSITION Data = (LPPRECEIVE_MOVE_POSITION)ReceiveBuffer;
    int Key = ((int)(Data->KeyH)<<8) + Data->KeyL;
    CHARACTER* c = &CharactersClient[FindCharacterIndex(Key)];
    OBJECT* o = &c->Object;
    if(o->Type == MODEL_BALL) {
        o->Gravity = 20.f;
        o->Direction[1] = (Data->PositionX-(c->PositionX))*400.f;
    }
    c->PositionX = Data->PositionX;
    c->PositionY = Data->PositionY;
    c->TargetX = Data->PositionX;
    c->TargetY = Data->PositionY;
}

Cliente – Envio de movimento com caminho (SendCharacterMoveNew)
📘 O Que é?

Função que compacta o caminho calculado pelo cliente em um buffer e envia para o servidor.

🎯 Para Que Serve?

Comunica ao servidor a intenção de deslocamento, codificando as direções numa sequência de nibbles (path).

💻 Como Funciona?

void CProtocolSend::SendCharacterMoveNew(..., unsigned char PathNum, unsigned char* PathX, unsigned char* PathY, ...){
    if (PathNum < 1) return;
    PMSG_MOVE_SEND pMsg = { 0 };
    if (PathNum >= MAX_PATH_FIND) { PathNum = MAX_PATH_FIND - 1; }
    pMsg.x = PathX[0];
    pMsg.y = PathY[0];
    BYTE Path[8]; ZeroMemory(Path, 8);
    for (int i = 1; i < PathNum; i++) {
        BYTE Dir = 0;
        for (int j = 0; j < 8; j++) {
            if (DirTable[j * 2] == (PathX[i] - PathX[i - 1]) && DirTable[j * 2 + 1] == (PathY[i] - PathY[i - 1])) {
                Dir = j; break;
            }
        }
        if (i % 2 == 1) Path[(i + 1) / 2] = Dir << 4; else Path[(i + 1) / 2] += Dir;
    }
    Path[0] += (BYTE)(PathNum - 1);
    memcpy(pMsg.path, Path, sizeof(pMsg.path));
    SendPacket(ProtocolHead::BOTH_MOVE,(uint8_t*)&pMsg,sizeof(pMsg));
}

Servidor – Timers de movimentação (QueueTimerCallback)
📘 O Que é?

Callback usado pelos timers do servidor para processar lógica periódica, incluindo movimentação de monstros.

🎯 Para Que Serve?

Separa tarefas de processamento (IA, movimento, eventos, viewport) em timers independentes para manter o loop responsivo.

💻 Como Funciona?

O callback recebe qual timer disparou via lpParameter e executa funções como gObjectManager.ObjectMoveProc() ou CMonsterAI::MonsterMoveProc(), protegidas por CCriticalSection para evitar condições de corrida.

void CALLBACK QueueTimerCallback(PVOID lpParameter,BOOLEAN) {
    static CCriticalSection critical;
    critical.lock();
    switch(((int)lpParameter)) {
        case QUEUE_TIMER_MONSTER_MOVE:
            gObjectManager.ObjectMoveProc();
            break;
        case QUEUE_TIMER_MONSTER_AI_MOVE:
            CMonsterAI::MonsterMoveProc();
            break;
        case QUEUE_TIMER_VIEWPORT:
            gObjViewportProc();
            break;
    }
    critical.unlock();
}

Servidor – Processamento de movimento (ProtocolCore case 0x1C)
📘 O Que é?

Entrada da tabela de protocolos que lida com teleporte/movimento do jogador.

🎯 Para Que Serve?

Valida e executa pedidos de teleporte/movimento originados pelo cliente.

💻 Como Funciona?

O case 0x1C encaminha para gMove.CGTeleportRecv, onde são aplicadas regras de distância, consumo de recursos e atualização de mapa.

case 0x1C:
    gMove.CGTeleportRecv((PMSG_TELEPORT_RECV*)lpMsg,aIndex);
    break;

Implementação em Unreal Engine 5

  • Use ACharacter com CharacterMovementComponent para aplicar posições recebidas do servidor.
  • Implemente replicação de posição via ServerMove/ClientAdjustPosition já fornecidos pelo UE5, substituindo ReceiveMovePosition.
  • Timers de servidor podem ser reimplementados como FTimerHandle em AGameModeBase ou UWorld::GetTimerManager().
  • Teleporte pode ser realizado com RPC confiável em APlayerController chamando SetActorLocation no servidor.

Passo a Passo em Unreal Engine 5

  1. Configurar ACharacter com replicação de movimento habilitada e ativar bUseControllerRotationYaw conforme o estilo de câmera do cliente original.
  2. Criar um componente UMovementSyncComponent que traduz o pacote de posição em um RPC ClientAdjustPosition customizado, aplicando SetActorLocation e SetActorRotation.
  3. Implementar timers no AGameModeBase para IA/movimento de NPCs, disparando ServerMove em intervalos equivalentes aos SetTimer do servidor.
  4. Criar um UDataAsset que liste mapas válidos e suas restrições (safe zone, arena, eventos), refletindo a validação feita no servidor original antes de teleporte.
  5. Implementar teleporte via RPC confiável; validar mapa/destino contra o DataAsset, recarregar UNavigationSystemV1 e sincronizar com UI de loading.
  6. Usar UNavigationSystemV1 e ProjectPointToNavigation para ajustar coordenadas recebidas antes de aplicá-las, evitando atravessar colisores.
  7. Integrar eventos de colisão e estados de UI: quando inventário/loja estiver aberta, desabilitar input no CharacterMovementComponent e suspender envio de pacotes de movimento.
  8. Serializar o caminho em um array de nibbles (ou um TArray<uint8>) antes de enviar via RPC ServerMove, seguindo a lógica de Path e DirTable; logar o tamanho para depurar.
  9. Implementar predição de movimento no cliente e correção ao receber a posição oficial, atualizando o CharacterMovementComponent e interpolando para evitar rubber band.
  10. Gravar um histórico circular de posições em TQueue para comparar com a posição oficial e diagnosticar divergências, similar ao uso de RandomTable.
  11. Automatizar testes com Functional Testing ou Gauntlet: caminhar entre dois pontos, validar mesma posição no servidor e reproduzir logs de tempos.
  12. Adicionar testes de teleporte entre mundos e validação de obstáculos com LineTraceSingle, garantindo que o teleporte é autorizado apenas em locais permitidos.
  13. Exibir um painel de debug (Widget) com coordenadas locais e remotas, estado de predição e número de correções aplicadas.
  14. Para compatibilizar com VaRest/Node.js, opcionalmente registrar posições em um endpoint HTTP de telemetria para auditoria de trapaça.

Checklist Final

  • Personagem do cliente se move e sincroniza posição recebida do servidor.
  • NPCs/monstros atualizam movimento em intervalos configurados.
  • Teleporte entre mapas funciona com validação server-side.
  • Logs ou prints confirmam recebimento de pacotes de posição.
