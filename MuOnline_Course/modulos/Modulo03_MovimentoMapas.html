Módulo 3 – Personagem e Movimentação

Sincronização de posição entre cliente e servidor, além de timers que processam movimentação.

Pré-requisitos

  • Ter lido os módulos 1 e 2.
  • Conhecimento básico de estruturas de personagem.

Conceitos do Código Original

Cliente – Aplicação de posição recebida (ReceiveMovePosition)
📘 O Que é?

Handler de rede do cliente que atualiza posição/target do personagem ao receber pacote de movimento.

🎯 Para Que Serve?

Sincroniza a posição local com o servidor, ajustando movimento, direção e efeitos (como bola com gravidade).

💻 Como Funciona?

O buffer é convertido em LPPRECEIVE_MOVE_POSITION. Busca o personagem pelo Key, atualiza campos de posição e, se for bola (MODEL_BALL), aplica física e efeitos sonoros/visuais.

void ReceiveMovePosition(BYTE* ReceiveBuffer) {
    LPPRECEIVE_MOVE_POSITION Data = (LPPRECEIVE_MOVE_POSITION)ReceiveBuffer;
    int Key = ((int)(Data->KeyH)<<8) + Data->KeyL;
    CHARACTER* c = &CharactersClient[FindCharacterIndex(Key)];
    OBJECT* o = &c->Object;
    if(o->Type == MODEL_BALL) {
        o->Gravity = 20.f;
        o->Direction[1] = (Data->PositionX-(c->PositionX))*400.f;
    }
    c->PositionX = Data->PositionX;
    c->PositionY = Data->PositionY;
    c->TargetX = Data->PositionX;
    c->TargetY = Data->PositionY;
}

Cliente – Envio de movimento com caminho (SendCharacterMoveNew)
📘 O Que é?

Função que compacta o caminho calculado pelo cliente em um buffer e envia para o servidor.

🎯 Para Que Serve?

Comunica ao servidor a intenção de deslocamento, codificando as direções numa sequência de nibbles (path).

💻 Como Funciona?

void CProtocolSend::SendCharacterMoveNew(..., unsigned char PathNum, unsigned char* PathX, unsigned char* PathY, ...){
    if (PathNum < 1) return;
    PMSG_MOVE_SEND pMsg = { 0 };
    if (PathNum >= MAX_PATH_FIND) { PathNum = MAX_PATH_FIND - 1; }
    pMsg.x = PathX[0];
    pMsg.y = PathY[0];
    BYTE Path[8]; ZeroMemory(Path, 8);
    for (int i = 1; i < PathNum; i++) {
        BYTE Dir = 0;
        for (int j = 0; j < 8; j++) {
            if (DirTable[j * 2] == (PathX[i] - PathX[i - 1]) && DirTable[j * 2 + 1] == (PathY[i] - PathY[i - 1])) {
                Dir = j; break;
            }
        }
        if (i % 2 == 1) Path[(i + 1) / 2] = Dir << 4; else Path[(i + 1) / 2] += Dir;
    }
    Path[0] += (BYTE)(PathNum - 1);
    memcpy(pMsg.path, Path, sizeof(pMsg.path));
    SendPacket(ProtocolHead::BOTH_MOVE,(uint8_t*)&pMsg,sizeof(pMsg));
}

Servidor – Timers de movimentação (QueueTimerCallback)
📘 O Que é?

Callback usado pelos timers do servidor para processar lógica periódica, incluindo movimentação de monstros.

🎯 Para Que Serve?

Separa tarefas de processamento (IA, movimento, eventos, viewport) em timers independentes para manter o loop responsivo.

💻 Como Funciona?

O callback recebe qual timer disparou via lpParameter e executa funções como gObjectManager.ObjectMoveProc() ou CMonsterAI::MonsterMoveProc(), protegidas por CCriticalSection para evitar condições de corrida.

void CALLBACK QueueTimerCallback(PVOID lpParameter,BOOLEAN) {
    static CCriticalSection critical;
    critical.lock();
    switch(((int)lpParameter)) {
        case QUEUE_TIMER_MONSTER_MOVE:
            gObjectManager.ObjectMoveProc();
            break;
        case QUEUE_TIMER_MONSTER_AI_MOVE:
            CMonsterAI::MonsterMoveProc();
            break;
        case QUEUE_TIMER_VIEWPORT:
            gObjViewportProc();
            break;
    }
    critical.unlock();
}

Servidor – Processamento de movimento (ProtocolCore case 0x1C)
📘 O Que é?

Entrada da tabela de protocolos que lida com teleporte/movimento do jogador.

🎯 Para Que Serve?

Valida e executa pedidos de teleporte/movimento originados pelo cliente.

💻 Como Funciona?

O case 0x1C encaminha para gMove.CGTeleportRecv, onde são aplicadas regras de distância, consumo de recursos e atualização de mapa.

Implementação em Unreal Engine 5

  • Use ACharacter com CharacterMovementComponent para aplicar posições recebidas do servidor.
  • Implemente replicação de posição via ServerMove/ClientAdjustPosition já fornecidos pelo UE5, substituindo ReceiveMovePosition.
  • Timers de servidor podem ser reimplementados como FTimerHandle em AGameModeBase ou UWorld::GetTimerManager().
  • Teleporte pode ser realizado com RPC confiável em APlayerController chamando SetActorLocation no servidor.
UFUNCTION(Server, Reliable)

void AMyCharacter::ServerTeleport_Implementation(const FVector& Dest) {

Passo a Passo em Unreal Engine 5

  1. Configurar ACharacter com replicação de movimento habilitada e ativar bUseControllerRotationYaw conforme o estilo de câmera do cliente original.
  2. Criar um componente UMovementSyncComponent que traduz o pacote de posição em um RPC ClientAdjustPosition customizado, aplicando SetActorLocation e SetActorRotation.
  3. Implementar timers no AGameModeBase para IA/movimento de NPCs, disparando ServerMove em intervalos equivalentes aos SetTimer do servidor.
  4. Criar um UDataAsset que liste mapas válidos e suas restrições (safe zone, arena, eventos), refletindo a validação feita no servidor original antes de teleporte.
  5. Implementar teleporte via RPC confiável; validar mapa/destino contra o DataAsset, recarregar UNavigationSystemV1 e sincronizar com UI de loading.
  6. Usar UNavigationSystemV1 e ProjectPointToNavigation para ajustar coordenadas recebidas antes de aplicá-las, evitando atravessar colisores.
  7. Recriação de mapas 1:1: crie /Game/Maps/Lorencia_P.umap, /Game/Maps/Noria_P.umap, /Game/Maps/Devias_P.umap (um por mapa original). Cada um deve ter um LevelInstance para decoração e um subnível _Gameplay só com colisão e atores interativos.
  8. DataTable de gates: adicione DT_Gates (Struct FGateRow { int32 GateId; int32 MapId; int32 TargetMapId; FVector2D SourceXY; FVector2D TargetXY; FRotator TargetRot; }). Converta coordenadas do cliente original (tile) para UE5 multiplicando por 100 UU e invertendo o eixo Y (FVector(X * 100, -Y * 100, Z)) para respeitar a orientação diferente.
  9. Instanciamento dinâmico: no servidor dedicado, para cada conexão, carregue o mapa alvo com ULevelStreamingDynamic::LoadLevelInstance passando nome (MapId → caminho). Guarde o ponteiro em um mapa MapId → ULevelStreamingDynamic*; se não existir, carregue e povoar com atores (NPCs, mobs, gates) usando SpawnActorDeferred com transform derivado do CSV original.
  10. Spawn de objetos por gate: no BeginPlay do subnível _Gameplay, leia DT_Gates e crie BP_GateTrigger (Box Collision 300×300×400) em SourceXY. Associe variável TargetMapId/TargetXY/TargetRot no blueprint.
  11. Sincronização de orientação: o projeto C++ usa ângulo 0° para Norte; UE5 usa Y como "para frente". No teleporte, faça Make Rotator(Yaw = -TargetRot.Yaw) para inverter o sentido e alinhar com o minimapa original. Para mobs/NPCs, aplique a mesma correção ao instanciar.
  12. Persistência da posição do jogador (servidor dedicado): na classe AMuPlayerState crie FVector LastServerLocation e FRotator LastServerRotation marcados como ReplicatedUsing. Sempre que ServerMove validar um passo, atualize essas variáveis e chame um Event Dispatch (ex.: OnLocationUpdated) para disparar uma gravação assíncrona em BP_ServerPersistence usando VaRest/SQL (tabela Characters.PosX/PosY/PosZ/Rot). No logout ou ao atravessar um gate, execute a mesma gravação antes de destruir o pawn para garantir que o login seguinte carregue a posição correta.
  13. Integrar eventos de colisão e estados de UI: quando inventário/loja estiver aberta, desabilitar input no CharacterMovementComponent e suspender envio de pacotes de movimento.
  14. Serializar o caminho em um array de nibbles (ou um TArray<uint8>) antes de enviar via RPC ServerMove, seguindo a lógica de Path e DirTable; logar o tamanho para depurar.
  15. Implementar predição de movimento no cliente e correção ao receber a posição oficial, atualizando o CharacterMovementComponent e interpolando para evitar rubber band.
  16. Gravar um histórico circular de posições em TQueue para comparar com a posição oficial e diagnosticar divergências, similar ao uso de RandomTable.
  17. Automatizar testes com Functional Testing ou Gauntlet: caminhar entre dois pontos, validar mesma posição no servidor e reproduzir logs de tempos.
  18. Adicionar testes de teleporte entre mundos e validação de obstáculos com LineTraceSingle, garantindo que o teleporte é autorizado apenas em locais permitidos.
  19. Exibir um painel de debug (Widget) com coordenadas locais e remotas, estado de predição e número de correções aplicadas.
  20. Para compatibilizar com VaRest/Node.js, opcionalmente registrar posições em um endpoint HTTP de telemetria para auditoria de trapaça.

Guia Blueprint detalhadíssimo (clique a clique)

  1. Setup de movimento no Player
    • No Character Blueprint, habilite Replicates e Use Controller Rotation Yaw = true para câmera isométrica.
    • Abra o Graph e crie evento OnLeftMouseButton. Adicione Get Hit Result Under Cursor → Break Hit → Vector Hit Location.
    • Use AI Move To com Pawn Self e Destination = Hit Location. Marque Stop On Overlap e Acceptance Radius = 35 para imitar o clique clássico.
    • No Tick, leia CharacterMovement → Velocity e repasse para variável replicada DesiredVelocity para HUD de depuração.
  2. Serializar caminho em Blueprint
    • Crie um Function Library BP_PathCodec. Função EncodePath(Nodes: TArray) retorna TArray<uint8>.
    • Implemente For Loop index 1..N-1: calcule Delta = Nodes[i] - Nodes[i-1]. Compare com tabela DirTable (DataTable 8 linhas) e devolva índice 0-7.
    • Para pares ímpares, Byte = Index << 4; para pares pares, Byte += Index. Salve em array de bytes. Na posição 0, some (Nodes.Length-1) ao byte inicial.
    • Retorne o array e envie via Send Bytes no componente de rede, alinhando com SendCharacterMoveNew.
  3. Receber posição oficial e corrigir
    • No BP_SocketClient, crie evento OnReceivePosition(Key, PosX, PosY). Converta para FVector (multiplique grid por 100 Unreal Units).
    • Use SetActorLocation com Interp Speed = 12 (via VInterp To) antes de aplicar; em bolas (MODEL_BALL), adicione Add Force Z = 20.000 para simular Gravity = 20.f.
    • Salve um log no BP_DebugPanel mostrando LocalPos vs ServerPos e o número de correções aplicadas.
  4. Teleporte com validação visual
    • Crie evento RequestTeleport(MapID, Target) no PlayerController. Chame endpoint VaRest /teleport/check passando account, map, pos.
    • Se o JSON retornar "allowed": true, faça RPC Server_Teleport com Target. No cliente, abra Widget Loading (fundo preto 0.6 alpha) por 0.8s.
    • No servidor, valide colisão com Box Trace antes de SetActorLocation; em caso de falha, devolva VaRest erro “blocked” e reabra posição anterior.
  5. Gate → troca de mapa instanciada
    • No Content Browser, crie Blueprint Class → Actor chamado BP_GateTrigger em /Game/Blueprints/World/BP_GateTrigger.uasset. Adicione Box Collision (Extent 150,150,200) e marque Generate Overlap Events.
    • Variáveis: GateId (Integer), TargetMapId (Integer), TargetXY (Vector2D), TargetRot (Rotator). Marque todas como Instance Editable.
    • No Event Graph, use Event ActorBeginOverlap → Cast To BP_MuCharacter → Get Game Instance → Cast To BP_MuGameInstance → Call RequestTeleport(TargetMapId, Make Vector(TargetXY.X*100, -TargetXY.Y*100, 120)). Conecte TargetRot no parâmetro de rotação invertendo yaw com Make Rotator (Yaw = -TargetRot.Yaw).
    • No Level Blueprint de Lorencia_P (e demais mapas), adicione BeginPlay → For Each Row (DT_Gates) filtrando MapId == 0 → SpawnActor BP_GateTrigger com Location = (Row.SourceXY.X*100, -Row.SourceXY.Y*100, 120) e Set Editor Property para preencher as variáveis.
    • Para instanciar o mapa de destino quando ainda não carregado, no BP_MuGameInstance adicione função EnsureMapLoaded(MapId): usa Does Stream Level Exist; se não, chama Load Stream Level (Level Name derivado do MapId) com Make Transform zerado e salva o retorno em mapa LoadedMaps (Key = MapId, Value = LevelStreamingDynamic). Chame essa função antes do ClientTravel/Teleport.
    • Checklist visual: coloque Billboard azul sobre cada BP_GateTrigger e, em PIE, confirme coordenadas 1:1 com o mapa original (use Draw Debug Box com os mesmos valores).
  6. Checklist para quem nunca usou UE5
    • Verde: ícone “Net OK” no topo direito acende quando BP_SocketClient conecta.
    • Amarelo: “Predição ativa” aparece quando AI Move To está correndo; desaparece ao receber correção.
    • Vermelho: texto “Correção aplicada!” surge no HUD quando a diferença > 120 UU, indicando rubber band.
    • Botão debug “Gravar Caminho” exporta o array de bytes para arquivo CSV via Save Game to Slot para comparar com capturas do cliente original.
