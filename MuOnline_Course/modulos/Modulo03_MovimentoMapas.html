Módulo 3 – Personagem e Movimentação

Sincronização de posição entre cliente e servidor, além de timers que processam movimentação.

Pré-requisitos

  • Ter lido os módulos 1 e 2.
  • Conhecimento básico de estruturas de personagem.

Conceitos do Código Original

Cliente – Aplicação de posição recebida (ReceiveMovePosition)
📘 O Que é?

Handler de rede do cliente que atualiza posição/target do personagem ao receber pacote de movimento.

🎯 Para Que Serve?

Sincroniza a posição local com o servidor, ajustando movimento, direção e efeitos (como bola com gravidade).

💻 Como Funciona?

O buffer é convertido em LPPRECEIVE_MOVE_POSITION. Busca o personagem pelo Key, atualiza campos de posição e, se for bola (MODEL_BALL), aplica física e efeitos sonoros/visuais.

void ReceiveMovePosition(BYTE* ReceiveBuffer) {
    LPPRECEIVE_MOVE_POSITION Data = (LPPRECEIVE_MOVE_POSITION)ReceiveBuffer;
    int Key = ((int)(Data->KeyH)<<8) + Data->KeyL;
    CHARACTER* c = &CharactersClient[FindCharacterIndex(Key)];
    OBJECT* o = &c->Object;
    if(o->Type == MODEL_BALL) {
        o->Gravity = 20.f;
        o->Direction[1] = (Data->PositionX-(c->PositionX))*400.f;
    }
    c->PositionX = Data->PositionX;
    c->PositionY = Data->PositionY;
    c->TargetX = Data->PositionX;
    c->TargetY = Data->PositionY;
}

Servidor – Timers de movimentação (QueueTimerCallback)
📘 O Que é?

Callback usado pelos timers do servidor para processar lógica periódica, incluindo movimentação de monstros.

🎯 Para Que Serve?

Separa tarefas de processamento (IA, movimento, eventos, viewport) em timers independentes para manter o loop responsivo.

💻 Como Funciona?

O callback recebe qual timer disparou via lpParameter e executa funções como gObjectManager.ObjectMoveProc() ou CMonsterAI::MonsterMoveProc(), protegidas por CCriticalSection para evitar condições de corrida.

void CALLBACK QueueTimerCallback(PVOID lpParameter,BOOLEAN) {
    static CCriticalSection critical;
    critical.lock();
    switch(((int)lpParameter)) {
        case QUEUE_TIMER_MONSTER_MOVE:
            gObjectManager.ObjectMoveProc();
            break;
        case QUEUE_TIMER_MONSTER_AI_MOVE:
            CMonsterAI::MonsterMoveProc();
            break;
        case QUEUE_TIMER_VIEWPORT:
            gObjViewportProc();
            break;
    }
    critical.unlock();
}

Servidor – Processamento de movimento (ProtocolCore case 0x1C)
📘 O Que é?

Entrada da tabela de protocolos que lida com teleporte/movimento do jogador.

🎯 Para Que Serve?

Valida e executa pedidos de teleporte/movimento originados pelo cliente.

💻 Como Funciona?

O case 0x1C encaminha para gMove.CGTeleportRecv, onde são aplicadas regras de distância, consumo de recursos e atualização de mapa.

case 0x1C:
    gMove.CGTeleportRecv((PMSG_TELEPORT_RECV*)lpMsg,aIndex);
    break;

Implementação em Unreal Engine 5

  • Use ACharacter com CharacterMovementComponent para aplicar posições recebidas do servidor.
  • Implemente replicação de posição via ServerMove/ClientAdjustPosition já fornecidos pelo UE5, substituindo ReceiveMovePosition.
  • Timers de servidor podem ser reimplementados como FTimerHandle em AGameModeBase ou UWorld::GetTimerManager().
  • Teleporte pode ser realizado com RPC confiável em APlayerController chamando SetActorLocation no servidor.
UFUNCTION(Server, Reliable)
void ServerTeleport(const FVector& Dest);

void AMyCharacter::ServerTeleport_Implementation(const FVector& Dest) {
    SetActorLocation(Dest);
    // replicação automática enviará a nova posição
}

Passo a Passo em Unreal Engine 5

  1. Configurar ACharacter com replicação de movimento habilitada.
  2. Mapear pacote de posição para um RPC ClientAdjustPosition customizado, aplicando SetActorLocation.
  3. Implementar timers no AGameModeBase para IA/movimento de NPCs.
  4. Implementar teleporte via RPC confiável, validando mapa/destino.

Checklist Final

  • Personagem do cliente se move e sincroniza posição recebida do servidor.
  • NPCs/monstros atualizam movimento em intervalos configurados.
  • Teleporte entre mapas funciona com validação server-side.
  • Logs ou prints confirmam recebimento de pacotes de posição.
