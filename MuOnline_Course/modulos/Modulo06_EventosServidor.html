Conceitos do Código Original

Loop de mensagens do GameServer
📘 O Que é?

Laço principal em WinMain que processa mensagens e mantém a janela/status do servidor.

🎯 Para Que Serve?

Garante que timers e sockets sejam processados pelo sistema de mensagens do Windows, mantendo a UI de monitoramento.

💻 Como Funciona?

Após configurar timers e sockets, o servidor entra em while(GetMessage(...)), traduz e despacha mensagens, permitindo que callbacks (como QueueTimerCallback) sejam acionados.

while(GetMessage(&msg,0,0,0) != 0) {
    if(TranslateAccelerator(msg.hwnd,hAccelTable,&msg) == 0) {
        TranslateMessage(&msg);
        DispatchMessageA(&msg);
    }
}

Envio periódico para ConnectServer (ConnectServerInfoSend)
📘 O Que é?

Função que monta e envia o status do GameServer para o ConnectServer via UDP.

🎯 Para Que Serve?

Atualiza o servidor de conexão com dados de população e capacidade, permitindo seleção de servidor no cliente.

💻 Como Funciona?

Preenche SDHP_GAME_SERVER_LIVE_SEND com código do servidor, percentual de usuários e limites. Usa gSocketManagerUdp.DataSend para transmitir.

SDHP_GAME_SERVER_LIVE_SEND pMsg;
pMsg.header.set(0x01,sizeof(pMsg));
pMsg.ServerCode = (WORD)gServerInfo.m_ServerCode;
pMsg.UserTotal = (BYTE)((gObjTotalUser==0)?0:((gObjTotalUser*100)/gServerInfo.m_ServerMaxUserNumber));
pMsg.UserCount = (WORD)gObjTotalUser;
pMsg.MaxUserCount = (WORD)gServerInfo.m_ServerMaxUserNumber;
gSocketManagerUdp.DataSend((BYTE*)&pMsg,pMsg.header.size);

Handlers de socket auxiliares (JoinServerMsgProc / DataServerMsgProc)
📘 O Que é?

Processamento de mensagens de rede para conexões com JoinServer e DataServer usando eventos WinSock.

🎯 Para Que Serve?

Garante que desconexões e dados recebidos sejam tratados corretamente, preservando a sessão dos jogadores.

💻 Como Funciona?

Para cada evento WinSock (FD_READ, FD_WRITE, FD_CLOSE), chama métodos de CConnection apropriados; em FD_CLOSE força disconnect e derruba todos os objetos.

void JoinServerMsgProc(WPARAM wParam,LPARAM lParam) {
    switch(LOWORD(lParam)) {
        case FD_READ: gJoinServerConnection.DataRecv(); break;
        case FD_WRITE: gJoinServerConnection.DataSendEx(); break;
        case FD_CLOSE: gJoinServerConnection.Disconnect(); gObjAllDisconnect(); break;
    }
}

Guia Blueprint ultra detalhado (timers + heartbeats + painéis)

Objetivo: recriar o loop de timers do GameServer no UE5 para iniciantes, sem escrever C++.

  1. No Content Browser, crie Blueprint Class → GameModeBase chamado BP_GS_Loop. Abra e marque Run Dedicated Server se usar PIE.
  2. Abra o Event Graph e insira blocos:
    • Event BeginPlay → Set Timer by Function Name (Function Name: SendHeartbeat, Time: 1.0, Looping: true).
    • Repita para SpawnEvents (tempo 5s), CleanDeadActors (tempo 15s) e RefreshServerStatus (tempo 10s).
  3. Crie Functions no Blueprint com o mesmo nome: em SendHeartbeat, coloque Create VaRestRequest (POST), Set URL (ex.: http://127.0.0.1:3000/api/heartbeat), Set Request Body (JSON) com campos ServerCode, OnlinePercent, MaxPlayers. Conecte a Execute → Process URL.
  4. Em SpawnEvents, use For Each Loop sobre um DataTable de eventos (CSV com colunas MapId, NpcID, Interval), chamando Spawn Actor From Class para cada item. Grave o retorno em um Array de Actor para limpeza.
  5. Em CleanDeadActors, use For Each Loop + IsValid + Is Actor Being Destroyed; se estiver destruído, chame Remove Index do array. Se vivo, pule.
  6. Em RefreshServerStatus, use VaRest GET em /api/server/metrics. Ao receber resposta, chame um Widget Blueprint (BP_AdminHUD) e atualize campos CPU, RAM, Users com SetText (RichTextBlock). Posicione o widget no viewport para debug.
  7. Para simular FD_CLOSE, crie função HandleAuxDisconnect com um Custom Event que desconecta todos os jogadores: itere Get All Actors of Class (PlayerController) e chame ClientTravel para tela de login.
  8. No Project Settings → Maps & Modes, defina BP_GS_Loop como GameMode Override para garantir execução dos timers.
  9. Teste no editor: use Output Log para ver prints (Print String) em cada timer; aumente Time Dilation para 10.0 e confirme que timers continuam, simulando o loop constante do GameServer.

Passo a Passo em Unreal Engine 5

  1. Substituir o loop de mensagens por timers em AGameModeBase, criando funções específicas para cada rotina do servidor (spawn, limpeza, broadcast).
  2. Implementar envio periódico de status via socket/HTTP em um subsystem (heartbeat) com payload equivalente ao DataServerInfoSend.
  3. Criar listeners para conexões auxiliares (Join/Data) ou mock services com FSocket ou VaRest; armazenar tokens e estado de conexão.
  4. Registrar logs de eventos/timers para monitoramento e enviar para painel externo (Node.js + SQL) para auditoria.
  5. Separar timers críticos (spawn, limpeza, reset de eventos) em FTimerHandle distintos para facilitar testes e permitir pausar cada rota individualmente.
  6. Usar UE_LOG + PerfCounters customizados para acompanhar uso de CPU/memória similar ao console do servidor, exibindo em uma HUD de admin.
  7. Criar comandos de console no servidor (Exec) para pausar/reiniciar eventos como BattleSoccer e forçar envio de heartbeat.
  8. Automatizar cenários com testes que simulam 100+ jogadores enviando pacotes para validar estabilidade do loop; medir tempos de resposta.
  9. Implementar alarmes: se algum timer atrasar ou falhar, disparar notificação (log + opcional e-mail via Node.js).
  10. Versionar arquivos de configuração de eventos (JSON/DataTable) e carregar no BeginPlay, replicando o comportamento de leitura de tabelas do servidor original.
  11. Documentar o fluxo de start/stop dos eventos, incluindo dependências de mapas e NPCs, para que o aluno consiga reproduzir sequência de boot completa.
