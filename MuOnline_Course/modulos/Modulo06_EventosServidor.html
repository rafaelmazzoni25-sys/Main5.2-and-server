Conceitos do Código Original

Loop de mensagens do GameServer
📘 O Que é?

Laço principal em WinMain que processa mensagens e mantém a janela/status do servidor.

🎯 Para Que Serve?

Garante que timers e sockets sejam processados pelo sistema de mensagens do Windows, mantendo a UI de monitoramento.

💻 Como Funciona?

Após configurar timers e sockets, o servidor entra em while(GetMessage(...)), traduz e despacha mensagens, permitindo que callbacks (como QueueTimerCallback) sejam acionados.

while(GetMessage(&msg,0,0,0) != 0) {
    if(TranslateAccelerator(msg.hwnd,hAccelTable,&msg) == 0) {
        TranslateMessage(&msg);
        DispatchMessageA(&msg);
    }
}

Envio periódico para ConnectServer (ConnectServerInfoSend)
📘 O Que é?

Função que monta e envia o status do GameServer para o ConnectServer via UDP.

🎯 Para Que Serve?

Atualiza o servidor de conexão com dados de população e capacidade, permitindo seleção de servidor no cliente.

💻 Como Funciona?

Preenche SDHP_GAME_SERVER_LIVE_SEND com código do servidor, percentual de usuários e limites. Usa gSocketManagerUdp.DataSend para transmitir.

SDHP_GAME_SERVER_LIVE_SEND pMsg;
pMsg.header.set(0x01,sizeof(pMsg));
pMsg.ServerCode = (WORD)gServerInfo.m_ServerCode;
pMsg.UserTotal = (BYTE)((gObjTotalUser==0)?0:((gObjTotalUser*100)/gServerInfo.m_ServerMaxUserNumber));
pMsg.UserCount = (WORD)gObjTotalUser;
pMsg.MaxUserCount = (WORD)gServerInfo.m_ServerMaxUserNumber;
gSocketManagerUdp.DataSend((BYTE*)&pMsg,pMsg.header.size);

Handlers de socket auxiliares (JoinServerMsgProc / DataServerMsgProc)
📘 O Que é?

Processamento de mensagens de rede para conexões com JoinServer e DataServer usando eventos WinSock.

🎯 Para Que Serve?

Garante que desconexões e dados recebidos sejam tratados corretamente, preservando a sessão dos jogadores.

💻 Como Funciona?

Para cada evento WinSock (FD_READ, FD_WRITE, FD_CLOSE), chama métodos de CConnection apropriados; em FD_CLOSE força disconnect e derruba todos os objetos.

void JoinServerMsgProc(WPARAM wParam,LPARAM lParam) {
    switch(LOWORD(lParam)) {
        case FD_READ: gJoinServerConnection.DataRecv(); break;
        case FD_WRITE: gJoinServerConnection.DataSendEx(); break;
        case FD_CLOSE: gJoinServerConnection.Disconnect(); gObjAllDisconnect(); break;
    }
}

Implementação em Unreal Engine 5

  • Substitua o loop de mensagens por AGameModeBase::Tick ou UWorld timers.
  • Para status de servidor, use FTimerManager para enviar batidas de vida a um serviço matchmaking via UDP ou HTTP.
  • Handlers de socket podem ser implementados com FUdpSocketReceiver ou FSocket em um UGameInstanceSubsystem, com callbacks de leitura.
  • Mantenha sincronização de estado global em classes derivadas de AGameStateBase.

Passo a Passo em Unreal Engine 5

  1. Substituir o loop de mensagens por timers em AGameModeBase.
  2. Implementar envio periódico de status via socket/HTTP em um subsystem.
  3. Criar listeners para conexões auxiliares (Join/Data) ou mock services.
  4. Registrar logs de eventos/timers para monitoramento.
  5. Separar timers críticos (spawn, limpeza, reset de eventos) em FTimerHandle distintos para facilitar testes.
  6. Usar UE_LOG + PerfCounters customizados para acompanhar uso de CPU/memória similar ao console do servidor.
  7. Criar comandos de console no servidor (Exec) para pausar/reiniciar eventos como BattleSoccer.
  8. Automatizar cenários com testes que simulam 100+ jogadores enviando pacotes para validar estabilidade do loop.

Checklist Final

  • Timers ativos para tarefas críticas do servidor UE5.
  • Heartbeat do servidor enviado e confirmado por serviço externo.
  • Handlers de conexões auxiliares recebem e processam eventos.
  • Dashboard/log apresenta estado do servidor em tempo real.
