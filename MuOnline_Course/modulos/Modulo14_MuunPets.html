Carregamento de definições Muun – CMuunSystem::Load
📘 O Que é?

Processo que lê duas seções de script: informações básicas do item Muun e opções especiais.

🎯 Para Que Serve?

Popular mapas m_MuunSystemInfo e m_MuunSystemOptionInfo usados em checagens posteriores de status.

💻 Como Funciona?

void CMuunSystem::Load(char* path) {
    CMemScript* lpMemScript = new CMemScript;
    if(lpMemScript == 0) { ErrorMessageBox(MEM_SCRIPT_ALLOC_ERROR,path); return; }
    if(lpMemScript->SetBuffer(path) == 0) { ErrorMessageBox(lpMemScript->GetLastError()); delete lpMemScript; return; }
    this->m_MuunSystemInfo.clear();
    this->m_MuunSystemOptionInfo.clear();
    try {
        while(true) {
            if(lpMemScript->GetToken() == TOKEN_END) { break; }
            int section = lpMemScript->GetNumber();
            while(true) {
                if(section == 0) {
                    if(strcmp("end",lpMemScript->GetAsString()) == 0) { break; }
                    MUUN_SYSTEM_INFO info;
                    info.Index = lpMemScript->GetNumber();
                    info.Type = lpMemScript->GetAsNumber();
                    info.Rank = lpMemScript->GetAsNumber();
                    info.OptionIndex = lpMemScript->GetAsNumber();
                    info.EvolutionItemIndex = lpMemScript->GetAsNumber();
                    this->m_MuunSystemInfo.insert(std::pair(info.Index,info));
                } else if(section == 1) {
                    if(strcmp("end",lpMemScript->GetAsString()) == 0) { break; }
                    MUUN_SYSTEM_OPTION_INFO info;
                    info.Index = lpMemScript->GetNumber();
                    info.OptionValue[0] = lpMemScript->GetAsNumber();
                    info.OptionValue[1] = lpMemScript->GetAsNumber();
                    info.OptionValue[2] = lpMemScript->GetAsNumber();
                    info.OptionValue[3] = lpMemScript->GetAsNumber();
                    info.OptionValue[4] = lpMemScript->GetAsNumber();
                    info.MaxOptionValue = lpMemScript->GetAsNumber();
                    info.SpecialOptionIndex = lpMemScript->GetAsNumber();
                    info.SpecialOptionValue = lpMemScript->GetAsNumber();
                    info.MapZone = lpMemScript->GetAsNumber();
                    info.PlayTime = lpMemScript->GetAsNumber();
                    info.DayOfWeek = lpMemScript->GetAsNumber();
                    info.MinHour = lpMemScript->GetAsNumber();
                    info.MaxHour = lpMemScript->GetAsNumber();
                    info.MinLevel = lpMemScript->GetAsNumber();
                    info.MaxLevel = lpMemScript->GetAsNumber();
                    info.MinMasterLevel = lpMemScript->GetAsNumber();
                    info.MaxMasterLevel = lpMemScript->GetAsNumber();
                    this->m_MuunSystemOptionInfo.insert(std::pair(info.Index,info));
                } else { break; }
            }
        }
    } catch(...) { ErrorMessageBox(lpMemScript->GetLastError()); }
    delete lpMemScript;
}

Aplicação contínua de status Muun – CMuunSystem::MainProc
📘 O Que é?

Loop que percorre jogadores conectados e ativa/desativa efeitos de itens Muun equipados.

🎯 Para Que Serve?

Garante que bônus sejam aplicados apenas quando as condições especiais são satisfeitas.

💻 Como Funciona?

void CMuunSystem::MainProc() {
    for(int n=OBJECT_START_USER;n < MAX_OBJECT;n++) {
        if(gObjIsConnectedGP(n) == 0) { continue; }
        LPOBJ lpObj = &gObj[n];
        for(int n=0;n < MUUN_INVENTORY_WEAR_SIZE;n++) {
            if(lpObj->MuunInventory[n].IsItem() == 0 || lpObj->MuunInventory[n].IsMuunItem() == 0 || lpObj->MuunInventory[n].m_Durability == 0) { continue; }
            MUUN_SYSTEM_INFO MuunSystemInfo;
            if(this->GetMuunSystemInfo(lpObj->MuunInventory[n].m_Index,&MuunSystemInfo) != 0) {
                MUUN_SYSTEM_OPTION_INFO MuunSystemOptionInfo;
                if(this->GetMuunSystemOptionInfo(MuunSystemInfo.OptionIndex,&MuunSystemOptionInfo) != 0) {
                    if(this->CheckSpecialOption(lpObj,&MuunSystemOptionInfo) == 0) {
                        if(lpObj->MuunItemStatus[n] != 0) {
                            gObjectManager.CharacterCalcAttribute(lpObj->Index);
                            this->GCMuunItemStatusSend(lpObj->Index,n,0);
                            lpObj->MuunItemStatus[n] = 0;
                        }
                    } else {
                        if(lpObj->MuunItemStatus[n] == 0) {
                            gObjectManager.CharacterCalcAttribute(lpObj->Index);
                            this->GCMuunItemStatusSend(lpObj->Index,n,1);
                            lpObj->MuunItemStatus[n] = 1;
                        }
                    }
                }
            }
        }
    }
}

Validação de inventário Muun – MuunInventoryRectCheck e MuunInventoryInsertItem
📘 O Que é?

Regras de encaixe de itens Muun em slots, respeitando largura/altura do item e mapa de ocupação.

🎯 Para Que Serve?

Impede sobreposição e mantém layout 4x15 do inventário Muun, retornando um slot válido ou 0xFF.

💻 Como Funciona?

BYTE CMuunSystem::MuunInventoryRectCheck(int aIndex,int x,int y,int width,int height) {
    if((x+width) > 4 || (y+height) > 15) { return 0xFF; }
    for(int sy=0;sy < height;sy++) {
        for(int sx=0;sx < width;sx++) {
            if(gObj[aIndex].MuunInventoryMap[(((sy+y)*4)+(sx+x))] != 0xFF) { return 0xFF; }
        }
    }
    return (((y*4)+x)+MUUN_INVENTORY_WEAR_SIZE);
}

Implementação em Unreal Engine 5

Vamos mapear o inventário Muun para componentes e DataAssets, mantendo compatibilidade com backend Node.js/SQL via VaRest.

Passo a Passo

  1. Defina um UDataTable para FMuunDefinition e FMuunOptionDefinition (campos alinhados aos scripts).
  2. Crie um UMuunInventoryComponent (subclasse de UActorComponent) com mapa 4x15 em TArray<int32> inicializado com 0xFF.
  3. Implemente métodos RectCheck e InsertItem replicando a lógica de limites e ocupação, disparando eventos OnMuunChanged.
  4. No APlayerState, mantenha um array de slots equipados (2 primeiros índices) e expor RPCs servidor <-> cliente para equipar/retirar.
  5. Crie um UMuunStatusSubsystem que, a cada tick server-side, avalia condições especiais (mapa, horário, nível) e aplica GameplayEffect ou modificadores de atributos.
  6. Integre com VaRest: ao logar, faça requisição GET para Node.js/SQL retornando lista de itens Muun; ao salvar, envie POST com slots e durabilidade.
  7. Implemente UI em UMG com grid 4x15 arrastável; use DragDropOperation para mover itens respeitando RectCheck.
  8. Adicione testes automatizados: unit test para RectCheck (ambos válidos/invalidos) e integração que carrega definições do DataTable e aplica um buff em personagem.

Guia Blueprint detalhado

  1. No Content Drawer crie Blueprints/Muun. Adicione Structure ST_MuunItem (Index, Name, Width, Height, Durability, OptionId) e Structure ST_MuunSave (Slot, ItemIndex, Durability).
  2. Crie um Actor Component BP_MuunInventoryComponent. Marque Replicates. Adicione variáveis: Slots (Array Int) tamanho 60 inicializado com 255 (0xFF), Equipped (Array Int) tamanho 2, Items (Array ST_MuunItem). Construa uma função SetupGrid que seta Slots com 60 valores 255.
  3. Função RectCheck (Pure): entrada X,Y,Width,Height; se X+Width > 4 ou Y+Height > 15, retorne -1. Senão, duplo loop sy=0..Height-1, sx=0..Width-1 verificando Slots[(sy+Y)*4 + (sx+X)] == 255. Se qualquer ocupado, retorne -1; caso contrário, retorne (Y*4+X).
  4. Função InsertItem (Run on Server, Reliable): entrada Item : ST_MuunItem. Faça Index = RectCheck(CandidateX, CandidateY, Item.Width, Item.Height). Ao receber -1, mostre toast "Sem espaço". Se válido, marque todos os blocos com um ID gerado (ex.: ItemGuid) e armazene Items.Add(Item). Acione OnRep_Slots para atualizar UI.
  5. UI: crie WBP_MuunInventory. No Designer, insira Uniform Grid Panel 4 colunas x 15 linhas, cada célula 40x40 px (Padding 2). Adicione um Overlay com texto "Equip" na coluna 0, linhas 0 e 1 para slots equipados. Vincule as células a Slots, colorindo o fundo de acordo com o item e mostrando tooltip com Name/Durability.
  6. Drag & Drop: em cada célula, implemente OnMouseButtonDown criando DragDropOperation contendo ItemGuid. Em OnDrop do destino, converta índice de célula para X = Index % 4 e Y = Index / 4, chame ServerMoveMuun (Run on Server) para tentar reposicionar usando RectCheck.
  7. Persistência VaRest: ao abrir a UI, VaRest GET /muun/load preenchendo Slots e Items com base na resposta JSON. Ao fechar a UI ou a cada 30s, POST /muun/save com lista de ST_MuunSave. Trate falha mostrando alerta vermelho no topo do widget.
  8. Buffs: crie Data Asset DA_MuunEffects mapeando OptionId para GameplayEffect. No componente, a cada Tick server-side, verifique itens equipados e aplique/remova efeitos. Exemplo: OptionId 101 = +5% MoveSpeed; 102 = +50 MaxHP.
  9. Checklist visual: adicione Text Block no topo direito da UI mostrando "Slots livres: {count}". Coloque o widget ancorado na direita (X=-520, Y=120, alinhamento 1,0). Use ícone do Muun ativo no canto inferior esquerdo da tela (X=40,Y=720) com brilho pulsante.
  10. Teste rápido: em PIE Multiplayer 2, arraste um item 2x2 para posição (X=1,Y=5) e outro 1x1 para (X=3,Y=0). Desconecte e reconecte verificando se os itens voltam e se o buff permanece aplicado após reload via VaRest.

Checklist Final

  • Inventário Muun replicado com regras de encaixe 4x15 e slots equipados funcionais.
  • Buffs/efeitos são aplicados e removidos dinamicamente conforme condições, com feedback visual em UI.
