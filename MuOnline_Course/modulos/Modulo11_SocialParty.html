Criação e liderança de party (Create, AddMember, ChangeLeader)
📘 O Que é?

Métodos que instanciam um grupo, adicionam membros e ajustam o líder quando necessário.

🎯 Para Que Serve?

Garantem que apenas um party ativo use um slot e que a liderança seja transferida ao remover o primeiro membro.

💻 Como Funciona?

bool CParty::Create(int aIndex) {
    if(this->IsParty(gObj[aIndex].PartyNumber) != 0) return 0;
    int count = this->m_PartyCount;
    for(int n=0;n < MAX_OBJECT;n++) {
        if(this->m_PartyInfo[count].Count == 0) {
            gObj[aIndex].PartyNumber = count;
            this->m_PartyInfo[count].Count = 1;
            this->m_PartyInfo[count].Index[0] = aIndex;
            for(int i=1;i < MAX_PARTY_USER;i++) this->m_PartyInfo[count].Index[i] = -1;
            this->GCPartyListSend(count);
            this->m_PartyCount = (((++this->m_PartyCount)>=MAX_OBJECT)?0:this->m_PartyCount);
            return 1;
        }
        else { count = (((++count)>=MAX_OBJECT)?0:count); }
    }
    return 0;
}

bool CParty::AddMember(int index,int aIndex) {
    if(this->IsParty(index) == 0) return 0;
    if(this->GetMemberNumber(index,aIndex) != -1) return 0;
    for(int n=0;n < gServerInfo.m_PartyMaxMembers;n++) {
        if(OBJECT_RANGE(this->m_PartyInfo[index].Index[n]) == 0) {
            gObj[aIndex].PartyNumber = index;
            this->m_PartyInfo[index].Count++;
            this->m_PartyInfo[index].Index[n] = aIndex;
            this->GCPartyListSend(index);
            return 1;
        }
    }
    return 0;
}

void CParty::ChangeLeader(int index,int number) {
    if(this->IsParty(index) == 0 || number != 0) return;
    for(int n=1;n < MAX_PARTY_USER;n++) {
        if(OBJECT_RANGE(this->m_PartyInfo[index].Index[n]) != 0) {
            this->m_PartyInfo[index].Index[0] = this->m_PartyInfo[index].Index[n];
            this->m_PartyInfo[index].Index[n] = -1;
            break;
        }
    }
}

Envio da lista e vida de membros (GCPartyListSend)
📘 O Que é?

Rotina que serializa a composição do grupo e envia para todos os membros, incluindo vida/mana.

🎯 Para Que Serve?

Sincroniza UI de party no cliente, garantindo que cada membro veja posições, mapa e status de cada participante.

💻 Como Funciona?

void CParty::GCPartyListSend(int index) {
    if(this->IsParty(index) == 0) return;
    BYTE send[256]; PMSG_PARTY_LIST_SEND pMsg; pMsg.header.set(0x42,0);
    int size = sizeof(pMsg); pMsg.result = 1; pMsg.count = 0; PMSG_PARTY_LIST info;
    for(int n=0;n < MAX_PARTY_USER;n++) {
        if(OBJECT_RANGE(this->m_PartyInfo[index].Index[n]) == 0) continue;
        LPOBJ lpObj = &gObj[this->m_PartyInfo[index].Index[n]];
        memcpy(info.name,lpObj->Name,sizeof(info.name)); info.number = n;
        info.map = lpObj->Map; info.x = (BYTE)lpObj->X; info.y = (BYTE)lpObj->Y;
        info.CurLife = (DWORD)(lpObj->Life); info.MaxLife = (DWORD)(lpObj->MaxLife+lpObj->AddLife);
        info.ServerCode = gServerInfo.m_ServerCode+1; info.CurMana = (DWORD)(lpObj->Mana);
        info.MaxMana = (DWORD)(lpObj->MaxMana+lpObj->AddMana);
        memcpy(&send[size],&info,sizeof(info)); size += sizeof(info); pMsg.count++;
    }
    pMsg.header.size = size; memcpy(send,&pMsg,sizeof(pMsg));
    for(int n=0;n < MAX_PARTY_USER;n++) if(OBJECT_RANGE(this->m_PartyInfo[index].Index[n]) != 0)
        DataSend(this->m_PartyInfo[index].Index[n],send,size);
}

Roteamento de pacotes de party (ProtocolCore)
📘 O Que é?

Switch central que direciona os códigos 0x40–0x43 para os handlers do CParty.

🎯 Para Que Serve?

Garante que convites, respostas e atualizações de lista sejam processados pelo subsistema correto.

💻 Como Funciona?

case 0x40: gParty.CGPartyRequestRecv((PMSG_PARTY_REQUEST_RECV*)lpMsg,aIndex); break;
case 0x41: gParty.CGPartyRequestResultRecv((PMSG_PARTY_REQUEST_RESULT_RECV*)lpMsg,aIndex); break;
case 0x42: gParty.CGPartyListRecv(aIndex); break;
case 0x43: gParty.CGPartyDelMemberRecv((PMSG_PARTY_DEL_MEMBER_RECV*)lpMsg,aIndex); break;

Passo a Passo em Unreal Engine 5

  1. Criar um ator de estado (APartyState) replicado no servidor dedicado contendo lista de membros, líder e metadados (mapa, posição).
  2. Implementar RPC ServerRequestParty disparado por UI (clique em jogador) para enviar convite; incluir tempo de expiração.
  3. No servidor, validar limites (MAX_PARTY_USER) e duplicação antes de aceitar (espelhando IsParty/GetMemberNumber) e rejeitar convites cruzados.
  4. Ao aprovar, popular Members e marcar o índice 0 como líder (similar ao array Index[0]); replicar imediatamente para os clientes.
  5. Propagar Members via OnRep_Members para atualizar widgets no cliente (equivalente a GCPartyListSend) e recalcular barras.
  6. Adicionar RPC de remoção que, ao excluir o líder, reatribui o slot 0 para o próximo membro, reproduzindo ChangeLeader e notificando todos via multicast.
  7. Replicar vida/mana (tick ou evento) alimentando barras de party, usando OnAttributeChanged do GAS ou eventos customizados; mostrar ícones de buffs se enviados.
  8. Criar Widget Blueprint de party que liste Members e permita chutar jogador via botão que chama ServerDelMember; bloquear ações quando não for líder.
  9. Integrar com minimapa replicado para mostrar a posição Pos dos membros como no pacote original e destacar o líder.
  10. Registrar logs/telemetria para cada convite e aceite, equivalente ao logging do protocolo 0x40–0x43, e enviar para backend Node.js/SQL para auditoria.
  11. Se quiser persistência externa, expor endpoints Node.js/SQL para salvar composições de grupo em sessões cooperativas e restaurar automaticamente quando os jogadores reconectarem.
  12. Automatizar testes funcionais: criar dois clientes simulados, enviar convite, aceitar e verificar atualização de barras de vida; testar remoção do líder e reatribuição automática.
  13. Adicionar comandos de console para forçar criação/remoção de party e para depurar replicação (dump em log).

Checklist Final

  • Convites de party são enviados e recebidos, respeitando limite de 5 membros.
  • Ao remover o líder, outro membro assume automaticamente o slot 0.
  • UI mostra vida/mana de todos os membros e atualiza ao receber replicação.
  • Logs confirmam o roteamento de pacotes 0x40–0x43 e a sincronização da lista.
