CIllusionTemple::CGIllusionTempleEnterRecv – Validação de entrada
📘 O Que é?

Handler do pacote 0xBF 0x70 que valida convite, slot, PK, duel, guild war e move o jogador para o gate adequado.

void CIllusionTemple::CGIllusionTempleEnterRecv(...,int aIndex) {
    if(gServerInfo.m_IllusionTempleEvent == 0) return;
    LPOBJ lpObj = &gObj[aIndex];
    PMSG_ILLUSION_TEMPLE_ENTER_SEND pMsg; pMsg.header.set(0xBF,0x70,sizeof(pMsg));
    pMsg.result = 0;
    lpMsg->level = this->GetUserAbleLevel(lpObj);
    if(INVENTORY_FULL_RANGE(lpMsg->slot) == 0) { pMsg.result = 1; DataSend(...); return; }
    if(gItemManager.GetInventoryItemCount(lpObj,GET_ITEM(13,51),(level+1)) == 0 ... ) { gNotice.GCNoticeSend(...); return; }
    if(lpObj->Inventory[lpMsg->slot].m_Index == GET_ITEM(13,51) && lpObj->Inventory[lpMsg->slot].m_Level != (lpMsg->level+1)) { pMsg.result = 3; DataSend(...); return; }
    if(OBJECT_RANGE(lpObj->PartyNumber) != 0) { pMsg.result = 1; DataSend(...); return; }
    if(lpObj->Guild != 0 && lpObj->Guild->WarState == 1) { pMsg.result = 1; DataSend(...); return; }
    if(OBJECT_RANGE(lpObj->DuelUser) != 0) { pMsg.result = 1; DataSend(...); return; }
    if(lpObj->PShopOpen != 0) { pMsg.result = 1; DataSend(...); return; }
    if(this->GetEnterEnabled(lpMsg->level) == 0) { pMsg.result = 3; DataSend(...); gNotice.GCNoticeSend(...); return; }
    if(gServerInfo.m_PKLimitFree == 0 && lpObj->PKLevel >= 4) { pMsg.result = 7; DataSend(...); return; }
    if(this->AddUser(lpLevel,aIndex) == 0) { pMsg.result = 4; DataSend(...); return; }
    gItemManager.DecreaseItemDur(lpObj,lpMsg->slot,1);
    if(lpObj->Inventory[lpMsg->slot].m_Index == GET_ITEM(13,19)) { gItemManager.InventoryDelItem(lpObj->Index,lpMsg->slot); gItemManager.GCItemDeleteSend(lpObj->Index,lpMsg->slot,1); }
    switch(lpMsg->level) { case 0: gObjMoveGate(aIndex,142); break; ... case 5: gObjMoveGate(aIndex,147); break; }
    this->GCIllusionTempleChangeScenarioSend(lpLevel,0,aIndex);
}

🎯 Para Que Serve?

Impede entradas inválidas (sem convite, slot errado, PK alto, duel/party ativos) e envia o jogador para o mapa/level correto, descontando o convite.

💻 Como Funciona?

Valida flags e inventário, envia respostas de erro via pMsg.result, remove durabilidade ou deleta o convite e faz gObjMoveGate para um dos gates 142–147, finalizando com GCIllusionTempleChangeScenarioSend.

Implementação em Unreal Engine 5

Mapeie o evento para GameMode/GameState dedicados, usando componentes para lógica de convite e teleporte.

  • Estrutura equivalente: AGameModeBase para orquestrar estados; AGameStateBase replicado para tempos e pontuação; APlayerController para comandos de entrada; UActorComponent para inventário/convite.
  • Crie um USTRUCT com horários e recompensas carregados de DataTable ou JSON (mirroring IllusionTemple.dat), aplicando-os ao GameMode no BeginPlay.
  • Validação de entrada: RPC servidor ServerRequestEnterIllusion(int32 Level, int32 Slot) no PlayerController; execute checks de inventário (componentes), estado de party/duel e PK. Em caso de falha, envie ClientNotifyEnterResult(uint8 Result).
  • Teleporte: use UGameplayStatics::OpenLevel ou ServerTravel para sub-levels/gates e posicione jogadores em coordenadas pré-definidas por nível.
  • Consumo de item: remova do inventário replicado (Array de FItemSlot) e notifique UI; utilize VaRest para registrar consumo em backend Node.js/SQL, persistindo uso do convite.
  • Estado do evento: timers com FTimerHandle replicados; ao fechar entrada, rejeite novos pedidos e avance para fase de combate, emitindo multicast para UI.

Passo a Passo em Unreal Engine 5

  1. Criar DataTable com horários/recompensas espelhando IllusionTemple.dat.
  2. Implementar AIllusionTempleGameMode com estados (Blank, Empty, Stand, Start, Clean) e timers replicados.
  3. No AIllusionTemplePlayerController, adicionar RPC ServerRequestEnterIllusion que consulta componente de inventário e estado social (party/duel/UI).
  4. Consumir item convite no componente de inventário e disparar ClientUpdateInventory; em caso de m_Index == GET_ITEM(13,19), deletar slot.
  5. Teletransportar para sub-level ou streaming cell conforme nível; chamar ClientTravel para o mapa correto.
  6. Replicar pontuação e posse do item objetivo via GameState; implementar multicast ClientUpdateScenario(State).
  7. Integrar VaRest para registrar entrada e resultado no Node.js/SQL (tabela de ranking do evento).
  8. Testar com convites válidos/ inválidos, PK >=4, duel ativo, guild war e party aberta.

Checklist Final

  • Horários e recompensas carregados de forma equivalente ao IllusionTemple.dat.
  • Convite consumido ou deletado corretamente e jogador movido para o gate do nível.
  • Rejeições replicam os mesmos códigos de pMsg.result (slot inválido, PK, duel, guild war, sem item).
  • Estado do evento e pontuação replicados para todos os clientes; UI notifica troca de cenário.
  • Entrada e resultado registrados via VaRest no backend Node.js/SQL.
