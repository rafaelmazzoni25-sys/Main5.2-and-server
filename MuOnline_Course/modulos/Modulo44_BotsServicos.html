Módulo 44 – Bots de Serviço (Buffer e Warper)

Explora os NPCs automáticos que buffam ou teleportam jogadores (BotBuffer e BotWarper) e mostra como reproduzir o comportamento em Unreal Engine 5, mantendo regras de nível, VIP e requisitos de Gens.

Pré-requisitos

  • Módulo 1 – Arquitetura Geral (ciclo do GameServer e eventos de inicialização).
  • Módulo 7 – Conexões entre Servidores (para entender mudanças de mapa e MapServer).
  • Módulo 41 – Progressão/Reset (para validar limites de nível/reset usados pelos bots).

Conceitos do Código Original

Carregamento de BotBuffer – ObjBotBuffer::Read
📘 O Que é?

Rotina que reseta o estado, limpa bots ativos e lê o script BotBuffer.txt para definir classe, posição, custos e itens de cada NPC buffador.

void ObjBotBuffer::Read(char * FilePath) {
  if(this->Enabled == 1) { /* remove bots vivos */ }
  for(int i=0;i<MAX_BOTBUFFER;i++) {
    this->bot[i].index = -1;
    this->bot[i].SkillCount = 0;
    this->bot[i].MaxLevel = ObjBotBuff.Max_Normal_Level;
    memset(&this->bot[i].skill,0,sizeof(this->bot[i].skill));
    this->bot[i].Enabled = 0;
    for(int j=0;j<9;j++) this->bot[i].body[j].num =-1;
  }
  CMemScript* lpMemScript = new CMemScript;
  if(lpMemScript->SetBuffer(FilePath) == 0) { ErrorMessageBox(...); return; }
  while(true) {
    if(lpMemScript->GetToken() == TOKEN_END) break;
    int section = lpMemScript->GetNumber();
    while(true) {
      if(section == 1) {
        if(strcmp("end",lpMemScript->GetAsString()) == 0) break;
        int BotNum = lpMemScript->GetNumber();
        this->bot[BotNum].Class = lpMemScript->GetAsNumber();
        this->bot[BotNum].Enabled = lpMemScript->GetAsNumber();
        this->bot[BotNum].ChangeColorName = lpMemScript->GetAsNumber();
        this->bot[BotNum].Zen = lpMemScript->GetAsNumber();
        this->bot[BotNum].PCPoints = lpMemScript->GetAsNumber();
        this->bot[BotNum].MaxLevel = lpMemScript->GetAsNumber();
        strncpy_s(this->bot[BotNum].Name,lpMemScript->GetAsString(),sizeof(...));
        this->bot[BotNum].Map = lpMemScript->GetAsNumber();
        this->bot[BotNum].X = lpMemScript->GetAsNumber();
        this->bot[BotNum].Y = lpMemScript->GetAsNumber();
        this->bot[BotNum].Dir = lpMemScript->GetAsNumber();
      }
      // demais seções continuam...
    }
  }
}

🎯 Para Que Serve?

Define, a partir de script, quais bots de buff estarão ativos, seus custos (Zen/PCPoint), posição no mapa e itens exibidos, para criar NPCs de suporte configuráveis.

💻 Como Funciona?

1) Se já havia bots ativos, remove-os via gObjDel.
2) Inicializa slots com índices inválidos e contadores zerados.
3) Usa CMemScript para iterar seções; na seção 1 lê atributos básicos (classe, nome, custos, posição) de cada bot.
4) Prepara arrays de skills e equipamentos que serão aplicados no spawn.

// reset inicial de cada entrada
this->bot[i].index = -1;
this->bot[i].SkillCount = 0;
this->bot[i].MaxLevel = ObjBotBuff.Max_Normal_Level;
memset(&this->bot[i].skill,0,sizeof(this->bot[i].skill));
this->bot[i].Enabled = 0;

Spawn e inventário do BotBuffer – ObjBotBuffer::MakeBot
📘 O Que é?

Rotina que instancia os NPCs buffadores após a leitura do script, configurando posição, classe, inventário e atributos base. 

void ObjBotBuffer::MakeBot() {
  if(this->Enabled == 1) {
    for(int botNum=0; botNum<MAX_BOTBUFFER; botNum++) {
      if(this->bot[botNum].Enabled == 1) {
        int result = gObjAddSummon();
        if(result >= 0) {
          this->bot[botNum].index = result;
          gObj[result].X = this->bot[botNum].X;
          gObj[result].Y = this->bot[botNum].Y;
          gObj[result].Dir = this->bot[botNum].Dir;
          gObj[result].Map = this->bot[botNum].Map;
          gObj[result].IsBot = 2;
          gObjSetBots(result,this->bot[botNum].Class);
          gObj[result].Class = this->bot[botNum].Class;
          gObj[result].Level = 400;
          gObj[result].PKLevel = this->bot[botNum].ChangeColorName;
          gObj[result].GensFamily = this->bot[botNum].GensFamily;
          gObj[result].Inventory = new CItem[INVENTORY_SIZE];
          memset(&gObj[result].InventoryMap[0], (BYTE)-1, INVENTORY_SIZE);
          strcpy_s(gObj[result].Name,this->bot[botNum].Name);
          for(int i=0;i<9;i++) {
            if(this->bot[botNum].body[i].num >= 0 && this->bot[botNum].body[i].Enabled == 1) {
              CItem item; item.m_Level = this->bot[botNum].body[i].level; item.m_Option2 = 1;
              item.m_Option3 = this->bot[botNum].body[i].opt; item.m_Durability = 255.0f;
              item.Convert(this->bot[botNum].body[i].num,...);
              gObjInventoryInsertItemPos(gObj[result].Index,item,i,0);
            }
          }
          gObjectManager.CharacterMakePreviewCharSet(result);
          GCActionSend(&gObj[result],ACTION_SALUTE1,result,result);
        }
      }
    }
  }
}

🎯 Para Que Serve?

Cria os NPCs buffadores in-game com visual e inventário definidos no script, prontos para atender jogadores.

💻 Como Funciona?

Usa gObjAddSummon para alocar um slot de NPC, configura coordenadas, flag IsBot, classe e inventário. Cada item do array body é convertido e inserido diretamente nas posições iniciais do inventário antes de gerar o preview.

Validação de atendimento do BotBuffer – ObjBotBuffer::TradeOpen
📘 O Que é?

Valida se o jogador pode interagir com o bot (nível máximo, VIP, Gens, Zen/PCPoint) antes de aplicar buffs.

🎯 Para Que Serve?

Garante que somente jogadores dentro dos limites configurados recebam o serviço de buff, exibindo mensagens específicas para restrições.

💻 Como Funciona?

1) Busca o bot pelo índice do NPC.
2) Verifica nível máximo, status VIP e contribuição Gens.
3) Confere saldo de Zen e PCPoint.
4) Interrompe com mensagens via gNotice.NewMessageDevTeam em caso de falha.

BOOL ObjBotBuffer::TradeOpen(int index,int nindex) {
  int number = this->GetBotIndex(nindex);
  if(lpObj->Level > this->bot[number].MaxLevel) { gNotice.NewMessageDevTeam(...); return 1; }
  if(this->bot[number].OnlyVip != 0 && lpObj->AccountLevel == 0) return 1;
  if((DWORD)this->bot[number].Zen > gObj[index].Money) return 1;
  if(this->bot[number].PCPoints > gObj[index].PCPoint) return 1;
  // checagens adicionais de família Gens...
}

Warp assistido por NPC – ObjBotWarper::TradeOpen
📘 O Que é?

Handler de trade do BotWarper que valida requisitos (VIP, level, reset, Gens, Zen/PCPoint) e calcula a posição de teleporte segura antes de acionar o MapServer ou mover o jogador. 

BOOL ObjBotWarper::TradeOpen(int index,int nindex) {
  int number = this->GetBotIndex(nindex);
  if(this->bot[number].OnlyVip != 0 && lpObj->AccountLevel == 0) { ...; return 1; }
  if(gObj[index].Level < this->bot[number].MinLevel) return 1;
  if(gObj[index].Reset < this->bot[number].MinReset) return 1;
  if(this->bot[number].ActiveGensFamily == 1) { /* valida família e contribuição */ }
  if(this->bot[number].Zen > gObj[index].Money) return 1;
  int addx = this->bot[number].Warp_X + rand()%9 - 4; // procura spot livre
  if(lpObj->Map != this->bot[number].Warp_Map) {
    short sSvrCode = gMapServerManager.CheckMapServerMove(...);
    if(sSvrCode != ServerCode) { GJMapServerMoveSend(...); return 1; }
  }
  lpObj->SkillSummonPartyMap = this->bot[number].Warp_Map;
  lpObj->SkillSummonPartyX = addx; lpObj->SkillSummonPartyY = addy;
  return 1;
}

🎯 Para Que Serve?

Oferece um NPC teleporter com regras de acesso e cobrança, incluindo redirecionamento para outro MapServer quando necessário.

💻 Como Funciona?

1) Checa privilégios VIP/Gens e requerimentos de level/reset.
2) Verifica Zen/PCPoint e interfaces bloqueadoras de movimento.
3) Busca coordenada segura próxima do warp configurado.
4) Se o mapa alvo está em outro servidor, envia GJMapServerMoveSend; caso contrário, grava o destino em SkillSummonParty* para teleporte.

Implementação em Unreal Engine 5

Para cada conceito acima, mapear para componentes e atores em UE5, garantindo lógica de validação e teleporte replicado.

Equivalências de Classes

  • NPC Buff/Warper: AActor ou ANPCCharacter derivado de ACharacter com componente UStaticMesh e USphereComponent para interação.
  • Gerenciador de scripts: UObject singleton (ex.: UDataTable carregado de CSV/JSON).
  • Controle de teleporte: APlayerController + UGameplayStatics::OpenLevel ou ServerTravel com RPCs.

Passo a Passo (Buff NPC)

  1. Crie um UDataTable (CSV) com campos: Class, Enabled, Zen, PCPoints, Map, Location, Dir, MaxLevel, BodyItems, Skills.
  2. Implemente um UObject UBotBufferConfig que faz o parsing do DataTable no GameInstance e instancia ABuffNPC no BeginPlay do AGameMode.
  3. No ABuffNPC, exponha UPROPERTY para custos e limites; no Server_OnInteract(APlayerController*) valide nível/reset/VIP/Gens armazenados no APlayerState.
  4. Para aplicar buffs, crie USpellComponent ou use GameplayAbilitySystem; replique efeitos via RPC multicast.
  5. Para custo em PCPoints/Zen, faça chamada HTTP usando VaRest para um endpoint Node.js que atualiza o saldo SQL antes de aplicar o buff.

Passo a Passo (Warper NPC)

  1. Adicione ao DataTable campos WarpMap, WarpX, WarpY, OnlyVip, GensFamily, ReqContribution.
  2. No AWarperNPC, implemente Server_HandleWarpRequest(APlayerController*) verificando: VIP (APlayerState), level/reset, Gens (variável replicada) e saldo (consulta VaRest/Node.js/SQL).
  3. Calcule posição segura usando UNavigationSystemV1::GetRandomPointInNavigableRadius, similar ao laço de tentativa do original.
  4. Se o destino estiver em outro servidor/mundo, chame um serviço Node.js para registrar a migração e depois ClientTravel no controller; senão use ServerTravel interno.
  5. Envie feedback ao jogador via UUserWidget replicado (mensagens equivalentes a gNotice).

Blueprint clique a clique (Buff + Warper)

  1. Colocação: posicione BP_BuffNPC e BP_WarperNPC no mapa nas coordenadas do CSV (usar detalhes de localização com X/Y/Z idênticos). Ajuste Collision Sphere Radius para 180.
  2. UI de interação: widget WBP_NPCDialog (âncora centro, 520×320) com abas “Buffs” e “Warp”. Cada linha vem do DataTable e possui botão “Comprar/Usar”. Bindings mostram custos e requisitos.
  3. Buff: ao clicar, chame Server_RequestBuff(RowID) no NPC. No servidor: checar saldo via VaRest POST /npc/buff/check (retorna {ok, newBalance}). Se ok, aplicar GameplayEffect e replicar via MulticastBuffApplied para mostrar partículas.
  4. Warp: botão chama Server_RequestWarp(RowID). Servidor valida nível/VIP/Gens; se ok, chama VaRest POST /npc/warp (cobrança). Depois usa Teleport ou ClientTravel. Mostre contagem de “3…2…1…” no widget antes de teleportar.
  5. Logs/SQL: cada sucesso chama VaRest POST /npc/log com {account, npcType, action, cost}. Tabela SQL npc_logs deve ter índice por data.
  6. Testes: em PIE 2 clientes, abra o widget, tente buff sem saldo (deve falhar), adicione Zen, tente novamente (aplica). Para warp, selecione um destino de outro mapa e confirme ClientTravel com posição correta.

Checklist Final

  • Scripts de bot carregam e criam NPCs com inventário e aparência corretos.
  • Buff NPC bloqueia jogadores fora do nível/VIP/Gens ou sem saldo e aplica buffs via componente replicado.
  • Warper NPC valida requisitos, cobra Zen/PCPoints via VaRest/Node.js/SQL e teleporta para coordenada segura (ou outro servidor) mantendo replicação.
  • Mensagens de feedback em UI replicam as notificações do servidor original.

Passos adicionais para quem nunca usou Blueprints

  1. Meshes e colisão: coloque o SkeletalMesh do NPC e um Billboard com texto “Buff/Warper”. No componente Collision Sphere, marque Generate Overlap Events e ajuste a resposta para Pawn: Overlap.
  2. Detecção de proximidade: em OnComponentBeginOverlap, verifique se é o jogador local → abra WBP_NPCDialog. Em OnEndOverlap, feche o widget automaticamente.
  3. Layout do diálogo: adicione abas usando Widget Switcher. Na aba Buffs, use TileView com cartão 220x80 contendo nome, duração, custo e botão “Aplicar”. Na aba Warp, outra TileView com destino, mapa, custo, requisito VIP.
  4. Fluxo Buff: botão “Aplicar” → Server_RequestBuff(RowID). No servidor, chame VaRest POST /npc/buff/check; se ok retornar falso, execute ClientShowError mostrando toast vermelho. Se true, aplique GameplayEffect e toque partícula no local do player.
  5. Fluxo Warp: botão “Warp” → Server_RequestWarp(RowID). Servidor chama VaRest POST /npc/warp; se sucesso, usa Set Timer by Event 3→2→1 (atualizando texto na UI) e, ao final, chama ClientTravel para map/destino do DataTable. Se falhar, mostre toast amarelo “Requisito não atendido”.
  6. Retentativa offline: se qualquer POST falhar, registre em array PendingNpcOps (struct com account, npcType, action). Um timer no GameInstance tenta reenviar a cada 10s até limpar.
  7. Teste guiado: roteiro: (1) entrar sem Zen e tentar buff (esperar erro); (2) adicionar Zen e repetir (buff aplicado + partícula + log salvo); (3) tentar warp para mapa proibido pelo VIP e ver mensagem; (4) warp válido mostrando contagem regressiva e teleporte para coordenadas do CSV.
