Módulo 20 – Devil Square e Blood Castle (Entrada e Ciclo)

Abordamos o fluxo de entrada (pacotes 0x90 e 0x9A), leitura de scripts e ciclo de estados dos eventos Devil Square e Blood Castle, além de como portar o comportamento para UE5 com instâncias de mapa, timers e backend VaRest/Node.js/SQL.

Pré-requisitos

  • Módulos 6 e 12 concluídos (timers e IA de monstros).
  • Conhecimento de instanciamento de mapas em UE5 e replicação.
  • Banco SQL preparado para armazenar agendamentos/recompensas.

Conceitos do Código Original

Protocol.cpp – Entrada Devil Square (0x90) e Blood Castle (0x9A)
📘 O Que é?

Roteamento dos pacotes de entrada dos eventos no switch principal do GameServer.

case 0x90:
    gDevilSquare.CGDevilSquareEnterRecv((PMSG_DEVIL_SQUARE_ENTER_RECV*)lpMsg,aIndex);
    break;
...
case 0x9A:
    gBloodCastle.CGBloodCastleEnterRecv((PMSG_BLOOD_CASTLE_ENTER_RECV*)lpMsg,aIndex);
    break;

🎯 Para Que Serve?

Recebe a requisição do cliente para entrar nos eventos, encaminhando para os handlers que validam itens, nível e estado da instância.

💻 Como Funciona?

O opcode 0xC1/0xC3 chega ao ProtocolCore e cai no case específico. Cada handler verifica se o evento está aberto e se o jogador possui o convite correto, depois transfere o personagem para o mapa do nível correspondente.

📁 Onde Encontrar?

Source MuServer Update 15/GameServer/GameServer/Protocol.cpp, casos 0x90 e 0x9A.

⏱️ Quando é Executado?

Quando o jogador clica para entrar no evento (após usar convite ou interface). O pacote é enviado pelo cliente e processado imediatamente no servidor.

CDevilSquare::Init/Load – Configuração e Start Times
📘 O Que é?

Inicialização e leitura do script de horários, experiência e prêmios do Devil Square.

for(int n=0;n < MAX_DS_LEVEL;n++) {
    DEVIL_SQUARE_LEVEL* lpLevel = &this->m_DevilSquareLevel[n];
    lpLevel->State = DS_STATE_BLANK;
    lpLevel->Map = ((n<4)?MAP_DEVIL_SQUARE1:MAP_DEVIL_SQUARE2);
    lpLevel->EnterEnabled = 0;
    this->CleanUser(lpLevel);
}
...
this->m_DevilSquareStartTime.push_back(info);
this->m_DevilSquareRewardExperience[level][n] = lpMemScript->GetAsNumber();

🎯 Para Que Serve?

Prepara os níveis do evento, define mapas e horários de início, e carrega tabelas de recompensa de experiência e zen para cada rank.

💻 Como Funciona?

No construtor, limpa estados e define mapas por nível. Em Load, lê um script via CMemScript preenchendo m_DevilSquareStartTime e tabelas de recompensa. Em Init, define estado inicial (BLANK ou EMPTY) conforme configuração do servidor.

📁 Onde Encontrar?

Source MuServer Update 15/GameServer/GameServer/DevilSquare.cpp, construtor, Init e Load.

⏱️ Quando é Executado?

Chamado na inicialização do GameServer, antes de aceitar jogadores. O loop de eventos usa os horários carregados para abrir/fechar instâncias.

CBloodCastle::Init/Load – Estados, Horários e Tabelas
📘 O Que é?

Inicialização das instâncias de Blood Castle, definindo mapas, estados e leitura de scripts de tempo, experiência e premiação.

for(int n=0;n < MAX_BC_LEVEL;n++) {
    BLOOD_CASTLE_LEVEL* lpLevel = &this->m_BloodCastleLevel[n];
    lpLevel->Level = n;
    lpLevel->State = BC_STATE_BLANK;
    lpLevel->Map = ((n<7)?(MAP_BLOOD_CASTLE1+n):MAP_BLOOD_CASTLE8);
    lpLevel->EnterEnabled = 0;
    this->CleanUser(lpLevel);
    this->CleanMonster(lpLevel);
}
...
this->m_BloodCastleStartTime.push_back(info);
this->m_BloodCastleExperienceTable[level][0] = lpMemScript->GetAsNumber();

🎯 Para Que Serve?

Define as oito instâncias de Blood Castle, limpa usuários/monstros e carrega tabelas de recompensas e tempos de evento.

💻 Como Funciona?

O construtor cria estruturas por nível, define mapas e limpa dados. Init habilita ou zera estados conforme configuração. Load lê seções do script: tempos de aviso/notificação/evento, horários de início, tabelas de experiência e zen, e vida de NPCs.

📁 Onde Encontrar?

Source MuServer Update 15/GameServer/GameServer/BloodCastle.cpp, construtor, Init e Load.

⏱️ Quando é Executado?

Executa na inicialização do servidor; os ciclos de estado usam esses valores para abrir/fechar entradas e controlar monstros.

gObjUserDie – Delegação para Eventos
📘 O Que é?

Função central de morte do jogador que delega para os eventos instanciados, garantindo processamento específico de cada mapa.

if(DS_MAP_RANGE(lpObj->Map) != 0) {
    gDevilSquare.UserDieProc(lpObj,lpTarget); return;
} else if(BC_MAP_RANGE(lpObj->Map) != 0) {
    gBloodCastle.UserDieProc(lpObj,lpTarget); return;
}
...
gGensSystem.UserDieProc(lpObj,lpTarget);

🎯 Para Que Serve?

Encaminha a lógica de morte para a instância certa (Devil Square ou Blood Castle), aplicando regras de pontuação e ressurgimento específicas do evento.

💻 Como Funciona?

Verifica mapas com macros DS_MAP_RANGE e BC_MAP_RANGE. Em caso positivo, chama UserDieProc do evento e retorna, impedindo execução de lógica padrão de PK/drop.

📁 Onde Encontrar?

Source MuServer Update 15/GameServer/GameServer/User.cpp, função gObjUserDie.

⏱️ Quando é Executado?

Disparado sempre que um jogador morre. Se estiver dentro de Devil Square ou Blood Castle, a rotina específica do evento roda imediatamente.

Implementação em Unreal Engine 5

  • Instâncias de mapa: use UWorld::SpawnActor para gerenciar arenas separadas ou níveis de streaming para cada instância.
  • Controladores de evento: crie Actors server-only (ex.: ADevilSquareController, ABloodCastleController) com timers para estados (Blank, Empty, Playing, Closing).
  • Entrada: implemente RPC ServerRequestEnterEvent(EventType, Level) no APlayerController; valide convite/nível e mova o player para a instância.
  • Persistência: mantenha tabelas SQL para horários e recompensas; carregue via Node.js e envie ao servidor UE5 no boot. Clientes podem consultar via VaRest para exibir tempo restante.

Exemplo de Controller em UE5

UENUM(BlueprintType)
enum class EEventState : uint8 { Blank, Empty, Playing, Closing };

UCLASS()
class ADevilSquareController : public AActor {
    GENERATED_BODY()
public:
    UPROPERTY(EditAnywhere, BlueprintReadWrite) int32 LevelIndex;
    UPROPERTY(ReplicatedUsing=OnRep_State) EEventState State = EEventState::Blank;
    UPROPERTY(EditAnywhere) TArray StartTimes;
    UPROPERTY(EditAnywhere) TArray RewardExp;

    UFUNCTION() void TickState();
    UFUNCTION(Server, Reliable) void ServerRequestEnter(APlayerController* PC);
};

Fluxo de Entrada

  1. No cliente, ao clicar em "Entrar", envie RPC para ServerRequestEnter com o nível.
  2. No servidor, valide estado State == Empty, horário ativo e item de convite (armazenado em inventário replicado).
  3. Use AController::Possess e TeleportTo para mover o player à instância correspondente.
  4. Informe Node.js via VaRest de que o jogador entrou (log SQL) para estatísticas.

Recompensas e Mortes

  1. Ao terminar a rodada, calcule rank e aplique recompensas replicando tabelas lidas de SQL.
  2. Substitua o tratamento de morte padrão: em OnCharacterDied, cheque se o mapa é Devil Square/Blood Castle e invoque lógica específica (similar a gObjUserDie).
  3. Envie resultados para os clientes via multicast e para o backend via VaRest.

Passo a Passo em Unreal Engine 5

  1. Carregue tabelas de horários/recompensas de Devil Square e Blood Castle do SQL (via Node.js) ao iniciar o servidor.
  2. Instancie controladores para cada nível e programe timers de estado.
  3. Implemente RPC de entrada que valida convite/nível e teleporta o jogador para o mapa instanciado.
  4. Adapte UI para mostrar tempo restante e estado (dados via VaRest) antes da entrada.
  5. Em mortes dentro da instância, aplique lógica específica e bloqueie drops padrão.
  6. Finalize a rodada calculando ranking, distribuindo recompensas e limpando a instância.

Checklist Final

  • Eventos Devil Square e Blood Castle possuem controladores de estado com timers equivalentes ao servidor original.
  • Entrada só ocorre quando o estado está aberto e o convite/nível são válidos.
  • Mapas instanciados isolam jogadores e aplicam regras de morte específicas.
  • Recompensas e logs são persistidos no SQL via Node.js.
  • UI do cliente mostra estado/tempo e confirmações de entrada.

Guia Blueprint Hiper Detalhado (para iniciantes)

Use este roteiro clique a clique para recriar Devil Square e Blood Castle em UE5 apenas com Blueprints e VaRest.

Configuração de Dados

  1. No Content Browser, crie uma DataTable baseada em FDSBCScheduleRow com campos State, StartTime (HH:MM), WarnSeconds, RewardExp, RewardZen. Importe um CSV com linhas para DevilSquare1-7 e BloodCastle1-8.
  2. Crie um Blueprint Actor chamado BP_DSBC_Controller. Em Defaults adicione arrays StartTimes (tipo TimeOfDay) e RewardExp/RewardZen (inteiro) preenchendo a partir da DataTable no BeginPlay usando o node Get Data Table Row Names → ForEachLoop → Get Data Table Row.
  3. Adicione variáveis CurrentState (Enum: Blank/Notify/Open/Playing/Closing), RemainingSeconds (int) e InstanceMap (Soft Object Path do nível streaming).

FSM e Timers (Blueprint)

  1. No Event BeginPlay, chame Set Timer by Function Name a cada 1s para TickState. Dentro de TickState diminua RemainingSeconds e troque CurrentState usando um Switch on EDSBCState replicado.
  2. Estados: Blank (aguarda próximo horário), Notify (broadcast UI), Open (aceita entradas), Playing (cronômetro 900s), Closing (expulsa e registra ranking). Use Multicast eventos para empurrar o estado aos clientes.
  3. Entrada: crie função Server_RequestEnter(EventType, Level) (Run on Server, Reliable) no PlayerController. Valide convite lendo inventário replicado, depois Open Level (by Object Reference) para o mapa da instância e chame Possess no Character.
  4. Saída/expulsão: no estado Closing, execute ForEach Player Controller → Client Travel para o mapa da cidade e limpe buffs temporários.

HUD e Coordenadas

  1. Crie o Widget WBP_EventTimer (Canvas 1920x1080). Adicione uma barra horizontal em (X=60, Y=72, W=420, H=38) ancorada no topo-esquerda. Texto do tempo em (X=70, Y=76) fonte 22, alinhamento center-left.
  2. Adicione um botão “Entrar” em (X=520, Y=70, W=120, H=40) com cor #1E90FF. Em OnClicked chame RequestEnter com os parâmetros atuais.
  3. Para ranking final, crie WBP_DSBC_Rank com ListView 600x400 em (X=660, Y=240) ancorado ao centro. Alimente via On Event Closing do controller replicado.

Persistência VaRest + SQL

  1. No GameInstance, configure endpoint POST /api/events/dsbc/log (JSON: eventType, level, character, state, score). Use VaRest Request JSON ao entrar, ao terminar e ao expulsar.
  2. Crie função Server_LogScore no controller (Run on Server) que chama Execute HTTP Request com VaRest para gravar kills e tempo. Retorne status para o cliente via Client RPC exibindo alerta.
  3. No backend, mantenha tabela SQL EventRuns(Id, EventType, Level, Character, Score, DurationSeconds, StartedAt). Preencha a partir dos POSTs.

Depuração Visual

  • Adicione Print String colorido em cada troca de estado (verde=Open, vermelho=Closing) para validar o fluxo.
  • Inclua um Widget Switch debug no canto inferior direito (X=1560, Y=960, 240x80) para forçar estado (botões para Open/Close) somente para GM (Role Authority).
  • Use Draw Debug Sphere nos pontos de spawn dos monstros em cada mapa instanciado para comparar com o layout original.
