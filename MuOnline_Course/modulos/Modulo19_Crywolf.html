Módulo 19 – Crywolf (Sincronismo, Benefícios e UI)

Documentamos o sincronismo do estado Crywolf no servidor, os campos de penalidade/benefício e a UI dedicada no cliente. Incluímos passos completos para replicar o evento em UE5 com GameState, widgets e back-end VaRest/Node.js.

Pré-requisitos

  • Módulos 6 e 12 (timers/eventos e IA) concluídos.
  • Noções de GameState replicado em UE5 e criação de widgets UMG.
  • Backend Node.js + SQL ativo para armazenar estado do evento.

Conceitos do Código Original

CCrywolfSync – Estado e Penalidades Globais
📘 O Que é?

Classe singleton que mantém estado atual do evento Crywolf e fatores de benefício/penalidade aplicados ao jogo.

CCrywolfSync::CCrywolfSync() {
    this->m_CrywolfEnable = 0;
    this->m_ApplyBenefit = 0;
    this->m_ApplyPenalty = 0;
    this->m_CrywolfState = 0;
    this->m_OccupationState = 1;
    this->m_PlusChaosRate = 0;
    this->m_GemDropPenaltyRate = 100;
    this->m_GettingExpPenaltyRate = 100;
    this->m_MinusMonHPBenefitRate = 100;
    this->m_KundunHPRefillState = 1;
}

🎯 Para Que Serve?

Controla se o evento está ativo, se benefícios/penalidades aplicam (drop, experiência, HP de monstros) e qual é o estado atual para sincronizar com o cliente.

💻 Como Funciona?

Construtor inicia valores padrão. Métodos Set* atualizam campos, enquanto CheckEnableCrywolf e CheckApplyBenefit retornam flags usadas por outros subsistemas para modificar taxas de drop e experiência.

BOOL CCrywolfSync::CheckEnableCrywolf() { return this->m_CrywolfEnable; }
void CCrywolfSync::SetApplyPenalty(int ApplyPenalty) { this->m_ApplyPenalty = ApplyPenalty; }
int CCrywolfSync::GetGemDropPenaltiyRate() { return this->m_GemDropPenaltyRate; }

📁 Onde Encontrar?

Source MuServer Update 15/GameServer/GameServer/CrywolfSync.cpp, classe CCrywolfSync.

⏱️ Quando é Executado?

Instanciado no início do GameServer (CCrywolfSync gCrywolfSync;). Atualizações acontecem quando o sistema Crywolf processa mudanças de estado (carregamento de config e ciclos do evento).

Protocol.cpp – Pacotes de Info/Contrato/Chaos Rate
📘 O Que é?

Roteamento de pacotes 0xBD que tratam informações do evento, contrato do altar e taxa de Chaos durante Crywolf.

case 0xBD:
    switch(lpMsg[3]) {
        case 0x00: gCrywolf.CGCrywolfInfoRecv(aIndex); break;
        case 0x03: gCrywolf.CGCrywolfAltarContractRecv((PMSG_CRYWOLF_ALTAR_CONTRACT_RECV*)lpMsg,aIndex); break;
        case 0x09: gCrywolf.CGCrywolfChaosRateRecv(aIndex); break;
    }
    break;

🎯 Para Que Serve?

Recebe do cliente pedidos de informação e ações no altar (contrato) e envia respostas contendo estado, sincronizando a UI e o cálculo de Chaos Mix.

💻 Como Funciona?

A mensagem 0xBD é de subcódigo. Dependendo de lpMsg[3], chama o handler apropriado na instância global gCrywolf. Esses handlers verificam permissões, atualizam estado do altar e retornam pacotes com o status e parâmetros (ex.: bônus de Chaos Mix).

📁 Onde Encontrar?

Source MuServer Update 15/GameServer/GameServer/Protocol.cpp, bloco de switch do opcode 0xBD.

⏱️ Quando é Executado?

Chamado quando o cliente envia pacotes de Crywolf (ao abrir UI, iniciar contrato ou solicitar Chaos Rate). O fluxo é disparado a partir das ações na interface Crywolf.

⏱️ Quando é Executado?

Ativado ao entrar no mapa/evento Crywolf e ao receber atualizações de estado (pacotes 0xBD). O Render é chamado no loop de UI enquanto o evento estiver ativo.

Implementação em Unreal Engine 5

  • Estado Global: use AGameStateBase ou um UObject replicado para armazenar bCrywolfEnabled, ApplyBenefit, ApplyPenalty, ChaosRate, etc.
  • Servidor: crie um ACrywolfController (Actor no servidor) com timers que gerenciam fases do evento e notificam clientes via Multicast.
  • UI: implemente um UUserWidget "CrywolfHUD" com contagem regressiva, barras de HP de estátuas e mensagens de resultado.
  • Backend: exponha endpoints Node.js (/crywolf/state, /crywolf/contract) para armazenar progressão e aplicar benefícios no SQL; consuma do cliente via VaRest.

Exemplo de GameState

USTRUCT(BlueprintType)
struct FCrywolfStateData {
    GENERATED_BODY()
    UPROPERTY(EditAnywhere, BlueprintReadWrite) bool bEnabled = false;
    UPROPERTY(EditAnywhere, BlueprintReadWrite) int32 OccupationState = 1;
    UPROPERTY(EditAnywhere, BlueprintReadWrite) int32 ChaosBonus = 0;

UCLASS()
class ACrywolfGameState : public AGameStateBase {
    GENERATED_BODY()
public:
    UPROPERTY(ReplicatedUsing=OnRep_Crywolf) FCrywolfStateData CrywolfData;
    UFUNCTION() void OnRep_Crywolf();
};

Fluxo Servidor

  1. Carregue configurações do evento (timings, penalidades) de um arquivo JSON ou tabela SQL no início do mapa.
  2. Implemente um controlador com fases (Preparo, Defesa, Resultado) usando FTimerManager e atualize CrywolfData a cada mudança.
  3. Ao receber contrato de altar (RPC do jogador), valide posição/estado e avance a fase, replicando novos valores.
  4. Ao final, envie resultado para Node.js via VaRest server-side ou HTTP em plugin C++ e salve no SQL.

UI/Cliente

  1. Adicione um Widget "CrywolfHUD" com animações de sucesso/fracasso; ligue a CrywolfData replicada para atualizar textos e cores.
  2. Dispare sons/efeitos ao receber mudanças (similar a variáveis Suc_Or_Fail e Delay do cliente original).
  3. Implemente um painel de contrato que chama endpoint /crywolf/contract via VaRest, recebendo confirmação e atualizando UI.

Passo a Passo em Unreal Engine 5

  1. Crie ACrywolfGameState com struct replicada para estado e taxas.
  2. Implemente ACrywolfController (Actor server-only) com timers de fase e RPC para contrato do altar.
  3. Adicione Widget "CrywolfHUD" e vincule a OnRep_Crywolf para atualizar contadores e mensagens.
  4. Configure endpoints Node.js/SQL para salvar progresso e fornecer taxas (ChaosRate, penalidades) ao carregar o mapa.
  5. Teste fluxo completo: entrada no mapa, solicitar info (equivalente ao pacote 0xBD 0x00), realizar contrato (0xBD 0x03) e verificar aplicação de benefícios/penalidades no gameplay.

Checklist Final

  • Estado Crywolf replicado para todos os clientes (habilitado, ocupação, penalidades).
  • Contrato de altar confirma via RPC/HTTP e atualiza GameState.
  • UI mostra contagem, estado e feedback animado de sucesso/fracasso.
  • Chaos Rate e penalidades são aplicadas a sistemas de drop/XP conforme GameState.
  • Dados persistem no banco via Node.js e são recarregados ao iniciar o mapa.
