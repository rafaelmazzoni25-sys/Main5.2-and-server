Módulo 31 – Comandos, Chat e Ferramentas de GM

Documenta o pipeline de comandos do GameServer (registro, parsing e validação) e como construir um sistema equivalente em UE5 com integração REST.

Pré-requisitos

  • Módulo 2 – Rede/Autenticação (para interceptar chat).
  • Módulo 10 – Interface/Input.
  • Conhecer Gameplay Ability System ou RPCs em UE5.

Conceitos do Código Original

CCommandManager::Init – Registro dos comandos
📘 O Que é?

Inicializa o vetor m_CommandInfo e associa rótulos do arquivo de comandos aos códigos internos.

🎯 Para Que Serve?

Permite mapear sintaxes textuais (ex.: /post, /reset) para handlers específicos do servidor.

💻 Como Funciona?

void CCommandManager::Init() {
  for(int n=0;n < MAX_COMMAND;n++) {
    this->m_CommandInfo[n].code = -1;
    this->Add(gCommand.GetCommand(n),n+1);
  }
  // lista comentada mostra comandos suportados (/move, /reset, /quest ...)
}

Source MuServer Update 15/GameServer/GameServer/CommandManager.cpp, linhas 77-160.

⏱️ Quando é Executado?

Chamado na inicialização do GameServer (bootstrap em GameMain.cpp) para preencher a tabela antes de qualquer chat.

CCommandManager::MainProc – Serviços automáticos
📘 O Que é?

Loop que trata comandos automáticos por player (auto-add de pontos e auto-reset).

🎯 Para Que Serve?

Executa rotinas periódicas configuradas sem depender de input de chat.

💻 Como Funciona?

for(int n=OBJECT_START_USER;n < MAX_OBJECT;n++) {
  if(gObjIsConnectedGP(n) == 0) continue;
  if(gObj[n].AutoAddPointCount > 0) { this->CommandAddPointAutoProc(&gObj[n]); }
  if(gObj[n].AutoResetEnable != 0) { this->CommandResetAutoProc(&gObj[n]); }
}

⏱️ Quando é Executado?

CCommandManager::ManagementCore – Parsing e validações
📘 O Que é?

Função que interpreta a linha digitada, obtém o comando e executa checagens de permissão, dinheiro, nível e reset.

🎯 Para Que Serve?

Garante que cada comando só rode quando o jogador cumpre requisitos e não está em trade ou com saldo insuficiente.

💻 Como Funciona?

this->GetString(message,command,sizeof(command),0);
if(gCommand.GetInfoByName(command,&CommandData) == 0) return 0;
int code = this->GetCommandCode(command);
if (CommandData.Enable[lpObj->AccountLevel] == 0) return 0;
if(lpObj->Money < (DWORD)CommandData.Money[lpObj->AccountLevel]) { GCNotice...; return 0; }
if(lpObj->Interface.use == INTERFACE_TRADE) { GCNotice...; return 0; }
if(lpObj->Level < CommandData.MinLevel[lpObj->AccountLevel]) { GCNotice...; return 0; }
if(CommandData.MaxLevel[...] != 0 && lpObj->Level > CommandData.MaxLevel[...]) { return 0; }
if(lpObj->Reset < CommandData.MinReset[...]) { return 0; }

⏱️ Quando é Executado?

Chamado quando o servidor recebe uma mensagem de chat que inicia com a sintaxe de comando; executa antes de despachar para handlers específicos (ex.: /move, /reset).

Implementação em Unreal Engine 5

  1. Crie um UCommandRegistry (UObject) com mapa FString → FCommandInfo replicando os campos Enable, Money, MinLevel, MaxLevel, MinReset.
  2. No AGameModeBase, intercepte chat via RPC ServerHandleChat(const FString& Message) e chame um ParseCommand semelhante a ManagementCore.
  3. Implemente FCommandInfo com callbacks TFunction<void(APlayerController*, const TArray<FString>&)> para despachar comandos.
  4. Integre com backend Node.js/SQL para comandos administrativos persistentes (ex.: /setvip) usando VaRest dentro de um UCommandService.
  5. Crie UI UMG para feedback imediato (notices) mapeando as respostas de validação, similar às chamadas GCNoticeSend.

Passo a Passo em Unreal Engine 5

  1. Definir FCommandInfo em um header compartilhado com propriedades BlueprintReadOnly para permitir atalhos em UMG.
  2. Popular UCommandRegistry no GameInstance a partir de um JSON carregado (equivalente ao arquivo de comandos).
  3. No ServerHandleChat, dividir a string em tokens; obter o comando e argumentos; validar dinheiro, nível, reset e estado de interface (ex.: se está em trade/loja).
  4. Executar a ação: para teleporte, chame ServerTravel ou ACharacter::SetActorLocation; para reset, ajuste atributos e salve em SQL via endpoint VaRest.
  5. Registrar comandos automáticos (auto-add, auto-reset) em um FTimerManager no GameState, iterando jogadores como MainProc faz.
  6. Checklist: comandos rejeitados exibem aviso; dinheiro/nível/reset são checados; comandos administrativos consultam backend; auto-serviços rodam em timer.

Checklist Final

  • Registro de comandos carregado antes do chat.
  • Parsing respeita limites de nível, reset, dinheiro e bloqueio de interface.
  • Feedback visual/sonoro de sucesso ou falha replicado em todos os clientes afetados.
  • Integração VaRest/Node.js/SQL para comandos persistentes.
  • Timers de serviços automáticos executam para todos os jogadores conectados.
