Módulo 48 – Empacotamento UE5, Build de Servidor, CI/CD e Observabilidade

Guia operacional para preparar entregas do cliente Unreal Engine 5 e do servidor clássico (Update 15), automatizar o pipeline e assegurar monitoramento/logs consistentes com o resto do curso.

Empacotamento do Cliente UE5

BuildCookRun (Shipping) com assets do curso
  1. Abrir o projeto UE5 (versão C++ + Blueprint usada nos módulos anteriores) e confirmar que os conteúdos convertidos do Source Main 5.2 estão referenciados.
  2. Usar o Unreal Automation Tool via RunUAT.sh / RunUAT.bat com o comando BuildCookRun para Windows ou Linux dedicados.
  3. Incluir -pak, -compressed e -prereqs para gerar instalador, e -CrashReporter para anexar o capturador de crash/stack.
  4. Validar binários com o projeto Main.sln (cliente original) aberto apenas como referência de assets/ícones e para manter a paridade de recursos.

Build do Servidor (Update 15)

GameServer e auxiliares

Use os .sln existentes para compilar no Visual Studio/MSBuild (mesmo ambiente já usado nos módulos anteriores).

  • Source MuServer Update 15/GameServer/GameServer.sln – ciclo principal e roteamento de protocolos.
  • Source MuServer Update 15/JoinServer/JoinServer.sln – autenticação e distribuição de salas.
  • Source MuServer Update 15/ConnectServer/ConnectServer.sln – handshake e anti-flood de conexão.
  • Source MuServer Update 15/DataServer/DataServer.sln – camada ODBC/SQL e timers (QueueTimer).
Passos rápidos
  1. Checar dependências ODBC/SQL e bibliotecas externas (como indicado nos módulos 7–9).
  2. Rodar msbuild GameServer.sln /p:Configuration=Release (repita para Join/Connect/DataServer) para gerar binários.
  3. Executar scripts de inicialização usados no curso (ex.: carregamento de Script\*.txt) antes de validar com o cliente UE5.

Pipeline de CI/CD

Automação alinhada ao repositório
  • Build cliente: estágio que chama RunUAT BuildCookRun em uma VM com UE5 e usa os mesmos assets do Main.sln para conferir versões de recursos.
  • Build servidor: jobs paralelos executando msbuild nos quatro .sln acima, reaproveitando os scripts de Script carregados no tempo de execução.
  • Testes/validadores: adicionar smoke tests que abrem o cliente empacotado e verificam conexão com ConnectServer + consultas básicas no DataServer (usando os binários gerados do repo).
  • Artefatos: publicar .pak do cliente e os binários GameServer/JoinServer/ConnectServer/DataServer como artefatos versionados.
  • Watchers: configurar gatilhos de CI para MuOnline_Course/ (documentação) e para modificações em Source Main 5.2/ ou Source MuServer Update 15/, evitando builds desnecessários.

Checklist de Monitoramento e Logs

Antes de liberar para o público
  1. Ativar logs de rede/timers no cliente (paridade com Winmain.cpp e ProtocolRecv/Send), salvando em arquivo para anexar a crash reports.
  2. Configurar rotação e nível de log nos servidores (GameServer/Join/Connect/Data) e expor um endpoint/arquivo health.log com batidas periódicas.
  3. Habilitar coleta de métricas de fila (QueueTimer.cpp) e uso de threads para detectar gargalos de persistência.
  4. Monitorar watchdogs de janela/entrada (mencionados no Módulo 1) e alarmes de reconexão (Módulo 38) para garantir estabilidade.
  5. Registrar versão do build (hash do commit) nos binários e no launcher do cliente UE5 para rastreabilidade.

Entrega Final e Checklist de Publicação

  • Validar instalador gerado pelo BuildCookRun em uma máquina limpa, incluindo pré-requisitos e assets compartilhados.
  • Executar sessão completa: login (Connect/Join), carregamento de mapa, combate rápido e transação simples (DataServer) usando os binários do repo.
  • Publicar release com .pak + servidores, anexando changelog e links para os scripts de Script e configurações SQL.
  • Agendar postmortem semanal: revisar logs, métricas e alarmes configurados acima.
