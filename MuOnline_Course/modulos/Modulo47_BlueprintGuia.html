Módulo 47 – Guia Blueprint: Recriando Cliente/Servidor e Todos os Módulos

Aula guiada para transformar os fluxos C++ legados (cliente Main 5.2 e GameServer Update 15) em Blueprints UE5, cobrindo todos os módulos (1–46) sem apagar o material original e mantendo o uso de VaRest + SQL.

Trilhas de Código C++ que Servem de Referência

  • Cliente: Source Main 5.2/source/Winmain.cpp (loop e globais), Source Main 5.2/source/ProtocolSend.cpp (envio) e Source Main 5.2/source/ProtocolRecv.cpp (recepção).
  • Servidor: Source MuServer Update 15/GameServer/GameServer/GameMain.cpp (boot), GameServer/Protocol.cpp (roteamento) e GameServer/MonsterAI/MonsterAI.cpp (IA e timers).
  • Persistência: DataServer/QueueTimer.cpp + SQL ODBC, mapeados em UE5 via Http/REST e Data Assets.

Blueprints: Pilares de Recriação

GameInstance para Globais

Centraliza singletons de UI, rede e áudio. Crie variáveis:

  • UIManagerRef (tipo Object de um subsystem)
  • NetworkQueue (array de structs de pacotes)
  • MusicState (enum replicando PlayMp3/StopMp3)

No Event Init, carregue assets e inicialize sockets HTTP/UDP.

GameMode/Controller para Boot do Servidor

Use AGameModeBase (dedicado) para ler Data Assets de monstros/experiência e abrir conexões REST/Socket com scripts equivalentes a gJoinServerConnection e gDataServerConnection.

Implemente timers (Set Timer by Function Name) para filas de eventos e invocação de IA.

Passo a Passo (Aula Guiada – Núcleo)

  1. Preparar o Projeto
    • Criar um projeto C++ + Blueprint em UE5 e definir UMuGameInstance como Game Instance no Project Settings.
    • Habilitar plugin VaRest ou Http integrada para emular consultas ao DataServer; adicionar socket/OSC se quiser persistir TCP bruto.
    • Importar Data Tables em CSV para tabelas de monstros/experiência, seguindo as colunas de MonsterSetBase e XP do GameServer.
  2. Cliente – Loop de Rede e Render
    • Criar um Blueprint Function Library chamado BP_Protocol com funções SendPacket e ConsumeRecvQueue que recebem structs equivalentes aos ProtocolSend/Recv.
    • Adicionar um Actor BP_NetworkTick com componente Tick habilitado para executar a cada frame: Poll Messages → Update UI → Play BGM, replicando o Scene() + ProtocolCompiler().
    • No BeginPlay do BP_NetworkTick, instanciar UIManager e registrar inputs, espelhando as globais definidas em Winmain.cpp.
  3. Servidor – Boot e Conexões
    • Em um mapa dedicado, definir GM_Server (Blueprint de GameMode) que chama Load Config (leitura de Data Assets) e abre conexões com serviços externos.
    • Configurar timers para: Processar fila de pacotes (100 ms), Atualizar IA (500 ms) e Persistir status (1 s), equivalentes às rotinas de GameMain.cpp e MonsterAI.cpp.
    • Registrar rotas de mensagem em um DataTable (ID → Function Name). No recebimento, use Switch on Int para chamar handlers, simulando Protocol.cpp.
  4. Persistência via Blueprints
    • Criar BP_DataServerClient (Actor ou Subsystem) com funções SendSQL (Http POST) e OnSQLResponse; mapear resultados em structs para ser consumidos pelo GameMode.
    • Usar Queues (Arrays) para requests pendentes e timers para reenvio, replicando QueueTimer.cpp.
    • Padronizar headers de autenticação para todos os módulos e manter um endpoint de /health para validar o DataServer antes de liberar UI.
  5. IA e Movimento
    • Converter scripts de MonsterAI/MovePath em Data Assets (listas de vetores). Carregar no GM_Server e usar AI MoveTo + Behavior Tree para seguir caminhos.
    • Usar Environment Query para checks de colisão e Gameplay Tags para estados (Aggro, Return, Dead) em vez de flags C++.
  6. Entrega e Depuração
    • Adicionar comandos de console (mu.DumpInit, mu.ForceRespawn) expostos por Exec functions em Blueprints para validar fases de boot.
    • Criar um Widget de monitoria que mostre Packets/s, Timers ativos e Estado das conexões para comparar com o log do C++.

Trilha Completa: Recriando os Módulos 1–46 em Blueprints

Use esta trilha paralela aos módulos originais (C++) sem apagá-los. Cada módulo herda o núcleo acima, usa VaRest para HTTP/JSON e persiste no mesmo banco SQL (exposto por um serviço REST).

Fundação (Mód. 1–10)
  • Arquitetura/Bootstrap: Configure UMuGameInstance e BP_NetworkTick para loops de cliente/servidor (mód.1–2).
  • Movimento/Interface: Use Character Movement + Replicate Movement para o módulo 3 e Widgets UMG para o módulo 10.
  • Persistência: Para o módulo 9, exponha endpoints /character/load e /character/save no serviço REST; no Blueprint, chame via VaRest com Retry usando as filas do núcleo.
Social, Eventos e IA (Mód. 11–24)
  • Party/Social (mód.11–13): replique pacotes com DataTable de eventos (PartyJoin, PartyHP) e widgets para mini-mapa.
  • IA (mód.12): Behavior Trees com Blackboard para estados de agressão; caminhos em Data Assets como no núcleo.
  • Eventos (mód.14–24): crie um BP_EventScheduler que lê Data Assets de scripts de evento e usa Switch on Name para executar fluxos (Crywolf, Blood Castle, Imperial Guardian, etc.). Cada resultado chave (recompensas, status global) persiste via VaRest em /events/{id}/state.
Economia, Itens e Scripts (Mód. 25–36)
  • Chaos Castle / Acheron / Illusion (mód.24–26): estados em State Machines de Blueprint, com checkpoints salvos via /instances/save.
  • Pentagram/Itens (mód.27–35): Data Tables para joias, sockets e mineração; use Gameplay Tags para validar buffs. As compras/rolagens chamam /inventory/update em VaRest.
  • MuRummy/Lucky Coin (mód.36): Widgets dedicados que chamam /minigames/rummy e /minigames/luckycoin para registrar embaralhamento e recompensas.
Segurança, Progressão e Serviços (Mód. 37–46)
  • Criptografia/Reconexão (mód.37–38): implemente cifra XOR em Blueprint Function Library e salve snapshots de sessão no endpoint /session/snapshot.
  • Casamento/PvP (mód.39–40): Data Assets para regras; persistência em /social/marriage e /pvp/match. Replicar timers com Timer by Event.
  • Progressão/Bonus (mód.41–46): aplique multiplicadores via Gameplay Effect e registre alterações no /progression. Para bots (mód.44), use BP_BotService com inventário em Data Assets.

Blueprints Essenciais para a Trilha Completa

  • BP_EventScheduler: lê Data Assets de eventos (IDs do módulo original) e instancia sub-fluxos. Mantém ponte para VaRest com rotas por evento.
  • BP_PacketRouter: tabela ID → Dispatcher de eventos. Útil para módulos de rede (2, 8, 37) mantendo compatibilidade de logs com o C++.
  • BP_SQLBridge: wrapper de VaRest que centraliza headers e roteia para endpoints SQL. Deve ser usado por todos os módulos para manter consistência.
  • Widgets dedicados: UI_EventStatus (eventos 14–25), UI_InventoryExtended (mód.27–35) e UI_DebugSession (mód.37–38) para monitorar estados.

Checklist de Convergência (C++ → Blueprint)

  • Para cada módulo original, valide se há um Data Asset correspondente (config) e uma função Blueprint que consome os dados.
  • Logs: mantenha o mesmo tag do C++ (ex.: [EventCrywolf]) em PrintString ou Log Blueprint para alinhar comparações.
  • VaRest + SQL: todas as operações de salvamento/leitura devem passar pelo BP_SQLBridge; não deixe chamadas diretas duplicadas para evitar divergência.
  • Compatibilidade: se um módulo ainda estiver em C++ para performance, mantenha o Blueprint como camada de orquestração e documente o ponto de integração.

Recursos Necessários

  • Blueprints: BP_NetworkTick, BP_Protocol, BP_DataServerClient, GM_Server, UI_Splash (loading) e UI_HUD.
  • Plugins: Http/REST (padrão UE), VaRest (opcional), Online Subsystem para autenticação local, e suporte a sockets se preferir TCP.
  • Data Assets: tabelas de monstros, experiência, configuração de eventos e mapeamento de mensagens (ID → handler).
  • Infra: servidor Node.js/SQL simples para simular DataServer com endpoints /login, /save e /load.

Checklist Final

  • Loop de rede/visual completo em Blueprint que processa pacotes e renderiza UI sem travar, inspirado em Winmain.cpp.
  • Servidor dedicado UE5 carregando dados e mantendo timers de IA e persistência equivalentes ao GameServer C++.
  • Rotas de mensagem e estrutura de dados documentadas para alunos reproduzirem 1:1.
  • Todos os assets (UI, Data Assets, Plugins) listados e configurados antes da aula.
